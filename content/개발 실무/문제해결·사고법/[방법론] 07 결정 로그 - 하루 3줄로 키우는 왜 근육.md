# 결정 로그 - 하루 3줄로 키우는 "왜" 근육

> [!NOTE] 한 줄 요약
> 하루에 **결정 하나**를 골라 **결정 / 이유 / 버린 대안** 3줄만 적는다. 쌓이면 내 생각의 빈틈이 보인다.

## 왜 적어야 할까요?

머릿속에서는 "그냥 그게 좋을 것 같아서"가 꽤 그럴듯하게 느껴져요. 그런데 **글로 적으려는 순간** 이유가 막히는 경우가 많아요. 바로 그 막히는 곳이 내 생각이 약한 지점이에요. 운동으로 치면 어느 근육이 약한지 알려 주는 거예요.

## 하루 루틴 (10~15분)

1. 하루를 마치기 전에 오늘 한 결정 중 **하나만** 고른다.
2. 아래 항목을 채운다.
3. 이유가 "그냥", "느낌", "원래 그래서"로 끝났다면 **표시**해 둔다. 내일 더 파고들 대상이에요.

## 양식

```
### 2026-11-10
- 결정:
- 이유(왜):
- 버린 대안과 이유(왜 아닌가):
- 근거 수준: 확인됨 / 추측 / 모름
- 오늘 막힌 이유: 정보 부족 / 정리 부족 / 해당 없음
```

## 예시

```
### 2026-11-07
- 결정: 프로그램의 시작 함수부터 읽었다
- 이유: 모든 흐름의 출발점이라 뒤의 갈래를 따라가기 쉽다
- 버린 대안: 데이터 구조부터 읽기 → 어디서 쓰이는지 몰라서 이해하기 어려움
- 근거 수준: 추측 (선배에게 확인 필요)
- 오늘 막힌 이유: 정보 부족
```

## 코드 읽을 때 쓰는 변형: 의문 노트

- 함수 하나를 볼 때마다 **"왜 이렇게 만들었을까?"** 의문을 하나 적어요.
- 답은 몰라도 괜찮아요. 나중에 변경 기록, 주석, 선배에게 물어서 확인해요.

## 일주일에 한 번 돌아보기

- 한 주의 기록에서 **"추측/모름"** 으로 남은 것을 모아요.
- 그중 **다음 주에 확인할 3개**를 골라요.
- 이유가 자꾸 얕게 끝나는 **버릇**이 있는지 살펴봐요.

## 조심할 점

- **모든 결정**을 적을 필요는 없어요. 되돌리기 어렵거나, 영향이 크거나, 남에게 설명해야 하는 것만 골라요.
- "모르겠다"는 실패가 아니라 **확인할 곳을 찾은 것**이에요.
- 완벽한 이유가 없어도 "그때 가진 정보로는 이게 최선이었다"까지 쓸 수 있으면 충분해요.

## 이어지는 연습

로그에 적은 내용은 그대로 **즉석 대답 재료**가 돼요. 앞서 배운 [피라미드 원칙](개발%20실무/문제해결·사고법/[방법론]%2006%20피라미드%20원칙%20-%20결론부터%20말하는%20기술.md)의 "결론-이유-근거"로 말해 보세요.

## 정리

- 하루 한 결정, 3줄, 10분!
- "그냥"이라고 쓰게 된 날이 **가장 많이 배우는 날**이에요.
