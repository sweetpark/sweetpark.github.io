# 테스트·AI 활용 용어

> 테스트 환경, 아키텍처 규칙 검사, AI 활용 개발 관련 용어

- 용어 6개

---

### Testcontainers

**테스트 때 Docker로 실제 DB 같은 의존 서비스를 띄워서 테스트하는 도구.**

- 인메모리 DB(H2)는 MySQL과 문법과 동작이 미묘하게 달라, "테스트는 통과했는데 운영에서 실패"하는 일이 생긴다. 실제 MySQL을 띄우면 이 차이가 없다.
- 학습 노트: [테스트 (Junit5)](개발%20%28CS%29/언어/JAVA/컨벤션·테스트·연동/[Java]%20테스트%20%28Junit5%29%20-%20핵심%20개념%20및%20특징%20정리.md)

### in-memory DB (인메모리 DB)

**디스크가 아니라 메모리에 데이터를 두는 DB. 테스트에서 가볍게 쓰려고 H2 같은 것을 쓴다.**

- 빠르고 설치가 필요 없지만 운영 DB와 완전히 같지 않다.
- 학습 노트: [테스트 (Junit5)](개발%20%28CS%29/언어/JAVA/컨벤션·테스트·연동/[Java]%20테스트%20%28Junit5%29%20-%20핵심%20개념%20및%20특징%20정리.md)

### architecture test (아키텍처 테스트)

**아키텍처 규칙을 테스트 코드로 강제하는 것.**

- 예) "controller 패키지는 repository를 직접 참조하면 안 된다". Java는 ArchUnit, Kotlin은 Konsist가 대표적이다.

### LLM / prompt / AI agent

**LLM(Large Language Model)은 대규모 언어 모델, prompt는 모델에 주는 지시문, AI agent는 목표를 받아 도구를 호출하며 스스로 여러 단계를 수행하는 AI.**

### MCP (Model Context Protocol)

**AI 모델이 외부 시스템(DB, 문서, 배포 도구 등)을 도구로 호출할 수 있게 하는 표준 프로토콜.**

### review bottleneck (리뷰 병목)

**AI로 코드를 빠르게 만들게 되어 PR 수와 크기는 늘었는데, 리뷰하는 사람의 시간은 그대로라 병목이 "코드 작성"에서 "코드 리뷰"로 옮겨 가는 현상.**

- AI가 쓴 코드는 겉보기엔 그럴듯해서 더 꼼꼼히 봐야 하고, 작성자도 세부 구현을 다 기억하지 못해 리뷰 비용이 커진다.
- 대응 방향: 1차 리뷰를 AI가 하는 code review agent, 아키텍처 규칙 자동 검사, 테스트 자동화로 사람이 볼 범위를 줄이기.
