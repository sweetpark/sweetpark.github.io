## 헷갈리는 용어 비교

| 비교 | 차이 |
| --- | --- |
| library vs framework | library는 내가 호출한다. framework는 틀이 내 코드를 호출한다(제어의 역전). |
| proxy vs gateway vs relay | proxy는 대리 전달, gateway는 다른 네트워크·시스템의 출입구(공통 처리 포함), relay는 단순 중계. 제품마다 경계가 모호하다. |
| VM vs container | VM은 가상 하드웨어와 자기 OS(게스트 OS)를 가진다. container는 호스트 커널을 공유해서 더 가볍다. |
| vm image vs docker image | vm image는 OS 전체 디스크 템플릿, docker image는 커널 없는 앱 단위 레이어 패키지. |
| image vs container vs pod | image는 템플릿, container는 그 이미지를 실행한 것, pod는 container를 묶어 배포하는 k8s 최소 단위. |
| Continuous Delivery vs Deployment | Delivery는 배포 가능한 상태까지 자동화(운영 반영은 승인), Deployment는 운영 반영까지 자동. |
| agenda vs minutes | agenda는 회의 전 안건 목록, minutes는 회의 후 기록. |
| due date vs deadline | due date는 계획된 마감일, deadline은 넘기면 안 되는 최종 시한(더 강한 뉘앙스). |
| PUT vs PATCH | PUT은 전체 교체(없으면 생성), PATCH는 바뀐 부분만 수정. |
| patch(소프트웨어) vs PATCH(HTTP) | 소프트웨어 patch는 배포된 프로그램의 버그 수정, HTTP PATCH는 자원의 부분 수정 요청. |
| revert vs reset vs rebase | revert는 취소하는 새 commit을 추가(이력 보존), reset은 HEAD를 옮겨 commit을 없앤 것처럼 되돌림(이력 변경), rebase는 되돌리기가 아니라 commit을 다른 기준 위에 다시 쌓는 것(이력 재작성). |
| merge vs rebase | merge는 이력을 그대로 두고 merge commit으로 합침, rebase는 commit을 새로 쌓아 일직선 이력을 만듦. |
| fork vs clone vs branch | fork는 서버에서 내 계정으로 복사, clone은 내 PC로 복제, branch는 같은 저장소 안의 작업 갈래. |
| sharding vs partitioning | sharding은 여러 DB 서버로 수평 분할, partitioning은 한 DB 안에서 테이블을 쪼갬. |
| optimistic vs pessimistic lock | 낙관적은 락 없이 진행하고 커밋 때 충돌 검사, 비관적은 먼저 락을 잡고 진행. |
| write-through vs write-behind | write-through는 캐시와 DB에 동시에 쓰고, write-behind는 캐시에 먼저 쓰고 DB에는 나중에. |
| service mesh vs API gateway | mesh는 서비스 간(동서) 통신을 사이드카로 제어, API gateway는 외부에서 들어오는(남북) 요청의 진입점. |
| API key vs HMAC vs JWT | API key는 키가 요청에 실림, HMAC은 secret 없이 서명만 실림(위변조 방지), JWT는 서명된 자가 포함 토큰(서버가 DB 없이 검증). |
| DEL vs UNLINK | DEL은 동기 삭제(큰 키는 서버를 멈춤), UNLINK는 삭제 표시 후 백그라운드에서 해제. |
| overload vs override | overload는 같은 이름·다른 매개변수로 함수를 여러 개 정의(컴파일 시점 선택), override는 상속받은 부모 메서드를 같은 시그니처로 재정의(실행 시점 선택, 덮어쓰기에 가까움). |
| 커널 vs 커널 영역·사용자 영역 | 커널은 OS의 핵심 프로그램이고, 커널 영역/사용자 영역은 메모리와 권한의 구분이다. 커널은 커널 영역에서 돈다. |
| local cache vs 분산 cache | local cache는 서버마다 따로(빠르지만 값이 달라질 수 있음), 분산 cache는 여러 서버가 공유. |
| stale vs old | stale은 단지 오래된 것이 아니라 최신과 어긋나서 믿으면 안 되는 상태. |
| L2 / L3 / L4 스위치 | L2는 MAC, L3는 IP 라우팅, L4는 IP+포트 기반 분산·제어. |
