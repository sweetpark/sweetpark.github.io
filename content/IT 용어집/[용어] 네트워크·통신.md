# 네트워크·통신 용어

### protocol (프로토콜)

**통신하는 양쪽이 미리 약속한 규칙. 메시지 형식, 순서, 오류 처리 방식 등.**

- 예) TCP, HTTP, TLS.

### peer (피어)

**통신에서 마주 보는 상대편(대등한 상대 노드).**

- 서버일 수도, 클라이언트일 수도 있다. "대상 서버"만을 뜻하지 않는다.
- 예) peer 정보 = 상대 쪽 주소, 식별자 같은 정보.

### client / server, request / response

**요청을 보내는 쪽(client)과 받아서 응답하는 쪽(server), 그리고 그 메시지 쌍.**

- 한 노드가 상황에 따라 client도 server도 될 수 있다.

### TCP

**연결 지향 전송 프로토콜(L4). 순서 보장, 유실 시 재전송, 흐름·혼잡 제어로 신뢰성 있는 통신을 제공한다.**

- 연결을 맺을 때 3-way handshake를 한다.
- UDP는 연결 없이 빠르게 보내지만 신뢰성은 제공하지 않는다.
- 학습 노트: [네트워크 기본 통신 정리 (TCP-UDP, NAT, 네트워크 품질)](개발%20%28CS%29/게임서버/게임서버%20프로그래머%20책/[게임서버프로그래밍#7]%20네트워크%20기본%20통신%20정리%20%28TCP-UDP,%20NAT,%20네트워크%20품질%29.md) · [인터넷 통신과정 ( + IP, TCP-UDP, PORT, DNS )](개발%20%28CS%29/언어/JAVA/웹개발/HTTP/인터넷%20통신과정%20%28%20+%20IP,%20TCP-UDP,%20PORT,%20DNS%20%29.md)

### OSI 7계층 (L1 ~ L7)

**통신 기능을 7단계로 나눈 참조 모델.**

| 계층 | 이름 | 핵심 역할 | 예시 |
| --- | --- | --- | --- |
| L7 | 응용(Application) | 사용자 서비스용 프로토콜 | HTTP, DNS, FTP |
| L6 | 표현(Presentation) | 데이터 형식 변환, 암호화, 압축 | TLS(일부), 문자 인코딩 |
| L5 | 세션(Session) | 연결(세션)의 시작, 유지, 종료 관리 | 세션 관리 |
| L4 | 전송(Transport) | 포트 기반 프로세스 간 전달, 신뢰성 | TCP, UDP |
| L3 | 네트워크(Network) | IP 주소 기반 경로 선택(라우팅) | IP, 라우터 |
| L2 | 데이터링크(Data Link) | MAC 주소 기반, 같은 네트워크 안 프레임 전달 | 이더넷, L2 스위치 |
| L1 | 물리(Physical) | 전기·광 신호로 비트 전송 | 케이블, 허브 |

> 아래에서 위로 "물리 → 데이터링크 → 네트워크 → 전송 → 세션 → 표현 → 응용" 순서다. 실무에서는 L5~L7을 합쳐 TCP/IP 4계층(링크, 인터넷, 전송, 응용)으로 설명하기도 한다.

### IP / MAC / port / socket

**IP는 네트워크 상의 주소(L3), MAC은 네트워크 카드 고유 주소(L2), port는 한 호스트 안에서 프로그램을 구분하는 번호(L4), socket은 통신의 끝점(IP + 포트).**

- 학습 노트: [Socket 통신](개발%20%28CS%29/언어/C언어/네트워크·시스템%20IO/[TCP_IP]%20Socket%20통신%20-%20핵심%20개념%20및%20특징%20정리.md) · [클라이언트-서버 구현을 위한 소켓 기초 정리](개발%20%28CS%29/게임서버/게임서버%20프로그래머%20책/[게임서버프로그래밍#6]%20클라이언트-서버%20구현을%20위한%20소켓%20기초%20정리.md)

### network byte order (네트워크 바이트 순서)

**네트워크로 보내는 멀티바이트 값(포트 번호, IP 주소, 프로토콜 헤더 필드)을 big endian으로 보내기로 한 약속.**

- little endian 장비(x86 등)는 보내기 전에 `htons`/`htonl`(host to network)로 바꾸고, 받은 뒤 `ntohs`/`ntohl`(network to host)로 되돌린다.
- 상세는 운영체제·시스템 노트의 endian 항목 참고.
- 학습 노트: [리틀엔디안-빅엔디안](개발%20실무/백엔드·데이터처리/[개발실무]%20리틀엔디안-빅엔디안%20-%20핵심%20개념%20및%20특징%20정리.md) · [엔디안(바이트 순서)과 인터넷 체크섬 — LSB·MSB와 htons를 직접 만들어보기](개발%20%28CS%29/언어/C언어/비트·바이트·정수/[C]%20엔디안%28바이트%20순서%29과%20인터넷%20체크섬%20—%20LSB·MSB와%20htons를%20직접%20만들어보기.md) · [3. 바이트 골격 — 비트플래그·엔디안·Pack·Unpack](개발%20%28CS%29/언어/C언어/코드%20골격/[골격]%203.%20바이트%20골격%20—%20비트플래그·엔디안·Pack·Unpack.md)

### L2 스위치

**MAC 주소를 보고 프레임을 해당 포트로만 전달하는 장비(같은 LAN 안).**

- "필터링"보다는 "MAC 주소 기반 전달(포워딩)"이 정확한 설명이다.
- 학습 노트: [ARP 프로토콜과 ARP Spoofing(MITM) 이론](개발%20%28CS%29/네트워크/[CS]%20ARP%20프로토콜과%20ARP%20Spoofing%28MITM%29%20이론%20-%20핵심%20개념%20및%20특징%20정리.md) · [Aruba 스위치 보안 하드닝 가이드](개발%20%28CS%29/네트워크/[Aruba]%20Aruba%20스위치%20보안%20하드닝%20가이드%20-%20핵심%20개념%20및%20특징%20정리.md)

### L3 스위치

**L2 스위치 기능에 IP 라우팅 기능을 더한 장비.**

- 서로 다른 네트워크(VLAN) 간 통신을 빠르게 라우팅한다.

### L4 스위치

**IP와 포트(TCP/UDP) 정보를 보고 트래픽을 분산하거나 제어하는 장비.**

- L4 로드밸런서로도 불린다. 더 위로 URL, 헤더, 쿠키 같은 L7 내용까지 보고 분산하는 것은 L7 스위치(로드밸런서)다.

### router (라우터)

**서로 다른 네트워크 사이에서 IP 주소를 보고 경로를 선택해 패킷을 전달하는 장비.**

### gateway (게이트웨이)

**서로 다른 네트워크나 시스템 사이의 출입구.**

- 네트워크 게이트웨이: 내부망이 외부로 나가는 출구(기본 게이트웨이).
- API gateway: 여러 서비스 앞에 두는 단일 진입점. 인증, 라우팅, 속도 제한, 로깅 같은 공통 처리를 한다.
- 학습 노트: [점진적 인증 전환과 게이트웨이 책임분리 패턴](개발%20실무/아키텍처·설계/인증·권한·게이트웨이/[HTTP]%20점진적%20인증%20전환과%20게이트웨이%20책임분리%20패턴%20-%20핵심%20개념%20및%20특징%20정리.md)

### proxy (프록시)

**클라이언트와 서버 사이에서 요청을 대신 전달하는 중간 서버(대리).**

- forward proxy: 클라이언트 쪽 대리. 접근 통제, 캐시에 쓴다.
- reverse proxy: 서버 쪽 대리. 로드밸런싱, TLS 종료, 보호에 쓴다.
- 중간에서 요청을 받으므로 전처리를 할 수 있지만, 정의의 핵심은 "대리"다.
- 학습 노트: [실무 프로젝트 및 오픈소스로 체득하는 GoF 핵심 디자인 패턴 10선 (Proxy, Decorator, Strategy, Chain, Template, SPI, Visitor, Facade)](개발%20실무/아키텍처·설계/설계%20패턴/[Design%20Pattern]%20실무%20프로젝트%20및%20오픈소스로%20체득하는%20GoF%20핵심%20디자인%20패턴%2010선%20%28Proxy,%20Decorator,%20Strategy,%20Chain,%20Template,%20SPI,%20Visitor,%20Facade%29.md)

### reverse proxy (리버스 프록시)

**서버 앞단에서 클라이언트의 요청을 대신 받아 뒤쪽 서버로 전달하는 중간 서버.**

- load balancing은 reverse proxy가 하는 일 중 하나일 뿐 전부는 아니다. 그 밖에 TLS 종료(암호화 처리), 캐시, 압축, 인증, URL별 라우팅, 뒤쪽 서버 숨기기(보안)를 한다.
- load balancer와 reverse proxy는 같은 말이 아니다. load balancer는 "분산"이 목적이고(L4도 가능), reverse proxy는 "대리 수신"이 정의다. nginx, HAProxy 같은 도구는 둘 다 수행한다.

### relay (릴레이)

**받은 메시지를 큰 변형 없이 다음 대상으로 중계하는 것.**

- proxy, gateway와 경계가 모호하고 제품마다 용어가 다르게 쓰인다. 중계에 초점이 있다는 정도로 이해한다.

### 방화벽 (firewall)

**규칙(IP, 포트, 프로토콜 등)에 따라 통신을 허용하거나 차단하는 보안 장치.**

- 상태 기반으로 연결을 추적하는 방식이 일반적이며, 웹 요청 내용까지 보는 WAF(웹 방화벽)는 L7을 본다.
- 학습 노트: [Linux 보안 · 원격 · 방화벽 · DNS 정리](개발%20%28CS%29/인프라/Linux/보안·네트워크/[Bash]%20Linux%20보안%20·%20원격%20·%20방화벽%20·%20DNS%20정리%20-%20핵심%20개념%20및%20특징%20정리.md)

### load balancing / load balancer (로드 밸런싱)

**들어온 요청(부하)을 여러 서버에 고르게 나누어 한 서버에 몰리지 않게 하는 것, 또는 그 장치·소프트웨어.**

- 분산 방식 예) round robin(순서대로), least connections(연결이 가장 적은 서버로), weighted(서버 성능에 따라 가중치), IP hash(같은 클라이언트는 같은 서버로).
- health check로 장애 난 서버를 제외하고 정상 서버로만 보낸다.
- L4(IP+포트 기준)와 L7(URL, 헤더, 쿠키 기준) 방식이 있다.
- 학습 노트: [로드밸런스](개발%20%28CS%29/인프라/모니터링·네트워크/[CS]%20로드밸런스%20-%20핵심%20개념%20및%20특징%20정리.md)

- HTTP/2는 하나의 연결에서 여러 요청을 동시에 주고받을 수 있다(multiplexing).
- 학습 노트: [HTTP 프로토콜 #1](개발%20%28CS%29/언어/JAVA/웹개발/HTTP/HTTP%20프로토콜%20#1.md) · [HTTP 이론](프레임워크/Spring%20Framework/HTTP·메시지%20변환/[Spring]%20HTTP%20이론%20-%20핵심%20개념%20및%20특징%20정리.md)

### HTTP 메서드 (GET / POST / PUT / PATCH / DELETE)

**요청이 "무엇을 하라는 것인지"를 나타낸다.**

- 학습 노트: [HTTP 프로토콜 #1](개발%20%28CS%29/언어/JAVA/웹개발/HTTP/HTTP%20프로토콜%20#1.md) · [HTTP 이론](프레임워크/Spring%20Framework/HTTP·메시지%20변환/[Spring]%20HTTP%20이론%20-%20핵심%20개념%20및%20특징%20정리.md)

| 메서드 | 의미 | 멱등 | 비고 |
| --- | --- | --- | --- |
| GET | 조회 | O | 본문 없이 자원을 가져온다 |
| POST | 생성, 또는 처리 요청 | 보통 X | 자원 생성에 가장 흔히 쓴다 |
| PUT | 전체 교체(없으면 생성) | O | 일부만 보내면 나머지가 사라진다 |
| PATCH | 부분 수정 | 설계에 따라 다름 | 바뀐 부분만 보낸다 |
| DELETE | 삭제 | O | |

- CRUD와의 대응: Create = POST(또는 PUT), Read = GET, Update = PUT/PATCH, Delete = DELETE.
- 주의: HTTP에는 `create`라는 메서드가 없다. "PUT = 수정"이 아니라 "PUT = 전체 교체"이고, 일부만 고치려면 PATCH를 쓴다.

### latency / throughput

**latency(지연)는 요청 후 응답까지 걸리는 시간, throughput(처리량)은 단위 시간당 처리하는 양.**

### throttling (스로틀링) / rate limiting

**단위 시간당 허용하는 요청 수를 제한해서 과부하를 막는 것.**

- "최대값을 정한다"는 이해가 맞다. 한도를 넘는 요청은 늦추거나 거절한다. 예) 초당 100건까지만 처리.
- HTTP에서는 보통 429 Too Many Requests로 거절하고, Retry-After 헤더로 다시 시도할 시점을 알려 줄 수 있다.
- rate limiting은 "한도 정책"을, throttling은 "그 한도에 맞게 속도를 조절하는 동작"을 가리키는 경우가 많지만 도구마다 같은 뜻으로 섞어 쓴다.
- 학습 노트: [장애 전파 방지 패턴 - Circuit Breaker·Bulkhead·Retry·Rate Limit](개발%20실무/아키텍처·설계/분산%20시스템·장애%20대응/[Architecture]%20장애%20전파%20방지%20패턴%20-%20Circuit%20Breaker·Bulkhead·Retry·Rate%20Limit.md)

### traffic spike (트래픽 급증)

**짧은 시간에 요청량(트래픽)이 평소보다 갑자기 크게 늘어나는 현상.**

- 원인 예) 이벤트·프로모션, 장애 복구 직후 클라이언트가 한꺼번에 다시 접속, 실패한 요청의 재시도가 몰리는 경우(retry storm), 배치 작업이 같은 시각에 시작.
- 처리 능력을 넘으면 응답 지연, 오류, 장애로 이어진다.
- 대응 수단: 서버를 늘리는 scale-out(자동 확장), throttling으로 한도 제한, 큐로 완충, 캐시, 로드밸런싱. 재시도 간격을 점점 늘리는(backoff) 것도 spike를 줄인다.
- 학습 노트: [장애 전파 방지 패턴 - Circuit Breaker·Bulkhead·Retry·Rate Limit](개발%20실무/아키텍처·설계/분산%20시스템·장애%20대응/[Architecture]%20장애%20전파%20방지%20패턴%20-%20Circuit%20Breaker·Bulkhead·Retry·Rate%20Limit.md) · [쿠버네티스 기본 개념 - Pod·Node·Cluster·Deployment](개발%20%28CS%29/인프라/컨테이너·가상화/[K8s]%20쿠버네티스%20기본%20개념%20-%20Pod·Node·Cluster·Deployment.md)

### keep-alive / connection pool

**keep-alive는 요청 하나가 끝나도 TCP 연결을 끊지 않고 재사용하는 것, connection pool은 연결을 미리 여러 개 만들어 두고 돌려 쓰는 것.**

- 연결을 맺는 비용(3-way handshake, TLS)을 아낀다.
- 주의: 클라이언트 pool의 idle timeout이 서버나 로드밸런서의 idle timeout보다 길면, 이미 끊긴 연결을 재사용하다 오류가 난다. 클라이언트 쪽을 더 짧게 둔다.
- 학습 노트: [Connection Pool의 이해와 DataSource](개발%20%28CS%29/데이터베이스/JDBC/[DataSource]%20Connection%20Pool의%20이해와%20DataSource.md) · [장애 전파 방지 패턴 - Circuit Breaker·Bulkhead·Retry·Rate Limit](개발%20실무/아키텍처·설계/분산%20시스템·장애%20대응/[Architecture]%20장애%20전파%20방지%20패턴%20-%20Circuit%20Breaker·Bulkhead·Retry·Rate%20Limit.md)

### DNS 캐시 / TTL

**도메인 → IP 변환 결과는 여러 층에서 캐시된다. 애플리케이션(JVM 등), OS·로컬 DNS 캐시, DNS 서버 순이다.**

- 원본 DNS 값이 바뀌어도 중간에 옛 값이 남아 있으면 이미 사라진 서버로 접속하거나 조회에 실패한다(stale cache). IP가 자주 바뀌는 클라우드·쿠버네티스에서 특히 자주 겪는다.
- TTL은 레코드를 캐시해도 되는 시간이다. 조회 실패 결과도 일정 시간 캐시하는(negative caching) 설정이 있어서, DNS가 잠깐 실패하면 그 뒤 한동안 계속 실패할 수 있다. 확인은 각 층의 캐시와 TTL 설정을 순서대로 본다.
- 학습 노트: [DNS](개발%20%28CS%29/인프라/모니터링·네트워크/[Bash]%20DNS%20-%20핵심%20개념%20및%20특징%20정리.md) · [인터넷 통신과정 ( + IP, TCP-UDP, PORT, DNS )](개발%20%28CS%29/언어/JAVA/웹개발/HTTP/인터넷%20통신과정%20%28%20+%20IP,%20TCP-UDP,%20PORT,%20DNS%20%29.md)

### Control Plane / User Plane (3GPP 통신망)

**control plane(제어 평면)은 연결 설정, 인증, 이동성 관리 같은 제어 신호를 다루는 부분이고, user plane(사용자 평면)은 실제 사용자 데이터(영상, 인터넷 트래픽)를 나르는 부분.**

- 두 평면을 나누면 독립적으로 확장하고 설계할 수 있다. 일반 네트워크 장비의 control plane / data plane 구분과 같은 개념이다.
