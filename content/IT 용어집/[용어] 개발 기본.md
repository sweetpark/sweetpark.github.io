# 개발 기본 개념

> 코드를 읽고 쓸 때 자주 나오는 개념 용어

- 용어 38개

---

### API (Application Programming Interface)

**프로그램끼리 기능을 호출하기 위해 공개한 약속된 창구.**

- 함수·클래스 형태일 수도 있고, HTTP로 호출하는 REST API일 수도 있다.
- 학습 노트: [API 개념](개발%20%28CS%29/인프라/인프라%20기초%20지식/[CS]%20API%20개념%20-%20핵심%20개념%20및%20특징%20정리.md)

### interface (인터페이스)

**내부 구현은 숨기고, 외부에는 "이렇게 호출하면 이렇게 동작한다"는 규약만 공개한 접점.**

- 호출하는 쪽(caller)이 아니라 "호출 규약"이다. 함수 시그니처, 클래스의 메서드 목록, API 명세, 통신 규격 모두 interface다.
- 통신망에서는 장비·기능 사이의 연결 지점(예: 3GPP의 NF 간 interface)을 뜻하기도 한다.

### library (라이브러리)

**필요할 때 내가 호출해서 쓰는 함수·클래스 모음.**

- 흐름의 주도권은 내 코드에 있다. framework와 비교해 기억하면 쉽다.
- 학습 노트: [라이브러리 (라이브러리, 모듈)](개발%20%28CS%29/언어/JAVA/기술면접/[JAVA%20기술면접]%20라이브러리%20%28라이브러리,%20모듈%29.md)

### framework (프레임워크)

**전체 구조와 실행 흐름을 틀로 제공하고, 그 틀 안에 내 코드를 끼워 넣어 쓰는 기반.**

- library는 "내가 호출", framework는 "틀이 나를 호출"(제어의 역전, Inversion of Control)이라는 점이 핵심 차이다.
- 예) Spring, Django.
- 학습 노트: [스프링 핵심원리](프레임워크/Spring%20Framework/역사·핵심%20원리/[Spring]%20스프링%20핵심원리%20-%20핵심%20개념%20및%20특징%20정리.md) · [Spring 역사 #3 (Spring의 탄생)](프레임워크/Spring%20Framework/역사·핵심%20원리/Spring%20역사%20%233%20%28Spring의%20탄생%29.md)

### SDK (Software Development Kit)

**특정 플랫폼·서비스용 프로그램을 만들 수 있게 묶어 놓은 개발 도구 모음.**

- 라이브러리, 도구, 문서, 예제 코드 등이 함께 들어 있다. "server"가 아니라 "software" development kit이다.

### caller / callee

**함수를 호출하는 쪽(caller) / 호출받는 쪽(callee).**

- 네트워크에서는 요청하는 client와 응답하는 server의 관계와 비슷하다.

### 전처리 / 후처리

**핵심 비즈니스 로직 실행 전/후에 공통으로 하는 작업.**

- 전처리 예) 인증, 입력값 검증, 로깅 시작. 후처리 예) 응답 변환, 로깅 종료, 자원 정리.
- 구현 방식은 filter, interceptor, middleware, hook 등으로 부른다.
- 학습 노트: [Servlet Filter](프레임워크/Spring%20Framework/웹%20기술%20%28Filter·세션·업로드%29/Servlet%20Filter.md) · [Spring Intercept](프레임워크/Spring%20Framework/웹%20기술%20%28Filter·세션·업로드%29/Spring%20Intercept.md) · [실무 프로젝트 및 오픈소스로 체득하는 GoF 핵심 디자인 패턴 10선 (Proxy, Decorator, Strategy, Chain, Template, SPI, Visitor, Facade)](개발%20실무/아키텍처·설계/설계%20패턴/[Design%20Pattern]%20실무%20프로젝트%20및%20오픈소스로%20체득하는%20GoF%20핵심%20디자인%20패턴%2010선%20%28Proxy,%20Decorator,%20Strategy,%20Chain,%20Template,%20SPI,%20Visitor,%20Facade%29.md)

### middleware (미들웨어)

**요청과 응답 흐름 중간에 끼어 공통 처리를 하는 계층.**

- 여러 middleware가 순서대로 이어지는 "체인" 구조가 많다.
- 학습 노트: [Servlet Filter](프레임워크/Spring%20Framework/웹%20기술%20%28Filter·세션·업로드%29/Servlet%20Filter.md) · [Spring Intercept](프레임워크/Spring%20Framework/웹%20기술%20%28Filter·세션·업로드%29/Spring%20Intercept.md)

### callback (콜백)

**어떤 일이 끝났거나 이벤트가 발생했을 때 나중에 호출되도록 넘겨 두는 함수(또는 URL).**

- 서버가 클라이언트에게 결과를 알려주려고 미리 받아 둔 주소로 호출하는 방식도 callback이라고 부른다.
- 학습 노트: [콜백함수 (함수객체, 템플릿)](개발%20%28CS%29/언어/C++/함수·템플릿·콜백/[C++]%20콜백함수%20%28함수객체,%20템플릿%29.md) · [POST & CALLBACK (libcurl HTTP 통신)](개발%20%28CS%29/언어/C언어/네트워크·시스템%20IO/[HTTP]%20POST%20&%20CALLBACK%20%28libcurl%20HTTP%20통신%29%20-%20핵심%20개념%20및%20특징%20정리.md) · [비동기 요청-응답의 타임아웃 감시 — Check-in과 Check-out 타이머 패턴](개발%20%28CS%29/언어/C언어/동시성·스레드/[C]%20비동기%20요청-응답의%20타임아웃%20감시%20—%20Check-in과%20Check-out%20타이머%20패턴.md)

### 동기 / 비동기 (sync / async)

**동기는 결과가 나올 때까지 이어서 기다리고, 비동기는 요청만 해 두고 다른 일을 하다가 결과를 나중에 받는 방식.**

- 학습 노트: [Non blocking - Select Model](개발%20%28CS%29/네트워크/[CS]%20Non%20blocking%20-%20Select%20Model%20-%20핵심%20개념%20및%20특징%20정리.md) · [대용량 처리 비동기 Job 큐 설계 패턴](개발%20실무/아키텍처·설계/대용량%20비동기·배치/[HTTP]%20대용량%20처리%20비동기%20Job%20큐%20설계%20패턴%20-%20핵심%20개념%20및%20특징%20정리.md)

### blocking / non-blocking

**blocking은 호출이 끝날 때까지 그 자리에서 멈춰 기다리고, non-blocking은 기다리지 않고 바로 돌아온다.**

- 동기/비동기와 비슷해 보이지만 "호출한 쪽이 멈추는가"에 초점을 둔 말이다.
- 학습 노트: [Non blocking - Select Model](개발%20%28CS%29/네트워크/[CS]%20Non%20blocking%20-%20Select%20Model%20-%20핵심%20개념%20및%20특징%20정리.md) · [select() — 여러 입력과 타임아웃 함께 기다리기](개발%20%28CS%29/언어/C언어/네트워크·시스템%20IO/[C]%20select%28%29%20—%20여러%20입력과%20타임아웃%20함께%20기다리기.md) · [epoll — fd가 많아질 때의 대안](개발%20%28CS%29/언어/C언어/네트워크·시스템%20IO/[C]%20epoll%20—%20fd가%20많아질%20때의%20대안.md)

### idempotent (멱등성)

**같은 요청을 여러 번 보내도 서버 상태가 한 번 보낸 것과 같은 성질.**

- HTTP에서 GET, PUT, DELETE는 멱등이고 POST는 일반적으로 아니다.
- 재시도(retry)를 안전하게 하려면 멱등이어야 한다.
- 학습 노트: [HTTP 프로토콜 #2 ( Method )](개발%20%28CS%29/언어/JAVA/웹개발/HTTP/HTTP%20프로토콜%20%232%20%28%20Method%20%29.md) · [분산 락과 멱등성 키 설계](개발%20실무/아키텍처·설계/분산%20시스템·장애%20대응/[Architecture]%20분산%20락과%20멱등성%20키%20설계.md)

### serialization / deserialization (직렬화 / 역직렬화)

**객체를 전송·저장할 수 있는 바이트나 문자열(예: JSON)로 바꾸는 것 / 다시 객체로 되돌리는 것.**

- 관련 노트: [Java 직렬화-역직렬화](개발%20%28CS%29/CS%20기초/[Java]%20직렬화-역직렬화%20-%20핵심%20개념%20및%20특징%20정리.md)

### parsing (파싱)

**문자열이나 데이터를 규칙에 따라 읽어서 의미 있는 구조로 바꾸는 것.**

- 예) JSON 문자열을 읽어 객체로 만든다.
- 학습 노트: [strtok_r과 sscanf 문자열 파싱 원리 및 &save 동작 분석](개발%20%28CS%29/언어/C언어/문자열·파싱/[Lang]%20strtok_r과%20sscanf%20문자열%20파싱%20원리%20및%20&save%20동작%20분석.md) · [snprintf와 sscanf — 문자열 조립과 파싱의 차이](개발%20%28CS%29/언어/C언어/문자열·파싱/[C]%20snprintf와%20sscanf%20—%20문자열%20조립과%20파싱의%20차이.md)

### handling (핸들링)

**어떤 상황, 오류, 요청을 받아 적절히 처리하는 것.**

- 예) 에러 핸들링 = 오류가 났을 때 어떻게 처리할지 정해 둔 것. "핸들링이 필요하다"는 방치하면 문제가 되니 처리 로직이 필요하다는 뜻.
- 학습 노트: [Exception(Checked 예외, UnChecked예외)](개발%20%28CS%29/언어/JAVA/중급·핵심%20정리/[JAVA]%20Exception%28Checked%20예외,%20UnChecked예외%29.md) · [예외처리 (API)](프레임워크/Spring%20Framework/검증·예외처리·로그/예외처리%20%28API%29.md)

### bug / defect (버그 / 결함)

**프로그램이 의도와 다르게 동작하게 만드는 코드의 오류.**

- bug는 코드나 설계의 잘못 자체(결함, defect)를 가리키고, 실제로 겉으로 드러난 오작동은 failure(장애)라고 구분하기도 한다.
- 코드 리뷰의 nit(사소한 지적)와는 다르다. nit는 결함이 아니라 스타일 수준이다(Git·버전관리 노트 참고).

### debug (디버그)

**프로그램의 오류(bug)를 찾아 원인을 파악하고 고치는 작업.**

- "프로세스를 면밀히 들여다본다"는 디버그의 핵심 수단이다. 실행을 멈추고 변수 값, 호출 순서, 메모리 상태를 확인하거나(디버거), 로그를 남겨서 흐름을 추적한다.
- 원인을 찾는 것(분석)에서 끝나지 않고 고쳐서 확인하는 것까지 포함한다.
- 학습 노트: [GDB 실전 디버깅 (멀티스레드·시그널)](개발%20%28CS%29/인프라/Linux/디버깅·성능·빌드%20도구/[Tool]%20GDB%20실전%20디버깅%20%28멀티스레드·시그널%29.md) · [process 비정상 종료 트러블 슈팅 목록](개발%20%28CS%29/언어/C언어/트러블슈팅/process%20비정상%20종료%20트러블%20슈팅%20목록.md)

### debugger / breakpoint (디버거 / 중단점)

**debugger는 실행 중인 프로그램을 멈추고 한 줄씩 진행하며 내부 상태를 볼 수 있게 해 주는 도구, breakpoint는 "여기서 멈춰라"고 지정한 지점.**

- step(한 줄씩 실행), continue(다음 중단점까지 실행), backtrace(호출 순서 확인)가 기본 동작이다. C/C++에서는 gdb가 대표적이다(운영체제·시스템 노트 참고).
- 학습 노트: [GDB 실전 디버깅 (멀티스레드·시그널)](개발%20%28CS%29/인프라/Linux/디버깅·성능·빌드%20도구/[Tool]%20GDB%20실전%20디버깅%20%28멀티스레드·시그널%29.md)

### log (로그)

**프로그램이 실행 중에 남기는 기록.**

- 디버거를 붙일 수 없는 운영 환경에서는 로그가 주된 분석 수단이다. 중요도에 따라 level(DEBUG, INFO, WARN, ERROR)을 나눈다.
- 학습 노트: [Log 설정 및 Logging 사용](프레임워크/Spring%20Framework/검증·예외처리·로그/Log%20설정%20및%20Logging%20사용.md) · [Logback](개발%20%28CS%29/CS%20기초/[Spring]%20Logback%20-%20핵심%20개념%20및%20특징%20정리.md) · [성능 분석 도구와 관측 - perf·flame graph·eBPF·메모리](개발%20%28CS%29/인프라/Linux/디버깅·성능·빌드%20도구/[Tool]%20성능%20분석%20도구와%20관측%20-%20perf·flame%20graph·eBPF·메모리.md)

### timeout / retry

**timeout은 응답을 기다리는 최대 시간, retry는 실패했을 때 다시 시도하는 것.**

- retry는 멱등성이 보장될 때 안전하다.
- 학습 노트: [장애 전파 방지 패턴 - Circuit Breaker·Bulkhead·Retry·Rate Limit](개발%20실무/아키텍처·설계/분산%20시스템·장애%20대응/[Architecture]%20장애%20전파%20방지%20패턴%20-%20Circuit%20Breaker·Bulkhead·Retry·Rate%20Limit.md) · [비동기 요청-응답의 타임아웃 감시 — Check-in과 Check-out 타이머 패턴](개발%20%28CS%29/언어/C언어/동시성·스레드/[C]%20비동기%20요청-응답의%20타임아웃%20감시%20—%20Check-in과%20Check-out%20타이머%20패턴.md)

### patch (소프트웨어)

**이미 배포된 프로그램의 버그나 취약점을 고치는 작은 수정.**

- HTTP의 PATCH 메서드(부분 수정)와 이름이 같지만 다른 개념이다. → 네트워크·통신 노트의 HTTP 메서드 참고.
- diff로 만든 "변경점 파일"을 patch라고 부르기도 한다.
- 학습 노트: [FUNCTION PATCH](개발%20%28CS%29/인프라/형상관리/[Bash]%20FUNCTION%20PATCH%20-%20핵심%20개념%20및%20특징%20정리.md)

### refactoring (리팩터링)

**겉으로 보이는 동작은 바꾸지 않고 내부 구조를 정리하는 것.**

### legacy (레거시)

**오래되어 유지보수가 어렵지만 아직 운영 중인 시스템이나 코드.**

### deprecated

**앞으로 제거될 예정이라 사용을 권장하지 않는 기능.**

- 대체 기능이 안내되는 경우가 많다.

### backward compatibility (하위 호환성)

**새 버전이 이전 버전의 사용 방식도 그대로 지원하는 것.**

### hardcoding (하드코딩)

**바뀔 수 있는 값을 코드에 직접 박아 넣는 것.**

- 설정 파일이나 환경 변수로 분리하는 것이 일반적인 대안.

### overload (오버로딩) / 과부하

**코드에서는 같은 이름의 함수(메서드)를 매개변수의 개수나 타입을 달리해 여러 개 정의하는 것. "덮어쓰기"가 아니라 "같은 이름의 함수가 여러 개 공존"하는 것이다.**

- 예) `print(int)`, `print(String)`, `print(int, int)`. 호출할 때 넘긴 인자에 맞는 것이 선택되며, 컴파일 시점에 결정된다.
- 반환 타입만 다른 것은 overload가 되지 않는다(매개변수가 달라야 한다). Python처럼 overload를 지원하지 않는 언어에서는 같은 이름으로 다시 정의하면 앞의 것이 덮어써진다.
- 시스템·통신 맥락의 overload는 전혀 다른 뜻으로, 처리 능력을 넘는 "과부하" 상태다(overload control, throttling).
- 학습 노트: [연산자 오버로딩 (대입연산자, 전위-후위연산자)](개발%20%28CS%29/언어/C++/클래스·객체지향/[C++]%20연산자%20오버로딩%20%28대입연산자,%20전위-후위연산자%29.md)

### override (오버라이딩)

**상속받은 하위 클래스가 부모 클래스의 같은 이름, 같은 매개변수의 메서드를 자기 방식으로 다시 정의하는 것. "덮어쓰기"에 가까운 쪽은 이것이다.**

- 부모 타입 변수로 호출해도 실제 객체가 자식이면 자식의 메서드가 실행된다. 어떤 것을 실행할지는 실행 시점에 결정된다(다형성, polymorphism).
- Java의 `@Override`, C++의 `virtual` / `override`는 "부모 메서드를 재정의한다"는 표시다. 실수로 이름이나 매개변수를 틀리면 컴파일러가 알려 준다.
- 설정 값을 "기본값 위에 덮어쓴다"는 뜻으로도 쓴다(예: 환경 변수로 설정 파일 값을 override).
- 학습 노트: [객체 지향 (다형성)](개발%20%28CS%29/언어/C++/클래스·객체지향/[C++]%20객체%20지향%20%28다형성%29.md) · [객체지향 특징 (4가지 특징, SOLID)](개발%20%28CS%29/언어/JAVA/기술면접/[JAVA%20기술면접]%20객체지향%20특징%20%284가지%20특징,%20SOLID%29.md)

### polymorphism (다형성)

**같은 이름의 호출(인터페이스)이라도 대상 객체에 따라 다르게 동작하는 성질.**

- override가 대표적인 구현 방법이다. 호출하는 쪽은 구체 타입을 몰라도 된다.
- 학습 노트: [객체 지향 (다형성)](개발%20%28CS%29/언어/C++/클래스·객체지향/[C++]%20객체%20지향%20%28다형성%29.md)

### dead code (데드 코드)

**실행되지 않거나, 실행돼도 결과에 영향을 주지 않는 코드.**

- 호출되지 않는 함수, 도달할 수 없는 분기, 주석 처리해 둔 옛 코드 등. 읽는 사람을 헷갈리게 하므로 지우는 것이 좋고, 필요하면 Git 이력에서 되살릴 수 있다.
- 학습 노트: [전처리기 조건부 컴파일 — #if 0으로 코드 끄기와 빌드 옵션 분기](개발%20%28CS%29/언어/C언어/전처리기·링키지·함수%20응용/[C]%20전처리기%20조건부%20컴파일%20—%20%23if%200으로%20코드%20끄기와%20빌드%20옵션%20분기.md)

### md (Markdown)

**간단한 기호로 서식을 표현하는 텍스트 문서 형식(확장자 .md).**

- `# 제목`, `- 목록`, `**굵게**`처럼 쓰고, 렌더러가 서식이 적용된 문서로 보여 준다.
- GitHub README, 기술 문서, Obsidian·노션 같은 노트 도구에서 널리 쓴다. 일반 텍스트라 Git으로 변경 이력을 관리하기 좋다.

### template (템플릿)

**변하는 부분을 비워 둔 틀. 값이나 타입을 채워 넣어 여러 번 찍어내는 용도.**

- C++ template: 타입을 매개변수로 받는 함수·클래스를 한 번 작성해 여러 타입에 쓰는 기능(제네릭 프로그래밍). 예) `template<typename T> T max(T a, T b)`, `std::vector<int>`. 컴파일할 때 타입별 코드가 만들어진다. Java, C#의 generics와 비슷한 개념이다.
- 일반 의미: 문서, 이슈, PR의 양식(PR 템플릿), HTML의 값만 바꿔 끼우는 템플릿 엔진(Thymeleaf, Jinja) 등.
- "뼈대"라고 번역하는 경우가 있지만, 핵심은 "변하는 자리가 표시된 틀"이라는 점이다. skeleton과 구분해서 쓴다.
- 학습 노트: [Template (함수 템플릿)](개발%20%28CS%29/언어/C++/함수·템플릿·콜백/[C++]%20Template%20%28함수%20템플릿%29.md) · [Template (클래스 템플릿)](개발%20%28CS%29/언어/C++/함수·템플릿·콜백/[C++]%20Template%20%28클래스%20템플릿%29.md) · [동적 템플릿 엔진 설계 패턴 (계층화·SpEL·Chain of](프레임워크/Spring%20Framework/실습%20%28스프링%20MVC%29/[Spring]%20동적%20템플릿%20엔진%20설계%20패턴%20%28계층화·SpEL·Chain%20of%20-%20핵심%20개념%20및%20특징%20정리.md)

### skeleton (스켈레톤)

**구조만 만들어 두고 내용(구현)은 비워 둔 최소한의 뼈대 코드.**

- template과의 차이: skeleton은 이미 구체적인 하나의 뼈대(복사해서 살을 붙여 가는 시작점)이고, template은 변하는 자리를 비워 두고 여러 번 찍어내는 틀이다.
- 프로젝트 skeleton: 초기 폴더 구조, 빌드 설정, 빈 클래스와 함수만 만들어 둔 시작 코드. 구조를 먼저 합의할 때 쓴다.
- RPC·원격 호출 용어로는 client 쪽 대리 코드를 stub, server 쪽에서 요청을 받아 실제 구현을 호출해 주는 코드를 skeleton이라 부른다.
- 학습 노트: [c코드 골격 목록](개발%20%28CS%29/언어/C언어/코드%20골격/c코드%20골격%20목록.md)

### boilerplate (보일러플레이트)

**거의 모든 프로젝트에서 똑같이 반복해 써야 하는 정형 코드.**

- 프레임워크나 생성 도구(scaffolding)가 줄여 주는 대상이다.

### queue (큐)

**먼저 넣은 데이터를 먼저 꺼내는 선입선출(FIFO, First In First Out) 자료구조.**

- 줄서기와 같다. 넣는 동작은 enqueue, 꺼내는 동작은 dequeue.
- 예) 작업 대기열, 메시지 큐(운영체제·시스템 노트 참고).
- 관련 노트: 큐
- 학습 노트: [배열 기반 원형 큐(Ring Buffer) — front·back 인덱스로 만드는 큐](개발%20%28CS%29/언어/C언어/동시성·스레드/[C]%20배열%20기반%20원형%20큐%28Ring%20Buffer%29%20—%20front·back%20인덱스로%20만드는%20큐.md)

### stack (스택)

**마지막에 넣은 데이터를 먼저 꺼내는 후입선출(LIFO, Last In First Out) 자료구조.**

- 접시를 쌓고 위에서부터 꺼내는 것과 같다. 넣는 동작은 push, 꺼내는 동작은 pop.
- 예) 함수 호출 순서를 기록하는 call stack, 되돌리기(undo).
- 같은 이름의 "스택 메모리(함수 호출 때 쓰는 메모리 영역)"도 이 구조로 동작한다.
- 관련 노트: 스택

### priority queue (우선순위 큐)

**넣은 순서가 아니라 우선순위가 높은 데이터부터 꺼내는 큐.**

- 보통 heap(힙)이라는 구조로 구현한다.
- 학습 노트: [우선순위 큐 (+JAVA)](개발%20%28CS%29/CS%20기초/자료구조/[자료구조]%20우선순위%20큐%20%28+JAVA%29.md)

### hash table (해시 테이블)

**키(key)를 해시 함수로 저장 위치로 바꿔서, 키로 값을 평균적으로 바로 찾는 자료구조.**

- 서로 다른 키가 같은 위치로 가는 충돌(collision)은 연결 리스트 등으로 처리한다. 예) 파이썬 dict, 자바 HashMap.
