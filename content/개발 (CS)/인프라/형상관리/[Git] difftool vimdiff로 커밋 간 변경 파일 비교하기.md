# Git difftool + vimdiff로 커밋 간 변경 파일 비교하기

> 코드 리뷰나 소스 점검처럼 "기준 커밋 이후 무엇이 바뀌었는지"를 파일 단위로 훑어야 할 때, **변경 파일 목록을 먼저 뽑고 → 파일별로 vimdiff 화면에서 좌우 비교**하는 방식이다. 서버(터미널)에 GUI 없이 vi/vim만 있어도 쓸 수 있다. vim 사용법은 [VIM 사용법](개발%20%28CS%29/인프라/Linux/기본%20사용·명령어/[CS]%20명령어%20VIM%20사용법%20-%20핵심%20개념%20및%20특징%20정리.md) 참고.

## 1. 전체 흐름

```mermaid
flowchart LR
    A[기준 커밋 해시 확인] --> B["git diff --name-only<br/>변경 파일 목록"]
    B --> C["git difftool -t vimdiff -y<br/>파일 하나씩 열기"]
    C --> D[좌우 비교 · 필요 시 수정]
    D --> E[":qa 로 닫고 다음 파일"]
```

## 2. 변경 파일 목록 뽑기

```bash
# 기준 커밋과 HEAD 비교 (파일 이름만)
git diff --name-only 4c7e44a..HEAD
```

- `--name-only`는 내용 없이 **경로만** 출력한다. 이 목록이 곧 오늘 볼 작업 대상이다.
- 해시는 앞 7자리만 써도 된다(전체 40자리와 같은 커밋을 가리킨다).
- 추가·삭제 여부까지 보려면 `--name-status`(`A` 추가, `M` 수정, `D` 삭제, `R` 이름 변경)를 쓴다.
- 폴더 단위로 좁히려면 뒤에 경로를 붙인다: `git diff --name-only 4c7e44a..HEAD -- src/모듈`

## 3. vimdiff로 파일 하나 열기

```bash
git difftool -t vimdiff -y 4c7e44a -- path/to/file.h
```

| 옵션 | 의미 |
| --- | --- |
| `-t vimdiff` | 비교 도구로 vimdiff를 사용(`--tool=vimdiff`) |
| `-y` | 파일마다 "launch vimdiff?" 확인을 묻지 않음(`--no-prompt`) |
| `4c7e44a` | 기준 커밋 |
| `--` | 이후는 경로라는 구분자. 브랜치명과 파일명이 헷갈릴 때 안전 |
| 경로 | 생략하면 변경된 **모든 파일을 순서대로** 하나씩 연다. 폴더를 주면 그 하위만 연다 |

폴더를 통째로 주면 하위 변경 파일을 차례로 열어 준다(`:qa`로 하나 닫으면 다음 파일이 열림).

```bash
git difftool -t vimdiff -y 4c7e44a -- src/PRMGR
```

### 자주 틀리는 점: `기준` vs `기준..HEAD`

| 명령 | 비교 대상 | 오른쪽 파일 수정 |
| --- | --- | --- |
| `git difftool 4c7e44a -- 파일` | 기준 커밋 ↔ **작업 디렉터리(실제 파일)** | **저장하면 실제 파일에 반영됨** |
| `git difftool 4c7e44a..HEAD -- 파일` | 기준 커밋 ↔ HEAD (**둘 다 커밋 내용**) | 임시 파일이라 **저장해도 반영 안 됨** |

- 보기만 할 거라면 어느 쪽이든 상관없다.
- **비교하면서 바로 고치려면 `..HEAD`를 빼고** 기준 커밋만 준다(그러면 오른쪽이 실제 작업 파일이다).
- 아직 commit하지 않은 변경이 있으면 `기준`만 준 쪽에는 그 변경도 함께 나온다.

## 4. 화면 구성

```
┌───────────────────────┬───────────────────────┐
│ LOCAL (왼쪽)          │ 오른쪽                │
│ 기준 커밋 시점의 파일 │ 비교 대상(작업 파일)  │
└───────────────────────┴───────────────────────┘
```

- 다른 줄은 색으로 강조되고, 같은 부분이 길게 이어지면 **접힌 상태(`+-- N lines: ...`)**로 보인다.
- 3-way(merge 충돌 해결용)와 달리 difftool은 **좌우 2창**이다.

## 5. vimdiff 단축키

| 하고 싶은 것 | 키 |
| --- | --- |
| 다음 변경 구간으로 이동 | `]c` |
| 이전 변경 구간으로 이동 | `[c` |
| 왼쪽 ↔ 오른쪽 창 이동 | `Ctrl-w w` (또는 `Ctrl-w h` / `Ctrl-w l`) |
| 상대 창의 내용을 **내 쪽으로 가져오기**(obtain) | `do` (`:diffget`) |
| 내 내용을 **상대 창으로 보내기**(put) | `dp` (`:diffput`) |
| 접힌 부분 펼치기 / 다시 접기 | `zo` / `zc` |
| 접힌 부분 전부 펼치기 | `zR` |
| 수정 후 diff 표시 다시 계산 | `:diffupdate` |
| 저장 | `:w` |
| 두 창 모두 닫기(현재 파일 끝, 다음 파일로) | `:qa` |
| 저장하고 모두 닫기 | `:wqa` |
| 저장 없이 모두 닫기 | `:qa!` |
| **남은 파일 비교 전체 중단** | `:cq` (비정상 종료 코드로 나가 difftool 순회를 멈춤) |

- 수정은 **작업 파일이 있는 쪽(오른쪽)**에서 한다. 왼쪽(기준 커밋 쪽)을 고쳐 저장해도 임시 파일이라 의미가 없다.
- 기준 시점 코드를 되살리고 싶은 줄은 오른쪽 창에서 그 구간으로 이동해 `do`를 누르면 왼쪽 내용이 오른쪽에 들어온다.

## 6. 여러 파일을 순서대로 보는 요령

```bash
# 목록 파일로 저장해 두고, 본 파일을 체크하며 진행
git diff --name-only 4c7e44a..HEAD > /tmp/changed.txt

# 목록을 순서대로 하나씩 열기 (:qa 하면 다음 파일)
while read f; do git difftool -t vimdiff -y 4c7e44a -- "$f"; done < /tmp/changed.txt
```

- 같은 모듈 파일끼리(`*.h` → `*.c`)는 헤더·구조체 변경을 먼저 보고 구현을 보면 이해가 빠르다.
- 매번 `-t vimdiff`를 치기 싫으면 기본 도구로 등록한다.

```bash
git config --global diff.tool vimdiff
git config --global difftool.prompt false
# 이후: git difftool 4c7e44a -- 파일
```

## 7. 정리

| 목적 | 명령 |
| --- | --- |
| 변경 파일 목록 | `git diff --name-only <기준>..HEAD` |
| 보기만 | `git difftool -t vimdiff -y <기준>..HEAD -- <경로>` |
| 보면서 수정 | `git difftool -t vimdiff -y <기준> -- <경로>` |
| 구간 이동 / 가져오기 / 보내기 | `]c` `[c` / `do` / `dp` |
| 종료 / 전체 중단 | `:qa` / `:cq` |
