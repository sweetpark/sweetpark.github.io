# 로드밸런스

> [!NOTE]
> 로드밸런서 종류(L4/L7)와 세션 관리 방식(sticky / clustering / storage)의 장단점, 네트워크 로드밸런서 구성(Listener + Target Group) 정리.

## 📌 개념

### 로드밸런스 종류

- Network 로드밸런스(L4)
- Application 로드밸런스(L7)
- Network Proxy 로드밸런스

### 세션 관리 방식

- **Sticky Session**
    - 동일한 서버로 보내도록 로드밸런서가 쿠키를 생성·저장(원래 처리했던 서버에서 처리 → 세션을 따로 관리하지 않아도 됨)
    - 단점
        - 서버끼리 세션을 공유하지 않아, 서버가 다운되면 재로그인이 필요할 수 있음
        - 특정 서버에만 요청이 집중되면 다른 서버가 여유롭더라도 부하가 발생할 수 있음
- **Session Clustering**
    - 세션들을 서로 다른 서버가 복제하여 보유
    - sticky에서 발생하는 한 서버 집중 부하를 없앨 수 있음
    - 단점
        - 세션을 복제하므로 많은 메모리를 사용할 수 있음
        - 서버를 추가할 때마다 복제 작업이 필요함
- **Session Storage**
    - 세션을 저장하는 공통 DB를 두어 사용 (예: Redis, Memcached)
    - 서버 부하 방지, 세션 관리, 메모리 효율적 사용 가능
    - 단점
        - Redis/Memcached 장애 시 세션 인증 불가로 서비스가 일시 중단될 수 있음
        - 사용하는 세션 저장소의 장단점을 고려해 선택해야 함

### 네트워크 로드밸런스 구성

- **Listener + Target Group**
    - **Listener**: 외부에서 들어오는 "프로토콜 + 포트"를 이용해 지정한 Target Group으로 라우팅
    - **Target Group**: 라우팅되어 도착하는 목적지 서버
