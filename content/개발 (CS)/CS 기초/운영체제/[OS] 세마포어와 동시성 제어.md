# 세마포어와 동시성 제어

> [!NOTE]
> 세마포어가 동시성 제어 도구이면서 동시에 IPC로 분류되는 이유, 스레드용 도구와 프로세스용 도구가 갈리는 기준, System V 세마포어 기본 API를 정리한다.

## 1. 세마포어의 본질: 동시성 제어

세마포어는 원래 여러 실행 흐름이 공유 자원에 접근할 때 순서를 맞추는 카운터/락 메커니즘입니다. 뮤텍스, 조건변수와 같은 계열이라고 보면 됩니다.

## 2. 근데 왜 IPC로 분류되나

동시성 제어가 필요한 대상이 **어디에 있느냐**에 따라 도구가 갈립니다.

| 대상 | 도구 | IPC 여부 |
| --- | --- | --- |
| 한 프로세스 안의 여러 스레드 | `pthread_mutex`, `pthread_cond`, 이름없는 세마포어(`sem_init`, `pshared=0`) | 아님 — 같은 주소공간이라 그냥 메모리 공유로 해결 |
| 서로 다른 프로세스 (독립된 주소공간) | System V 세마포어(`semget/semop/semctl`), named 세마포어(`sem_open`) | 맞음 — 커널이 관리하는 공유 리소스에 여러 프로세스가 키/이름으로 접근 |

프로세스 경계를 넘어서 "락 걸림/풀림" 상태를 주고받는 것 자체가 **프로세스 간 통신(정보 교환)의 한 형태**라서, System V는 세마포어를 메시지 큐 · 공유메모리와 나란히 IPC 3형제로 묶어놓았습니다.

## 3. 기본 API

| 함수 | 역할 |
| --- | --- |
| `semget(key, nsems, flags)` | 세마포어 집합 생성/오픈 |
| `semop(semid, ops, nops)` | P/V 연산(대기/신호) 수행 |
| `semctl(semid, semnum, cmd, ...)` | 초기값 설정, 조회, 삭제 등 제어 |

`msgget`과 마찬가지로 key 기반으로 자원을 식별한다는 패턴은 동일합니다. → [ftok과 IPC 키 생성]([OS]%20ftok과%20IPC%20키%20생성.md)

## 핵심

세마포어는 "동시성 제어 도구"이면서 동시에 "IPC"입니다 — 프로세스 경계를 넘어 동작할 때만 IPC로 분류되고, 한 프로세스 내부(스레드 간)에서는 그냥 동시성 도구일 뿐입니다.
