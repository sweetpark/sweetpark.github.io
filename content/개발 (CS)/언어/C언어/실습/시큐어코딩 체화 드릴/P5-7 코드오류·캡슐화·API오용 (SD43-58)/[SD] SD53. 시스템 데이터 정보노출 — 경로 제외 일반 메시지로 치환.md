## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 환경변수·내부 경로 → 그대로 → 예외/에러 메시지 화면 출력 |
| **공격 시나리오** | PATH·경로·DB 접속 정보 같은 내부 데이터가 노출되면 공격자가 후속 공격의 표적과 경로를 정밀하게 설계할 수 있다. |
| **치환 규칙** | 예외 상황에서도 환경변수·경로·스택 정보를 오류 메시지에 포함하지 않는다: 상세 정보는 접근 통제된 내부 로그로만. |
| **주의** | 에러 메시지는 "사용자용(일반화)"과 "운영자용(상세 로그)"을 물리적으로 분리하라. |
| **자세한 설명** | [Part 6. 캡슐화 — 2. 시스템 데이터 정보노출](개발%20%28CS%29/언어/C언어/시큐어코딩/[시큐어코딩]%20Part%206.%20캡슐화.md#2-시스템-데이터-정보노출-cwe-497) (Bad/Good 전체 코드, 보충) |

```diff
  char* path = getenv("PATH");
- fprintf(stderr, "cannot find exe on path %s\n", path);   /* 경로 정보 그대로 노출 */
+ fprintf(stderr, "cannot find exe on path \n");            /* 내부 경로 제외한 일반 메시지 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `PATH` 환경변수 값 | `getenv("PATH")` | 화면(stderr)에 그대로 찍히는 오류 메시지 |
| 실패한 할당의 포인터 값 | `malloc()` 실패 시점의 인자 | 오류 메시지에 `%p`로 그대로 찍히는 지점 |

**공격 입력표**

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 실행 파일 탐색 실패 | **`PATH` 값이 메시지에 그대로 노출** | `%s`로 경로 문자열을 그대로 끼워 넣는다 |
| 메모리 할당 실패 | **메모리 주소가 16진수로 노출**(`0x...`) | `%p`로 포인터 값을 그대로 찍는다 → 공격자가 ASLR을 우회하는 데 쓸 수 있는 메모리 배치 정보다 |
| 같은 상황(Good, 둘 다) | 경로·주소 정보 전혀 없이 일반 메시지만 | 값 자체를 메시지 포맷에서 뺀다 |

## 3. 주의해야 할 점

1. **경로만 신경 쓰고 메모리 주소·PID·호스트명 등은 "시스템 데이터"로 인식 못 함**
	- CWE-497은 "시스템 데이터" 전반을 다룬다.
	- 파일 경로 말고도 프로세스 내부 상태를 드러내는 값(주소, PID, 스레드 ID, 커널 버전 등)은 전부 후속 공격에 쓰일 수 있는 정찰 정보다
1. **"디버그 로그에만 남기면 되니까 그냥 다 찍자"는 태도로 사용자 메시지와 로그를 구분 안 함**
	- [SD40](개발%20%28CS%29/언어/C언어/실습/시큐어코딩%20체화%20드릴/P3-4%20시간·상태·에러처리%20%28SD37-42%29/[SD]%20SD40.%20오류%20메시지를%20통한%20정보%20노출%20—%20일반%20메시지%20응답으로%20치환.md)에서 다룬 채널 분리 원칙이 여기도 그대로 적용된다.
	- "어딘가에 남긴다"와 "사용자 화면에 안 보인다"는 별개의 요구사항이다
1. **`%p` 포맷 자체를 문제라고 생각**
	- 포맷 지정자가 문제가 아니라, **그 값이 흘러가는 목적지(사용자 화면)가 문제**다.
	- 같은 `%p` 출력이라도 접근 통제된 내부 디버그 로그에만 남는다면 이 항목의 위반이 아니다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 스택 트레이스/함수 이름 노출로 변형

예외 발생 시 `__func__`나 `__FILE__:__LINE__`을 사용자 메시지에 그대로 포함하는 함수를 만들어, 코드 구조 자체가 노출되는 사례까지 확장한다

### 변형 C — 프로세스 ID·호스트명 노출로 변형

`getpid()`나 `gethostname()` 결과를 오류 메시지에 넣는 함수로 바꿔, "시스템 데이터"의 범위가 경로·주소를 넘어선다는 걸 확인한다
