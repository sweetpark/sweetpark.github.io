## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | (해당 없음: 파라미터 선택 결함) |
| **공격 시나리오** | 512비트 RSA 키는 현재 컴퓨팅 성능으로 소인수분해가 가능해, 암호화를 적용했음에도 사실상 평문과 다름없다. |
| **치환 규칙** | RSA 512/1024비트 금지 → 2048비트 이상(3072 권장), 대칭키는 128비트 이상. |
| **주의** | 알고리즘이 안전해도 키가 짧으면 무의미하다. RSA 2048비트 이상, 대칭키 128비트 이상이 하한선이다. |
| **자세한 설명** | [Part 2-3. 암호화 계열 — 11. 충분하지 못한 키 길이 사용](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-3.%20암호화%20계열.md#11-충분하지-못한-키-길이-사용-cwe-310) (Bad/Good 전체 코드, 보충) |

```diff
- int validate_key_length_bad(int key_bits) { (void)key_bits; return 1; }
+ int validate_key_length_good(int key_bits) { return key_bits >= MIN_SYMMETRIC_KEY_BITS; }
```

---

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| `key_bits` | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 256 (정상) | 통과 | 충분한 길이 |
| 56(DES 수준) | **통과(취약)** | 검사 자체가 없다 |

---

## 3. 주의해야 할 점

1. **`key_bits > MIN` 으로 써서 정확히 128을 거부**
	- 경계값 처리 실수다.
	- "128비트 이상"이므로 `>=` 가 맞다
1. **이 검사를 알고리즘 선택(SD28) 로직과 분리하지 않고 하나로 뭉침**
	- 알고리즘 종류와 키 길이는 서로 다른 축의 검증이다.
	- 함수를 분리해야 SD30 변형 C(알고리즘별 기준표)로 자연스럽게 확장된다

---

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — RSA 키 길이 검증

최소 기준을 2048로, 3072 이상이면 "권장" 등급까지 반환하는 3단계(거부/최소/권장) 함수로 확장

### 변형 C — 알고리즘별 최소 기준표

SD28의 화이트리스트와 결합해, 알고리즘 이름에 따라 다른 최소 키 길이를 요구하는 테이블 기반 검증으로 발전
