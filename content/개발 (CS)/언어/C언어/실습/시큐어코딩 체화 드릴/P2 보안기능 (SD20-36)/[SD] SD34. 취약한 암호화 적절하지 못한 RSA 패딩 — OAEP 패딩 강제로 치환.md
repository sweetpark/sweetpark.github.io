## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 해당 없음 : 패딩 파라미터 선택 결함 |
| **공격 시나리오** | 패딩 없는(교과서적) RSA는 결정적이라 같은 평문이 같은 암호문을 만들고, 작은 지수 공격·선택 암호문 공격으로 평문이 복원된다. |
| **치환 규칙** | `RSA_NO_PADDING` 금지 → `RSA_PKCS1_OAEP_PADDING`(서명/복호화 계열도 동일). |
| **주의** | RSA는 "알고리즘"이 아니라 "알고리즘 + 패딩"이 한 세트다. NO_PADDING은 사실상 암호화하지 않은 것과 같다. |
| **자세한 설명** | [Part 2-3. 암호화 계열 — 15. 취약한 암호화: 적절하지 못한 RSA 패딩](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-3.%20암호화%20계열.md#15-취약한-암호화-적절하지-못한-rsa-패딩-cwe-325) (Bad/Good 전체 코드, 보충) |

```diff
- int is_safe_padding_bad(padding_t p) { (void)p; return 1; }        /* PAD_NONE도 허용 */
+ int is_safe_padding_good(padding_t p) { return p != PAD_NONE; }     /* 패딩 없는 RSA만 거부 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| 패딩 모드 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `PAD_OAEP` (정상) | 허용 | 안전한 패딩 |
| `PAD_NONE` | **허용됨(취약)** | 교과서적 RSA는 결정적이라 같은 평문이 같은 암호문을 만들고, 선택 암호문 공격에 취약하다 |

---

## 3. 주의해야 할 점

1. **`p == PAD_OAEP` 로만 허용(화이트리스트가 너무 좁음)**
	- PKCS1도 안전한 패딩이다.
	- "안전하지 않은 것만 콕 집어 거부"가 이 항목의 요구사항이다
		- 안전한 옵션이 늘어나도 코드를 안 고쳐도 되게 설계한다
1. **enum 대신 문자열로 패딩을 표현해서 오타에 취약**
	- `padding_t` 처럼 enum을 쓰면 컴파일러가 오타를 잡아준다.
	- 이런 유한한 선택지는 문자열보다 enum이 안전하다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 서명용 패딩 게이트

암호화가 아니라 서명(PSS vs PKCS1v1.5)용 패딩 검증으로 변형

### 변형 C — 패딩 모드별 최소 RSA 키 길이까지 결합

SD30(키 길이)과 결합해, "OAEP + 2048비트 이상"처럼 두 조건을 함께 검증하는 함수로 확장
