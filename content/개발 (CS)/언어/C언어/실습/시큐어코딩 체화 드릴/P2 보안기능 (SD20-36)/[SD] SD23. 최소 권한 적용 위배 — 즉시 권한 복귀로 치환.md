## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | `chroot`/상위 권한 작업 완료 시점 → 즉시 반납 없이 → 이후 코드 전체가 상승된 권한으로 실행 |
| **공격 시나리오** | 상승된 권한이 유지된 채 이후 코드가 실행되므로, 그 구간의 어떤 결함도 곧바로 시스템 전체 권한 탈취로 이어진다. |
| **치환 규칙** | 권한 상승 직후 필요한 작업만 수행하고, 원래 UID를 백업했다가 작업 종료(정상·예외 경로 모두) 즉시 복귀. |
| **주의** | 권한 상승은 "빌린 것"이다. 쓰자마자 즉시 반납하고, 반납 코드는 예외 경로에도 반드시 넣어라. |
| **자세한 설명** | [Part 2-1. 인가·권한 계열 — 4. 최소 권한 적용 위배](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-1.%20인가·권한%20계열.md#4-최소-권한-적용-위배-cwe-272) (Bad/Good 전체 코드, 보충) |

```diff
- g_current_priv = ROOT_UID;      /* 상승만 하고 되돌리지 않는다 */
+ int backup = g_current_priv;
+ g_current_priv = ROOT_UID;
+ /* ... 필요한 작업만 ... */
+ g_current_priv = backup;        /* 즉시 원래 권한으로 복귀 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `elevate_bad()` 호출 후 | **권한이 계속 root(0)로 남아있다** | 반납 코드가 아예 없다 |
| `do_privileged_work_good()` 호출 후 | 원래 권한(1000)으로 복귀 | 작업 직후 즉시 반납 |

---

## 3. 주의해야 할 점

1. **복귀 값을 상수(`1000`)로 하드코드**
	- 변형 C(중첩 상승)처럼 "상승 전 값"이 항상 기본값이 아닐 수 있다.
	- 반드시 **그 시점의 실제 값을 백업**해서 되돌려야 한다
1. **작업 중간에 `return` 이 있는데 그 경로엔 반납 코드가 없음**
	- 변형 B에서 드러나는 함정이다.
	- 모든 종료 경로(정상+예외)에서 반납이 실행되어야 한다 — 자원 정리와 똑같은 원칙([SD44. 부적절한 자원 해제](개발%20%28CS%29/언어/C언어/실습/시큐어코딩%20체화%20드릴/P5-7%20코드오류·캡슐화·API오용%20%28SD43-58%29/[SD]%20SD44.%20부적절한%20자원%20해제%20—%20단일%20해제%20지점으로%20치환.md)와 같은 계열의 문제)
1. **백업 변수를 지역이 아니라 전역으로 둠**
	- 여러 스레드/재귀 호출이 얽히면 백업값 자체가 덮인다.
	- 백업은 반드시 **그 함수 호출의 지역 변수**로 둔다

---

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 예외 경로에서도 반납

작업 도중 "실패"가 발생하는 상황을 추가하고, 실패해도 반드시 원래 권한으로 복귀하는지 확인(early return이 있어도 반납 로직을 타야 한다)

### 변형 C — 중첩 상승

이미 상승된 상태에서 한 번 더 상승을 요청하는 경우, 반납이 "최초 권한"으로 정확히 돌아가는지(중간값으로 잘못 복귀하지 않는지) 확인
