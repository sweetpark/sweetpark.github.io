## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 정상 로그인 여부 → 권한 등급 검증 없이 → `seteuid(0)` root 권한 부여 |
| **공격 시나리오** | 정상 유저인지만 확인하고 무조건 root 권한을 부여하면, 접근 불가능해야 할 파일에 접근하고 일반 사용자가 관리자와 동일한 권한으로 동작하게 된다. |
| **치환 규칙** | 인증 성공 여부와 권한 등급을 분리: 그룹별 최소 유효 UID를 미리 테이블로 정의하고 그 결과로만 `seteuid`. |
| **주의** | "인증(누구인가)"과 "인가(무엇을 할 수 있는가)"는 별개다. 로그인 성공이 root 권한의 근거가 될 수 없다. |
| **자세한 설명** | [Part 2-1. 인가·권한 계열 — 3. 잘못된 권한 부여](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-1.%20인가·권한%20계열.md#3-잘못된-권한-부여-cwe-266) (Bad/Good 전체 코드, 보충) |

```diff
- if (isCorrectUser) return 0;              /* 정상 유저이기만 하면 무조건 root(0) */
+ for (그룹별 테이블에서 group과 일치하는 항목을 찾는다)
+     return 테이블에_정의된_UID;
+ return -1;                                 /* 모르는 그룹은 권한 없음 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 정상 로그인(그룹 무관) | **UID 0(root) 부여** | "정상 유저인지"만 확인하고 어떤 그룹인지는 안 본다 |
| 게스트 그룹 정상 로그인(Good 대상) | 게스트 전용 UID | 그룹에 맞는 권한만 부여 |

---

## 3. 주의해야 할 점

1. **테이블 순회 후 못 찾았을 때 기본값을 `0`(root)으로 둠**
	- "모르면 최소 권한"이 원칙이다.
	- 실수로 기본값을 관대하게 잡으면 새로 추가되는 그룹이 전부 관리자가 되는 사고로 이어진다
1. **`isCorrectUser` 하나로 인증과 인가를 동시에 처리하려 함**
	- Bad의 근본 결함이다.
	- 인증 확인과 권한 조회는 **별개의 함수/단계**로 분리한다
1. **그룹 enum에 없는 값(정수 캐스팅 등)이 들어와도 대응 못 함**
	- `group_t` 는 enum이라 잘못된 정수가 들어오면 정의되지 않은 case가 될 수 있다
		- 테이블에 없으면 무조건 거부하는 구조(`for` 루프 후 `return -1`)로 이런 상황도 커버된다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 부서별 접근 등급

UID 대신 "결재 등급"(1~5)을 그룹별 테이블에서 조회하는 형태로 변형

### 변형 C — 테이블에 없는 신규 그룹 추가 시 기본값 정책

새 그룹이 테이블에 없을 때 "기본값은 항상 최소 권한"이어야 한다는 원칙을 코드로 강제(테이블 순회 결과가 없으면 반드시 최소 권한 상수를 반환하도록 구조화)
