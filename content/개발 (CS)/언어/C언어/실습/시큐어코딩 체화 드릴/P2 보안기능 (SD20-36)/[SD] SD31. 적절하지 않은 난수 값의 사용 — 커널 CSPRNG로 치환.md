## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | `time(NULL)` seed → 예측 가능한 채로 → 세션 토큰·IV·솔트 |
| **공격 시나리오** | `rand()` 계열은 seed만 알면 난수열 전체가 재현되고, 출력 몇 개만 관측해도 내부 상태가 복원된다. 세션 ID·토큰·솔트가 예측되면 세션 탈취·인증 우회로 이어진다. |
| **치환 규칙** | `rand()`/`srand()` 전면 금지 → `getrandom(2)`/`/dev/urandom`/`RAND_bytes()`/`BCryptGenRandom()`, 실패 시 약한 값 대체 금지하고 중단. |
| **주의** | seed를 바꾸는 것으로는 해결되지 않는다. rand() 계열은 보안용이 아니며, 커널 CSPRNG나 검증필 DRBG로 통째로 교체해야 한다. |
| **자세한 설명** | [Part 2-3. 암호화 계열 — 12. 적절하지 않은 난수 값의 사용](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-3.%20암호화%20계열.md#12-적절하지-않은-난수-값의-사용-cwe-330) (Bad/Good 전체 코드, 보충) |

```diff
- srand(seed); for (...) out[i] = "0123456789abcdef"[rand() % 16];   /* seed만 알면 재현됨 */
+ if (getrandom(raw, sizeof(raw), 0) != (ssize_t)sizeof(raw)) return -1;  /* 실패는 반드시 중단 */
+ for (...) sprintf(out + i*2, "%02x", raw[i]);
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 같은 seed로 두 번 생성 | **완전히 같은 토큰** | `rand()` 는 seed가 같으면 항상 같은 시퀀스를 낸다(예측 가능) |
| 매번 새로 생성(Good) | 매번 다른 토큰 | 커널 CSPRNG는 내부 엔트로피 풀에서 뽑는다 |

---

## 3. 주의해야 할 점

1. **`srand(time(NULL))` 로 "개선"했다고 착각**
	- seed가 초 단위 시각이면 하루치 후보가 86400개뿐이라 전수 시도로 재현된다.
	- 여전히 `rand()` 계열 자체가 문제다
1. **`getrandom` 실패 시 `rand()` 로 폴백**
	- "실패하면 약한 값이라도 쓰자"는 대응이 가장 위험하다.
	- 실패는 반드시 호출자에게 알리고 중단한다
1. **반환된 바이트를 `%d` 로 찍어 10진수 토큰을 만듦**
	- 바이트당 표현 범위가 줄어 엔트로피가 낭비된다.
	- 16진수(`%02x`)로 그대로 펼치는 것이 표준적이다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 일회용 비밀번호(OTP) 생성

- 16진수 대신 6자리 숫자 OTP로 변형
	- `getrandom` 결과를 숫자 범위로 매핑할 때 모듈로 편향(modulo bias)이 생기지 않게 하는 법까지 고려

### 변형 C — 초기화 벡터(IV) 생성

AES-CBC용 16바이트 IV를 만드는 함수로 변형.
IV는 비밀은 아니지만 예측 불가능해야 하는 이유를 설명해본다
