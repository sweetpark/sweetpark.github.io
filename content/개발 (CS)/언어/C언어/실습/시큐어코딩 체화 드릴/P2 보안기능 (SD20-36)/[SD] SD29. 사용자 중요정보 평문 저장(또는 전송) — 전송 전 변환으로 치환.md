## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 소켓 수신 데이터(패스워드) → 암호화 없이 → 저장/전송 |
| **공격 시나리오** | 같은 네트워크 구간의 공격자가 패킷 스니핑만으로 ID/패스워드, 주민등록번호, 카드번호를 그대로 획득한다. |
| **치환 규칙** | 개인정보·금융정보·패스워드는 저장·전송 양쪽 모두 암호화, 평문이 메모리·로그·설정파일에 남지 않게. |
| **주의** | "내부망이라 괜찮다"는 없다. 저장할 때뿐 아니라 통신채널을 지날 때도 암호화해야 한다. |
| **자세한 설명** | [Part 2-3. 암호화 계열 — 10. 사용자 중요정보 평문 저장(또는 전송)](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-3.%20암호화%20계열.md#10-사용자-중요정보-평문-저장또는-전송-cwe-311) (Bad/Good 전체 코드, 보충) |

```diff
- strncpy(out, pw, out_size - 1); out[out_size-1] = '\0';   /* 그대로 전송/저장 */
+ xor_mask(pw, out, out_size);                               /* 원본과 다른 값으로 변환 후 전송/저장 */
```

## 3. 주의해야 할 점

1. **"복원 불가능한 변환"(단방향 해시)을 인증 패킷에 적용**
	- 로그인 패킷은 서버가 원본과 대조해야 하므로 **양방향(암호화)** 이어야 한다.
	- 단방향(해시)은 SD32~33(저장용)과 다른 용도다
		- 용도별로 방식이 다르다는 걸 구분한다
1. **`test_good_hides_plaintext` 만 확인하고 복원 테스트를 생략**
	- "숨기기만 하고 다시 못 꺼내면" 암호화가 아니라 그냥 데이터 파괴다.
	- 두 시험이 한 쌍이어야 의미가 있다
1. **이 드릴의 `xor_mask` 를 실전 코드에 그대로 가져다 씀**
	- 이 드릴은 원리 시연용이다.
	- 실전에서는 반드시 SD28의 화이트리스트를 통과한 검증된 알고리즘을 쓴다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 로그 기록 시 마스킹

- 디버그 로그에 패스워드 필드를 남길 때도 같은 원리 적용
	- 단, 로그는 "복원 불필요"이므로 되돌릴 수 없는 마스킹(`****`)으로 바꿔도 됨을 비교해본다

### 변형 C — 주민등록번호 등 개인정보로 확장

여러 필드(주민번호, 카드번호)를 한 번에 마스킹하는 구조체 단위 변환 함수로 확장
