## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 개발 편의로 남긴 주석 → 제거 없이 → 배포 소스/저장소 |
| **공격 시나리오** | 소스코드나 배포물에 한 번만 접근하면 인증 절차 없이 관리자 패스워드와 시스템 내부 구조를 획득할 수 있다. |
| **치환 규칙** | 배포 전 `grep`/정적분석으로 `password`/`key`/`id` 키워드 주석 전수 검사 후 제거. |
| **주의** | 주석은 컴파일되지 않을 뿐 사라지지 않는다. 배포 전 "주석 청소"를 릴리스 체크리스트에 넣어라. |
| **자세한 설명** | [Part 2-2. 자격증명 관리 계열 — 8. 주석문안에 포함된 패스워드 등 시스템 주요정보](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%202.%20보안기능/[시큐어코딩]%202-2.%20자격증명%20관리%20계열.md#8-주석문안에-포함된-패스워드-등-시스템-주요정보-cwe-615) (Bad/Good 전체 코드, 보충) |

+ int release_ok_good(const char *source_code) {
+     return find_secret_in_comments(source_code) == 0;   /* 주석을 스캔해서 위험 키워드 검사 */
+ }

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| 소스 코드 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 주석에 `default password is "abracadabra"` 포함 | **배포 승인(1)** | 검사 자체를 안 한다 |
| 정상 주석만 있음 | 배포 승인(1) | 위험 요소 없음 |

---

## 3. 주의해야 할 점

1. **`strstr` (대소문자 구분)로 검사**
	- `Password`, `PASSWORD` 처럼 대문자가 섞이면 놓친다.
	- 이 항목은 대소문자 무관이 요구사항이다
1. **주석 구간을 못 찾고 소스 전체에서 키워드를 검색**
	- 함수 이름에 `password` 가 들어간 정상 코드(`verifyAuth`, `checkPassword` 등)까지 전부 걸려서 과잉 차단된다.
	- **주석 구간만** 잘라서 검사해야 한다
1. **`/* ` 뒤에 `*/` 가 없는 미종료 주석 처리 안 함**
	- 이 드릴의 파서는 `end` 가 `NULL` 이면 문자열 끝까지를 주석으로 간주해야 한다(모범답안의 `len = end ? ... : strlen(p)` 부분)

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 한 줄 주석(`//`)도 검사 대상에 추가

C99/C++ 스타일 한 줄 주석까지 스캔하도록 `find_secret_in_comments` 를 확장

### 변형 C — 키워드 목록을 파일에서 로드

하드코딩된 키워드 배열 대신, 팀이 관리하는 금지어 목록을 외부에서 주입받는 구조로 바꾼다(이 드릴 시리즈 전체를 관통하는 "화이트/블랙리스트는 외부화"의 마지막 반복)
