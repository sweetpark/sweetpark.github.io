## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | `read()`/`readlink()` 로 받은 버퍼 → 널 종료 보장 없이 → 문자열 함수(`strcpy`/`strlen`) |
| **공격 시나리오** | `read()` 로 읽은 버퍼는 널 종료가 보장되지 않으므로 `strcpy()` 가 널을 만날 때까지 계속 복사해 경계를 넘고, 인접 메모리가 유출되거나 스택이 덮인다. |
| **치환 규칙** | `read`/`readlink` 결과에 `strcpy`/`strcat`/`strlen` 직접 적용 금지 → `strlcpy`/`strlcat` 또는 길이 인자 명시. |
| **주의** | 널 종료는 자동이 아니다. read 계열로 받은 버퍼는 "문자열"이 아니라 "바이트 배열"로 취급하라. |
| **자세한 설명** | [Part 1-3. 메모리 경계 계열 — 16. 널 종료 문제](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-3.%20메모리%20경계%20계열.md#16-널-종료-문제-cwe-170) (Bad/Good 전체 코드, 보충) |

```diff
- strcpy(out, raw);                                    /* raw가 널 종료 안 되면 계속 읽음 */
+ size_t n = (raw_len < out_size - 1) ? raw_len : out_size - 1;
+ memcpy(out, raw, n);
+ out[n] = '\0';                                        /* 널 종료를 직접 보장 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| `raw` 상태 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 8바이트를 `\0` 로 채우고 `"hi"` 를 앞에 씀 (정상) | 정상 동작 | 우연히 널 종료가 되어 있는 경우 |
| **정확히 8바이트를 `'A'` 로만 채움(널 없음)** | **힙 버퍼 오버리드로 크래시** | `strcpy` 가 8바이트를 넘어 널을 찾아 계속 읽는다 |

---

## 3. 주의해야 할 점

1. **테스트에서 `raw` 를 스택 배열(`char raw[8]`)로만 두고 `malloc(8)` 을 안 씀**
	- 스택 배열은 컴파일러가 여유 공간이나 다른 지역변수를 바로 뒤에 둘 수 있어 ASan이 항상 정확히 잡아주지 못할 때가 있다.
	- **힙에 정확한 크기로 할당**해야 재현이 안정적이다
1. **Good에서 실패(`-1`) 시 `out` 을 아예 안 건드림**
	- 호출자가 실패를 무시하고 `out` 을 문자열로 쓰면 초기화 안 된 메모리를 읽는 또 다른 버그가 생긴다.
	- 실패해도 **최소한 널 종료된 빈 상태**는 보장한다
1. **`raw_len` 을 아예 안 받고 `strlen(raw)` 로 길이를 구하려 함**
	- 이 항목의 전제 자체가 "raw는 널 종료가 안 되어 있다"는 것이다.
	- `strlen` 을 쓰는 순간 이미 이 항목이 경고하는 함정에 빠진 것이다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 두 조각을 이어붙이기(`strncat` 흉내)

`firstName` + `" "` + `lastName` 을 붙이는 로직에서, 앞부분이 널 종료가 안 됐을 때 `strncat` 이 어떻게 추가로 폭주하는지 재현

### 변형 C — C++ `std::string`/C의 길이 기반 구조체로 전환

널 종료에 의존하지 않는 자료구조(길이를 항상 들고 다니는 구조체)로 설계를 바꾸면 이 계열의 문제가 원천적으로 사라진다는 것을 체감
