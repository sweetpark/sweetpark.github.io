## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 외부에서 정해진 `size` → 오버플로우 검사 없이 → `malloc()` 할당 크기 |
| **공격 시나리오** | `size` 가 오버플로우로 음수가 되어도 `malloc()` 의 `size_t` 파라미터로 넘어가면 거대한 양수로 해석되거나 극히 작은 버퍼가 할당되고, 이후 복사에서 힙 오버플로우가 발생한다. |
| **치환 규칙** | 할당 크기 파라미터는 `unsigned`, 곱셈·덧셈 결과는 쓰기 전에 오버플로우 여부 선(先)검사. 곱셈은 `x > MAX / y` 형태로 나눗셈 이용해 사전 판별. |
| **주의** | malloc(n * size)를 보면 곱셈부터 의심하라. 검사는 계산 "후"가 아니라 "전"에 해야 한다. |
| **자세한 설명** | [Part 1-4. 정수·타입변환 계열 — 17. 정수 오버플로우](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-4.%20정수·타입변환%20계열.md#17-정수-오버플로우-cwe-190) (Bad/Good 전체 코드, 보충) |

```diff
- int total = count + RESERVE;
- return malloc((size_t)total * sizeof(int));            /* 오버플로우된 값을 그대로 할당 크기로 */
+ if (count < 0 || count > INT_MAX - RESERVE) return NULL;   /* 덧셈 전에 검사 */
+ int total = count + RESERVE;
+ if ((size_t)total > SIZE_MAX / sizeof(int)) return NULL;   /* 곱셈 전에 검사 */
+ return malloc((size_t)total * sizeof(int));
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| `count` | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 10 (정상) | 정상 할당 | 오버플로우 없음 |
| `INT_MAX - 4` | **UBSan이 오버플로우를 리포트 → 결과값이 음수 → size_t 캐스팅으로 거대해짐 → ASan이 할당 요청을 거부하며 abort** | `count + RESERVE` 가 `INT_MAX` 를 넘는다 |

---

## 3. 주의해야 할 점

1. **`count + RESERVE > INT_MAX` 로 검사(오버플로우가 이미 일어난 후 비교)**
	- 이 비교 자체가 이미 오버플로우된 값을 사용하는 UB다.
	- `count > INT_MAX - RESERVE` 처럼 **뺄셈으로 미리 뒤집어서** 오버플로우가 나기 전에 검사해야 한다
1. **곱셈 오버플로우 검사를 빼먹고 덧셈만 막음**
	- `total` 이 안전해도 `total * sizeof(int)` 에서 또 오버플로우(혹은 극단적인 크기)가 날 수 있다.
	- 나눗셈으로 사전 검사(`total > SIZE_MAX / sizeof(int)`)
1. **Bad를 "정수 오버플로우 자체가 크래시"라고 오해**
	- 정수 오버플로우는 UBSan이 리포트만 하고 넘어간다.
	- **그 값이 메모리 크기·인덱스로 쓰일 때** 비로소 위험해진다는 연쇄를 이해해야 한다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 곱셈 오버플로우로 변형

`malloc(n * elem_size)` 형태에서 `n`, `elem_size` 둘 다 외부에서 온다고 가정하고, `n > SIZE_MAX / elem_size` 형태의 나눗셈 사전 검사를 직접 짜본다

### 변형 C — 뺄셈 오버플로우

`remaining = total - used` 형태에서 `used > total` 이면 결과가 큰 양수(부호 있는 경우 음수)가 되는 패턴을 다뤄본다
