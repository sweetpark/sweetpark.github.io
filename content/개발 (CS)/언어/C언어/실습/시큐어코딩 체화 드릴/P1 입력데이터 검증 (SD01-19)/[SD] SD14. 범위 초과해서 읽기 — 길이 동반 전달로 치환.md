## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 배열 인덱스 → 상한 검사 없이 → 배열 참조 |
| **공격 시나리오** | 배열 뒤에 있던 세션 토큰·암호키가 반환값에 실려 그대로 흘러나가고, 값에 포인터가 섞이면 실제 주소가 드러나 ASLR이 무력화된다. 이 주소는 11·12번 버퍼 오버플로우를 정확히 겨냥하는 열쇠가 된다. |
| **치환 규칙** | 배열을 넘길 때 크기 인자를 항상 동반, 종료 마커만 믿지 말고 길이 기반 종료 조건을 함께 둔다. |
| **주의** | 배열 포인터를 넘길 때는 반드시 길이도 함께 넘긴다. "포인터 단독 전달"이 out-of-bounds read의 근본 원인이다. |
| **자세한 설명** | [Part 1-3. 메모리 경계 계열 — 14. 범위 초과해서 읽기](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-3.%20메모리%20경계%20계열.md#14-범위-초과해서-읽기-cwe-125) (Bad/Good 전체 코드, 보충) |

```diff
- return arr[idx];                                    /* 상한 검사 없음 */
+ if (idx < 0 || (size_t)idx >= size) return -1;       /* 배열과 "길이"를 항상 같이 받는다 */
+ *out = arr[idx];
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| `idx` (배열 크기 3) | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 2 (정상) | 정상 값 반환 | 유효 인덱스(0~2) |
| 5 (범위 초과) | **힙 버퍼 오버리드로 크래시** | 배열 뒤 힙 메모리를 읽는다 → 다른 데이터·포인터 값이 새어나갈 수 있다 |

---

## 3. 주의해야 할 점

1. **"읽기"라서 검사를 생략해도 된다고 생각함**
	- 읽기 오버플로우는 크래시가 없을 때도 있다(매핑된 페이지라면).
	- 대신 세션 토큰·키 같은 민감정보가 반환값에 실려 유출된다
		- 쓰기보다 더 늦게 발견된다
1. **함수가 값과 에러를 같은 채널로 반환(`int read_at_index(...)` 하나로 값과 -1 에러를 겸용)**
	- 정상 값이 우연히 `-1` 일 때 구분이 안 된다.
	- 이 드릴처럼 리턴값은 상태 전용, 실제 값은 출력 인자(`*out`)로 분리하는 습관을 들인다
1. **`size` 를 `int` 로 받아서 음수 크기가 들어올 가능성을 열어둠**
	- 배열 크기는 개념적으로 음수일 수 없다.
	- `size_t` 로 받아 타입 자체가 음수를 표현 못 하게 한다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 문자열 배열(`char*[]`) 조회

범위를 넘으면 포인터 값 자체가 유출될 수 있다는 점(ASLR 무력화로 이어지는 이유)을 노트에 적어본다

### 변형 C — 2차원 배열(행렬) 조회

`data[row][col]` 형태에서 `row`, `col` **양쪽 모두** 범위를 검사해야 하는 이유를 확인
