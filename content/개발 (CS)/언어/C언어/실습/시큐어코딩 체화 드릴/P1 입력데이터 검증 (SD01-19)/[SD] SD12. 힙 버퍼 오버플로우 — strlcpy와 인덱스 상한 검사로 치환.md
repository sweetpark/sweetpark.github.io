## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 외부 토큰 개수 → 경계 검사 없이 → `malloc()` 버퍼 인덱스 |
| **공격 시나리오** | 토큰 개수가 할당 크기를 넘으면 힙 관리 구조체가 덮여, `free()` 시점에 임의 주소 쓰기로 이어져 코드 실행이나 프로세스 다운을 유발한다. |
| **치환 규칙** | 힙 버퍼 복사는 `strlcpy`(크기 인자 필수), 반복 인덱스는 매 루프 상한 검사. |
| **주의** | 힙이든 스택이든 "할당 크기"와 "쓰기 인덱스"는 한 쌍으로 관리하고, 복사 함수는 크기 인자를 받는 것으로 통일한다. |
| **자세한 설명** | [Part 1-3. 메모리 경계 계열 — 12. 힙에 할당된 버퍼 오버플로우](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-3.%20메모리%20경계%20계열.md#12-힙에-할당된-버퍼-오버플로우-cwe-122) (Bad/Good 전체 코드, 보충) |

```diff
- char *dest = (char *)malloc(BUFSIZE);
- strcpy(dest, input);                    /* 길이 검사 없음 */
+ if (strlen(input) >= BUFSIZE) return -1;
+ *out = (char *)malloc(BUFSIZE);
+ strncpy(*out, input, BUFSIZE - 1);
+ (*out)[BUFSIZE - 1] = '\0';
```

## 3. 주의해야 할 점

1. **Good 성공 경로에서 `*out` 을 `free` 하지 않고 테스트를 끝냄**
	- ASan의 LeakSanitizer가 누수로 잡는다.
	- "오버플로우만 막으면 끝"이 아니라 소유권까지 관리해야 한다
1. **`malloc(BUFSIZE)` 실패(`NULL`) 검사를 빼먹음**
	- 드물지만 힙 고갈 시 `NULL` 에 `strncpy` 하면 또 다른 크래시(널 역참조)가 된다
1. **스택 버퍼(SD11)와 힙 버퍼(SD12)의 방어 코드를 그대로 복붙**
	- 원리는 같지만 **소유권(할당·해제) 책임**이 추가된다는 차이를 놓치기 쉽다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 가변 크기 할당

버퍼 크기를 인자로 받는 `malloc(size)` 로 바꾸고, `size` 자체가 외부에서 온다면 [SD17. 정수 오버플로우](개발%20%28CS%29/언어/C언어/실습/시큐어코딩%20체화%20드릴/P1%20입력데이터%20검증%20%28SD01-19%29/[SD]%20SD17.%20정수%20오버플로우%20—%20연산%20전%20오버플로우%20검사로%20치환.md)와 어떻게 연결되는지 생각해본다

### 변형 C — 토큰 배열을 힙에 저장

고정 배열(`int dataBuffer[N]`) 대신 `malloc` 으로 할당한 배열에 인덱스 상한 검사 없이 쓰는 경우까지 확장
