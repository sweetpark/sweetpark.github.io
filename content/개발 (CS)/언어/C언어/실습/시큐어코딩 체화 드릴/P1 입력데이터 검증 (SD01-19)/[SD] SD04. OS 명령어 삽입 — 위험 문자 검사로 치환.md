## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 표준입력 인자 → 검증 없이 → `system()` 명령 문자열 |
| **공격 시나리오** | `cat` 프로그램에 `"Story.txt; ls"` 를 넘기면 파일 출력에 이어 `ls` 가 실행된다. |
| **치환 규칙** | `system()` 금지 → 후보 명령어 리스트에서만 선택, 부득이하면 `; \ " ' .` 검사 + 길이 상한. 근본 해결은 `execve` 계열로 인자를 배열 분리 전달. |
| **주의** | system()에 사용자 문자열이 닿는 순간 셸 권한을 넘겨준 것이다. 허용 목록에 있는 값만 실행하라. |
| **자세한 설명** | [Part 1-1. 삽입 계열 — 4. 운영체제 명령어 삽입](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-1.%20삽입%28Injection%29%20계열.md#4-운영체제-명령어-삽입-cwe-78) (Bad/Good 전체 코드, 보충) |

```diff
- snprintf(cmd, sizeof(cmd), "cat %s", userArg);           /* 검증 없이 조립 */
+ if (strpbrk(userArg, ";|&`$\\\"'") != NULL) return -1;   /* 위험 문자 있으면 거부 */
+ snprintf(cmd, sizeof(cmd), "cat %s", userArg);
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `userArg` | 외부(표준입력) | `system()` 에 전달될 명령 문자열 |

**공격 입력표**

| 입력 | Bad 결과(명령 개수) | 이유 |
| :--- | :--- | :--- |
| `Story.txt` (정상) | 1 | 정상 동작 |
| `Story.txt; ls` | **2** | 세미콜론 뒤 `ls` 가 별도 명령으로 실행된다 |
| `Story.txt \ | rm -rf /` | (파이프, mock에서는 명령 1개로 세지만 실제 셸에서는 위험) | Good에서 파이프도 함께 차단 |

## 3. 주의해야 할 점

1. **PDF 원문 그대로 `.` 을 위험 문자에 넣음**
	- 정상 파일 확장자까지 차단(과잉 차단)
		- 요구사항과 실제 위협을 구분하지 못한 것
1. **세미콜론만 막고 파이프(`\**
	- `)·백틱을 빠뜨림
	- 셸 메타문자는 세미콜론 하나가 아니다.
	- `` `cmd` ``, `$(cmd)` 도 명령 실행이다
1. **위험 문자 검사를 `system()` 호출 **직전이 아니라** 다른 곳에서 함**
	- 검증과 사용 사이에 값이 바뀔 여지가 있으면 안 된다
		- 조립 직전에 검사

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 압축 명령 조립

`gzip <로그파일명>` 형태.
위험 문자에 `>`(리다이렉트)도 추가해야 하는 이유를 생각해본다

### 변형 C — 허용 명령 화이트리스트로 전환

- 위험 문자 블랙리스트 대신, 미리 정의한 명령 후보 목록(`{"cat","gzip","ls"}`)에서만 선택하도록 바꾼다
	- 가이드 원문이 제시하는 더 근본적인 해법
