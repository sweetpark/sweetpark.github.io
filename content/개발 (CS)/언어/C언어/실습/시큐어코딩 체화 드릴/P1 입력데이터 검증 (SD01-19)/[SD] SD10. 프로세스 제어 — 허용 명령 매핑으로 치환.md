## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 환경변수(`SHAREDFILE`)·요청 파라미터 → 검증 없이 → 라이브러리 경로·OS 명령어 |
| **공격 시나리오** | `SHAREDFILE` 환경변수를 악성 `.so` 로 바꾸면 해당 프로세스 권한으로 임의 코드가 실행된다. |
| **치환 규칙** | 라이브러리 경로는 상대경로·환경변수 대신 신뢰 디렉터리 절대경로. 실행 명령은 화이트리스트 맵 결과값만 사용. |
| **주의** | 실행 대상(라이브러리 경로, 명령어)은 코드에 고정하거나 화이트리스트 맵을 거치게 하라. |
| **자세한 설명** | [Part 1-2. 외부제어·우회 계열 — 10. 프로세스 제어](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-2.%20외부제어·우회%20계열.md#10-프로세스-제어-cwe-114) (Bad/Good 전체 코드, 보충) |

```diff
- snprintf(out, out_size, "%s %s", op, documentName);              /* op 자체가 실행 프로그램명이 됨 */
+ for (매핑 테이블에서 op와 일치하는 항목을 찾는다) {
+     snprintf(out, out_size, "%s %s", 매핑된_고정_명령어, documentName);
+ }
+ /* 매핑에 없으면 거부 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `op` | 외부(요청 파라미터) | `system()` 에 전달될 명령어의 **프로그램 이름 부분** |

**공격 입력표**

| 입력(`op`) | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `"DocToHtml"` (정상) | `"DocToHtml report.doc"` | 정상 동작(단, `op` 값이 그대로 실행 프로그램명이 되므로 근본적으로 취약한 설계다) |
| `"rm -rf /tmp/x; echo pwned"` | **`"rm -rf /tmp/x; echo pwned report.doc"`** | `op` 자체가 임의의 명령으로 대체될 수 있다 |

---

## 3. 주의해야 할 점

1. **`op` 값을 위험 문자 검사(`strpbrk`)로만 거르고 그대로 조립**
	- SD04의 방식을 그대로 재사용한 것
		- 이 항목은 "명령 자체"가 오염되므로 문자 단위 필터로는 `op="malicious_binary"`처럼 셸 메타문자 없이도 임의 프로그램을 실행시키는 공격을 못 막는다
1. **매핑 테이블에 없는 `op` 에 대해 기본 명령을 실행**
	- "모르면 거부"가 원칙이다.
	- 모르는 값에 기본 동작을 주면 그 자체가 새로운 화이트리스트 우회 경로가 된다
1. **매핑을 `strcmp` 대신 `strstr`(부분 일치)로 검사**
	- `"DocToHtml; rm -rf /"` 가 `"DocToHtml"` 을 부분 문자열로 포함한다는 이유로 통과해버릴 수 있다
		- 반드시 완전 일치

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 이미지 리사이즈 명령 조립

`op` 값이 `{"thumbnail","preview"}` 로 바뀌고, 매핑된 명령에 추가 옵션(`-resize 100x100`)까지 고정으로 붙는 경우

### 변형 C — 매핑 테이블을 설정 파일에서 로드

허용 명령 목록을 하드코딩 대신 신뢰할 수 있는 설정 파일에서 읽어오되, "그래도 외부 요청은 여전히 이 테이블의 key(op)만 지정할 뿐 value(실제 명령어)는 알 수도 바꿀 수도 없다"는 원칙이 유지되는지 확인
