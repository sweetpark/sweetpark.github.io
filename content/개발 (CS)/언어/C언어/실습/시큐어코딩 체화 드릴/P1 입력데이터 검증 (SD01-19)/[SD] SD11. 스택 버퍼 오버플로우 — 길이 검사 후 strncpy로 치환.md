## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 함수 인자 문자열 → 경계 검사 없이 → 스택 지역 버퍼로 복사 |
| **공격 시나리오** | 24바이트 지역버퍼에 더 긴 문자열을 `strcpy()` 로 복사하면 반환주소까지 덮여, 공격자가 실행 흐름을 자신의 코드로 돌릴 수 있다. |
| **치환 규칙** | `strcpy` → 길이 비교 후 `strncpy` + 마지막 바이트 수동 널 종료. |
| **주의** | strcpy/strcat/sprintf/gets는 보이면 즉시 교체 대상. strncpy를 써도 마지막 바이트 널 종료는 직접 채워야 한다. |
| **자세한 설명** | [Part 1-3. 메모리 경계 계열 — 11. 스택에 할당된 버퍼 오버플로우](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-3.%20메모리%20경계%20계열.md#11-스택에-할당된-버퍼-오버플로우-cwe-121) (Bad/Good 전체 코드, 보충) |

```diff
- char buf[24];
- strcpy(buf, input);                      /* 길이 검사 없는 복사 */
+ char buf[24];
+ if (strlen(input) < sizeof(buf))
+     strncpy(buf, input, sizeof(buf)-1);
+ buf[sizeof(buf)-1] = '\0';                /* 반드시 null 종료 */
```

## 3. 주의해야 할 점

1. **`strncpy` 로 바꾸고 널 종료를 안 함**
	- `strncpy` 는 원본이 대상 크기보다 길거나 같으면 널 종료를 보장하지 않는다.
	- `out[out_size-1] = '\0'` 을 반드시 별도로 적어야 한다
1. **`test_bad_normal` 이 없어서 Good만 있으면 되는 줄 앎**
	- Bad가 "항상" 죽는 게 아니라 "긴 입력에서만" 죽는다는 걸 확인해야 한다
		- 짧은 입력에서도 죽으면 애초에 테스트 설계가 잘못된 것
1. **`expect_crash` 안에서 `fn()` 호출 전에 `fflush(stdout)` 을 안 함**
	- fork 이후 자식과 부모가 동일한 stdio 버퍼를 공유해 출력이 중복되거나 꼬일 수 있다(이 드릴 정도 규모에서는 거의 안 나타나지만, 실무 습관으로 기억)

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 8바이트 버퍼 + 두 개 필드

`char id[8]; char tag[8];` 처럼 인접한 두 버퍼 중 하나에 오버플로우가 나면 다른 필드까지 오염되는 것을 확인

### 변형 C — 함수 인자를 구조체로 교체

`char buf[N]` 을 구조체 멤버로 두고, 구조체 안의 다른 멤버(정수 플래그 등)가 오버플로우로 덮이는지 관찰(가능하면 값 검증까지 추가)
