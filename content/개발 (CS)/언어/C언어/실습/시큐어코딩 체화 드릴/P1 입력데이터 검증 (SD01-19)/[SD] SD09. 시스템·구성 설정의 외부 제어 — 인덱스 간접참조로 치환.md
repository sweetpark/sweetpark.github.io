## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 명령줄 인자 → 검증 없이 → 시스템 설정 함수 인자 |
| **공격 시나리오** | 공격자가 명령줄 인자로 호스트 ID나 FTP 서비스 포트를 바꾸면 시스템이 다르게 식별되거나 기존 서비스와 충돌해 서비스가 중단된다. |
| **치환 규칙** | 설정 함수 인자에 외부 값 직접 전달 금지 → 내부 상수 또는 "인덱스 → 상수" 매핑 테이블 경유. |
| **주의** | 외부에서는 "값"이 아니라 "선택지 번호"만 받게 하는 간접 참조(indirection)가 표준 해법이다. |
| **자세한 설명** | [Part 1-2. 외부제어·우회 계열 — 9. 시스템 또는 구성 설정의 외부 제어](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-2.%20외부제어·우회%20계열.md#9-시스템-또는-구성-설정의-외부-제어-cwe-15) (Bad/Good 전체 코드, 보충) |

```diff
- return atoi(portStr);                              /* 외부 문자열을 그대로 설정값으로 */
+ if (index < 0 || index >= PORT_TABLE_SIZE) return -1;
+ return PORT_TABLE[index];                            /* 외부에서는 "인덱스"만 받는다 */
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `portStr` | 외부(명령줄 인자/설정 요청) | 서비스 포트 설정값 |

**공격 입력표**

| 입력 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `"21"` (정상) | 21 | 정상 동작 |
| `"22"` | **22** | SSH 등 이미 쓰이는 포트와 충돌시켜 서비스 거부(DoS)를 유발할 수 있다 |
| `"0"` | **0** | 예약 포트(0)를 그대로 받아 시스템이 예기치 않게 동작할 수 있다 |

## 3. 주의해야 할 점

1. **`resolve_service_port_good` 도 문자열을 받아서 내부에서 `atoi` 후 범위 검사**
	- SD02와 똑같은 해법이 되어버린다
		- 이 항목의 핵심(값 자체를 안 받는 것)을 놓친 것
1. **테이블 인덱스 범위 검사에서 상한만 확인하고 음수는 빼먹음**
	- `index`가 `int` 이므로 음수가 들어올 수 있다.
	- `(size_t)index >= SIZE` 로 캐스팅 비교 시 음수가 거대한 값으로 바뀌어 우연히 막히는 경우와, 하한을 명시적으로 검사하는 경우를 구분해서 이해할 것
1. **테이블에 없는 값을 반환할 때 `0`을 리턴**
	- 포트 `0`은 그 자체로 유효하지 않은 값일 수 있다
		- 에러를 알리는 값(`-1`)과 정상 값(`0`)이 겹치지 않게 설계

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 호스트 ID 설정

PDF 원문의 `sethostid()` 사례처럼, 문자열이 아니라 정수 하나를 통째로 시스템 설정 함수에 넘기는 대신 미리 정의한 상수(`0xC0A80101` 등) 중 하나를 인덱스로 선택하도록 변경

### 변형 C — 테이블 크기를 런타임에 바꿔야 하는 상황

포트 후보가 설정 파일에서 동적으로 로드되는 경우, "로드된 테이블도 여전히 서버 내부 자원이고 외부는 인덱스만 받는다"는 원칙이 유지되는지 확인
