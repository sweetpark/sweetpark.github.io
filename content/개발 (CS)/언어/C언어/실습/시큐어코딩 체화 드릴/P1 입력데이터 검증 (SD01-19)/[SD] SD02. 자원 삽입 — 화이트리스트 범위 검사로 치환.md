## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 환경변수(`getenv("rPort")`) → 검증 없이 → 소켓 포트 식별자 |
| **공격 시나리오** | 포트 번호를 외부 입력으로 그대로 받으면 공격자가 원하는 대상으로 소켓을 열게 만들 수 있다. |
| **치환 규칙** | 자원 식별자(포트·파일명)는 화이트리스트 범위 검사 후 사용, 벗어나면 기본값 또는 중단. |
| **주의** | 포트·파일·핸들: 자원의 "이름"을 사용자가 정하게 두는 순간 접근제어는 무너진다. |
| **자세한 설명** | [Part 1-1. 삽입 계열 — 2. 자원 삽입](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-1.%20삽입%28Injection%29%20계열.md#2-자원-삽입-cwe-99) (Bad/Good 전체 코드, 보충) |

```diff
- return atoi(env_val);                              /* 검증 없이 그대로 포트로 사용 */
+ int port = atoi(env_val);
+ if (port < PORT_MIN || port > PORT_MAX) return PORT_DEFAULT;  /* 범위 밖이면 기본값 */
+ return port;
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `env_val` | 외부(환경변수) | 소켓 `bind()` 포트 인자 |

**공격 입력표**

| 입력 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `"3002"` (정상) | 3002 | 정상 동작 |
| `"22"` | **22** | SSH 등 다른 서비스 포트를 그대로 점유하려 든다 |
| `"99999"` | **99999** | `uint16_t` 범위(0~65535)를 넘어 소켓 바인딩 시 오동작·크래시 소지 |

---

## 3. 주의해야 할 점

1. **상한만 검사하고 하한(음수)은 빼먹음**
	- `atoi("-1")` 은 `-1` 을 반환한다.
	- 포트로 쓰이면 정수 변환 시 예기치 않은 값이 된다
1. **기본값을 범위 밖 값(예: `0`)으로 잡음**
	- "안전한 기본값"이 아니라 새로운 결함이 된다
1. **`atoi` 실패(비숫자 문자열)와 "범위 밖"을 구분하지 않음**
	- 변형 C에서는 이 둘을 구분해야 한다
		- `atoi("abc")` 는 `0` 을 반환하므로 "파싱 실패"인지 "값이 0"인지 알 수 없다(`strtol` + `endptr` 검사로 개선 가능)

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 로그 레벨 결정

환경변수로 로그 레벨 문자열(`"debug"`,`"info"`,`"error"` 등)을 받되, 화이트리스트에 없으면 `"info"` 로 강제.
값 자체가 아니라 "허용된 문자열 집합"으로 판단하는 연습

### 변형 C — 워커 스레드 수 결정

환경변수 정수값이 `1~16` 범위 밖이면 기본값 `4` 로 대체.
정수 파싱 실패(`atoi` 가 0을 반환하는 비정상 문자열)까지 구분해서 처리
