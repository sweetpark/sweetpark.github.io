## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 환경변수 필터 문자열 → 검증 없이 → LDAP 질의어 |
| **공격 시나리오** | 필터 문자열에 이름 대신 `*`(와일드카드)를 넣으면 한 사람 조회가 디렉터리 전체 조회로 바뀐다. |
| **치환 규칙** | 필터·DN을 외부 입력으로 조립 금지 → 상수 또는 화이트리스트로 고정. 불가피하면 `= + < > # ; \` 를 이스케이프. |
| **주의** | LDAP 필터의 `*` 와 `\|` 는 SQL의 OR과 같다. 필터 문자열을 사용자가 조립하게 두지 마라. |
| **자세한 설명** | [Part 1-1. 삽입 계열 — 5. LDAP 삽입](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-1.%20삽입%28Injection%29%20계열.md#5-ldap-삽입-cwe-90) (Bad/Good 전체 코드, 보충) |

```diff
- snprintf(filter, sizeof(filter), "(name=%s)", name);   /* 검증 없이 조립 */
+ if (!is_safe_ldap_value(name)) return -1;               /* 영숫자만 허용 */
+ snprintf(filter, sizeof(filter), "(name=%s)", name);
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `name` | 외부(조회 폼) | LDAP 필터 문자열 |

**공격 입력표**

| 입력 | Bad 결과(매칭 개수) | 이유 |
| :--- | :--- | :--- |
| `alice` (정상) | 1 | 정상 동작 |
| `*` | **3** | 와일드카드로 디렉터리 전체가 노출된다 |

---

## 3. 주의해야 할 점

1. **`*` 하나만 블랙리스트로 막음**
	- LDAP 특수문자는 `* ( ) \ NUL` 다섯 개다.
	- `(`, `)` 를 넣으면 필터 구조 자체를 깰 수 있다
1. **SD01의 SQL 필터 함수를 그대로 복사해서 예약어(`select` 등) 검사를 넣음**
	- LDAP은 SQL과 위험 문자 집합이 다르다.
	- 계열이 같다고 필터 내용까지 같지 않다
1. **DN과 필터의 이스케이프 규칙을 혼동**
	- DN 특수문자(`\`)와 필터 특수문자(`= + < > # ; \`)는 서로 다르다(변형 C에서 필터 이스케이프만 다룬다)

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 부서 조회

`(department=%s)` 형태.
`department` 값에 `)(uid=*` 같은 필터 이스케이프 시도가 들어올 수 있음을 고려

### 변형 C — 화이트리스트 대신 이스케이프로 전환

- 영숫자만 허용하는 대신, `* ( ) \ NUL` 다섯 문자를 LDAP RFC 방식(`\2a`, `\28` 등)으로 이스케이프하도록 바꾼다
	- 한글 이름처럼 영숫자가 아닌 정상 입력도 통과시켜야 할 때 필요한 접근
