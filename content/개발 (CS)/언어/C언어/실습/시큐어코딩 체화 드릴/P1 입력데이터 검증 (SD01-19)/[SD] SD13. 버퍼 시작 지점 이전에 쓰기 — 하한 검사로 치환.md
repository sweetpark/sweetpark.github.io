## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 토큰 개수(외부 입력) → 하한 검사 없이 → 감소하는 배열 인덱스 |
| **공격 시나리오** | 토큰 수가 배열 크기보다 많으면 인덱스가 0 아래로 내려가, 버퍼 앞쪽의 다른 변수나 스택 프레임이 덮인다. |
| **치환 규칙** | 감소 루프·포인터 뺄셈에 하한(0) 검사 명시, 가능하면 범위 검사가 내장된 접근자(`.at()`) 사용. |
| **주의** | 오버플로우는 위(상한)뿐 아니라 아래(하한)로도 발생한다. 감소 인덱스와 포인터 뺄셈에도 하한 검사를 붙여라. |
| **자세한 설명** | [Part 1-3. 메모리 경계 계열 — 13. 버퍼 시작 지점 이전에 쓰기](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-3.%20메모리%20경계%20계열.md#13-버퍼-시작-지점-이전에-쓰기-cwe-124) (Bad/Good 전체 코드, 보충) |

```diff
  int wordIndex = MAX_WORDS - 1;
  for (i = 0; i < count; i++) {
+     if (wordIndex < 0) return -1;   /* 하한 검사 */
      words[wordIndex] = i;
      wordIndex--;
  }
```

## 2. 재현 — 신뢰 경계와 공격 입력

**공격 입력표**

| `count` | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 10 (정상, 배열 크기와 동일) | 정상 동작 | 인덱스가 정확히 9→0으로 끝난다 |
| 11 (배열 크기 초과) | **버퍼 시작 이전 쓰기로 크래시** | 인덱스가 0 아래로 내려가 `words[-1]` 에 쓴다 |

---

## 3. 주의해야 할 점

1. **루프 시작 전에 `count > arr_size` 만 검사하고 끝냄**
	- 이 항목의 취약점은 "인덱스가 반복 중에 감소하다가" 발생한다.
	- 시작 전 검사만으로는 "정확히 언제 0 아래로 내려가는지" 찾기 어렵다
		- 매 반복 직전에 검사하는 게 더 명확하다(이 드릴의 모범답안 방식)
1. **상한 검사(SD15)와 하한 검사(이 항목)를 혼동해서 `>=` 방향을 반대로 씀**
	- "감소 인덱스는 하한", "증가 인덱스는 상한"이라는 방향 감각을 반사적으로 연결한다
1. **`int` 대신 `size_t` 로 인덱스를 선언**
	- `size_t` 는 부호 없는 타입이라 `wordIndex--` 가 0에서 한 번 더 감소하면 거대한 양수(랩어라운드)가 되어 오히려 더 위험해진다.
	- 감소하는 인덱스는 **부호 있는 타입**으로 선언한다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 포인터 뺄셈으로 순회

인덱스 대신 포인터(`int *p = arr + N - 1; *p-- = ...`)로 같은 로직을 짜서, 포인터가 배열 시작보다 앞으로 가는 경우도 같은 문제임을 확인

### 변형 C — 가변 길이 배열(VLA) 버전

크기를 런타임에 받는 배열로 바꿔서, 컴파일타임 상수(`MAX_WORDS`)에 의존하지 않는 하한 검사를 설계
