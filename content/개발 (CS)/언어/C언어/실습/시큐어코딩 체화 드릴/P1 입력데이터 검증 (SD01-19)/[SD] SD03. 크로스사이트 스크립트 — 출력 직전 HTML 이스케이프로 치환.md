## 1. 이론 요약

| 항목 | 내용 |
|---|---|
| **신뢰 경계** | 게시글 입력 → 검증 없이 → HTML 출력 스트림 |
| **공격 시나리오** | 게시판 제목에 `<script>alert(1)</script>` 를 저장하면 그 글을 여는 모든 사용자 브라우저에서 공격자 코드가 실행된다. |
| **치환 규칙** | · 출력 직전에 `< > & "` 를 엔티티로 치환.<br>· 태그가 필요하면 허용 태그 화이트리스트만 통과. |
| **주의** | 입력을 저장할 때가 아니라 화면에 그릴 때 이스케이프하라. 블랙리스트보다 허용 태그 화이트리스트가 안전하다. |
| **자세한 설명** | [Part 1-1. 삽입 계열 — 3. 크로스사이트 스크립트(XSS)](개발%20%28CS%29/언어/C언어/시큐어코딩/Part%201.%20입력데이터%20검증%20및%20표현/[시큐어코딩]%201-1.%20삽입%28Injection%29%20계열.md#3-크로스사이트-스크립트xss-cwe-79) (Bad/Good 전체 코드, 보충) |

```diff
- snprintf(out, out_size, "<FONT...>%s</FONT>", title);       /* 그대로 삽입 */
+ escape_html(title, escaped, sizeof(escaped));                /* < > & " 를 엔티티로 */
+ snprintf(out, out_size, "<FONT...>%s</FONT>", escaped);
```

## 2. 재현 — 신뢰 경계와 공격 입력

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `title` | 외부(게시글 작성 폼) | HTML 출력 스트림 |

**공격 입력표**

| 입력 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| `Hello World` (정상) | 그대로 출력 | 정상 동작 |
| `<script>alert(1)</script>` | **`<script>` 태그가 그대로 살아남는다** | 열람자 브라우저에서 스크립트가 실행된다 |

## 3. 주의해야 할 점

1. **`&` 를 가장 나중에 치환**
	- `<` 를 `&lt;` 로 바꾼 뒤 `&` 를 다시 치환하면 `&lt;` 의 `&` 까지 `&amp;lt;` 로 이중 치환된다.
	- **`&` 를 가장 먼저** 치환해야 한다
1. **이스케이프를 **저장 시점**에 함**
	- 요구사항에 따라 원문을 그대로 저장해야 하는 경우(수정 화면에 다시 보여줘야 할 때)가 있다.
	- 이스케이프는 화면에 낼 때(렌더링 시점)가 원칙
1. **치환 결과 버퍼 크기를 원본과 같게 잡음**
	- `<` 한 글자가 `&lt;` 네 글자가 된다
		- 이스케이프 버퍼는 원본보다 넉넉해야 한다

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다. 저장소에는 변형 A 만 문제로 있다.

### 변형 B — 댓글 본문 렌더링

- 개행문자(`\n`)를 `<br>` 로 바꿔야 하는 요구사항이 추가된다
	- 이스케이프 순서(개행 치환을 먼저 할지, HTML 이스케이프를 먼저 할지)를 스스로 판단해본다

### 변형 C — 속성값 렌더링

`<a href="%s">` 의 `href` 값을 이스케이프.
작은따옴표(`'`)도 이스케이프 대상에 추가해야 하는 이유를 확인
