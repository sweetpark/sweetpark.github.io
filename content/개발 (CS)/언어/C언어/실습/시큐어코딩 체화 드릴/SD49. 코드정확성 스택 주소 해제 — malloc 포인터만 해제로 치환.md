# SD49. 코드정확성: 스택 주소 해제 — malloc 포인터만 해제로 치환

> **원본 항목**: [Part 5. 코드 오류 — 7. 코드정확성: 스택 주소 해제](../../시큐어코딩가이드/Part%205.%20코드%20오류.md#7-코드정확성-스택-주소-해제-cwe-730) `CWE-730`
> **repo 폴더**: `sd49_badfree/` (`make D=sd49_badfree T=main`)
> **목표 시간**: 1회차 8분 / 2회차 5분 / **3회차 3분**
> `free()`의 유일한 정당한 인자는 "내가 malloc 계열로 받은 포인터"뿐이다. ASan은 `free()`를 가로채 대상 주소가 실제로 malloc이 추적 중인 청크인지 확인하므로, 이 위반은 **진짜 UB로 100% 결정론적으로 재현**된다.

---

## 0. 이 드릴로 체화할 것

```diff
- char p[10];
- free(p);                          /* 스택 주소 해제 -> 비정상 동작 */
+ char *p = (char *)malloc(10);
+ if (!p) return -1;
+ /* 사용 */
+ free(p);                          /* malloc으로 받은 포인터만 해제 */
```

`free()`에 넘기는 포인터가 "정말 malloc 계열이 반환한 것인가"를 항상 스스로에게 묻는다. 스택 배열, 전역 변수, `strtok()`의 반환값은 전부 대상이 아니다.

## 1. 취약 시나리오 — 변형 A: 임시 버퍼 정리

> [!QUOTE] 요구사항서 (발췌)
> 임시로 쓴 버퍼를 다 쓴 뒤 정리한다.
> - 힙에서 받은 메모리만 `free()` 대상이다.

### 신뢰 경계

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| (해당 없음) | — | `free()` 대상 오분류(스택 주소를 힙 포인터로 착각) 자체가 결함이다 |

### 공격 입력표

| 상황 | Bad 결과 | 이유 |
| :--- | :--- | :--- |
| 스택 배열 `p`를 그대로 `free(p)` | **`bad-free`로 크래시**(`expect_crash`가 감지) | `free()`가 관리하는 힙 메타데이터에 스택 주소가 없으니 즉시 위반이 드러난다 |
| 같은 상황(Good) | 정상 종료 | `malloc`으로 받은 포인터만 `free`한다 |

### 회차별 변형

| 회차 | 변형 | 요구사항 |
| :--- | :--- | :--- |
| **A (1회차)** | 임시 버퍼 정리(스택 배열 vs `malloc`) | 위 내용 |
| **B (2회차)** | **`strtok()` 반환값을 `free()`하는 실수로 변형** | 가이드 원문처럼 `strtok(str, " ,.-")`의 반환값을 순회하며 실수로 `free(pch)`를 호출하는 버전을 만들어본다 — `strtok`은 원본 문자열 내부를 가리킬 뿐 아무것도 할당하지 않는다는 걸 크래시로 확인한다 |
| **C (3회차)** | **이중 해제(double free)로 확장** | 이번엔 진짜 `malloc` 포인터를 두 번 연속 `free()`하는 함수를 만들어, "malloc 포인터라도 한 번만 해제해야 한다"는 별개의 규칙까지 재현한다 |

### 시험 코드 — 이 형태를 고정한다

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>
#include "badfree.h"

static int g_fail = 0;
#define T_TRUE(cond, msg) \
    do { if (!(cond)) { g_fail++; \
        printf("  X %s:%d %s\n", __func__, __LINE__, msg); } } while (0)

static int expect_crash(void (*fn)(void))
{
    pid_t pid = fork();
    if (pid == 0) { fn(); _exit(0); }
    int status = 0;
    waitpid(pid, &status, 0);
    if (WIFSIGNALED(status)) return 1;
    if (WIFEXITED(status) && WEXITSTATUS(status) != 0) return 1;
    return 0;
}

static void test_bad_is_vulnerable(void)
{
    T_TRUE(expect_crash(free_stack_addr_bad) == 1,
        "Bad는 malloc으로 받지 않은 스택 주소를 free해 크래시해야 한다(취약점 재현)");
}

static void test_good_normal(void)
{
    T_TRUE(alloc_and_free_good() == 0, "Good은 malloc으로 받은 주소만 free하므로 정상 종료해야 한다");
}

int main(void)
{
    test_bad_is_vulnerable();
    test_good_normal();
    printf(g_fail ? "FAIL %d\n" : "PASS\n", g_fail);
    return g_fail ? 1 : 0;
}
```

> [!WARNING] `free_stack_addr_bad`를 그대로 타이핑하면 컴파일이 안 될 수 있다
> `free(p)`에 스택 배열을 넘기면 clang이 `-Wfree-nonheap-object`로 **컴파일 타임에 잡아낸다**(`-Werror`라 빌드 실패). [SD38](SD38.%20제대로%20제어되지%20않은%20재귀%20—%20깊이%20제한%20동반으로%20치환.md), [SD47](SD47.%20스택%20변수%20주소%20리턴%20—%20힙%20할당%20반환으로%20치환.md)과 같은 방식으로 `#pragma clang diagnostic push` / `ignored "-Wfree-nonheap-object"` / `pop`으로 감싸 "의도적으로 재현한 버그"임을 명시한다.

## 4. 자주 하는 실수

| 실수 | 왜 문제인가 |
| :--- | :--- |
| "포인터가 유효해 보이니 괜찮다"고 판단 | `free()`의 정당성은 "가리키는 메모리가 유효한가"가 아니라 **"malloc 계열이 반환한 그 주소인가"**다. 스택 주소도 함수가 살아있는 동안은 완전히 유효한 메모리지만 `free()` 대상은 아니다 |
| 라이브러리 함수의 반환값을 볼 때마다 "할당 여부"를 확인하지 않음 | `strtok()`, `getenv()`, `ctime()` 등 많은 표준 함수가 "내부 정적 버퍼" 또는 "입력 문자열 내부"를 가리키는 포인터를 반환한다. 반환값을 받을 때마다 매뉴얼에서 "할당된 메모리인가"를 확인하는 습관이 필요하다 |
| `free()` 이후 포인터를 `NULL`로 안 만듦(이 드릴 자체보단 습관 문제) | 이 항목의 핵심은 아니지만, `free(p)` 직후 `p = NULL;`을 습관화하면 실수로 같은 포인터를 다시 `free()`하는 이중 해제(변형 C)를 예방하는 데 도움이 된다 |

## 5. 모범답안 (변형 A)

> [!success]- 다 치고 나서 열 것 — `badfree.h` / `badfree.c`
> ```c
> #ifndef BADFREE_H
> #define BADFREE_H
> void free_stack_addr_bad(void);
> int  alloc_and_free_good(void);
> #endif
> ```
> ```c
> #include <stdlib.h>
> #include "badfree.h"
>
> #pragma clang diagnostic push
> #pragma clang diagnostic ignored "-Wfree-nonheap-object"
> void free_stack_addr_bad(void)
> {
>     char p[10];
>     free(p);                          /* 스택 주소 해제 -> 비정상 동작 */
> }
> #pragma clang diagnostic pop
>
> int alloc_and_free_good(void)
> {
>     char *p = (char *)malloc(10);
>     if (!p) return -1;
>     p[0] = 'x';                       /* 사용 */
>     free(p);                          /* malloc으로 받은 포인터만 해제 */
>     return 0;
> }
> ```
>
> **눈여겨볼 점**: `free_stack_addr_bad`의 `p`는 `char p[10]`(스택 배열)이고, `alloc_and_free_good`의 `p`는 `char *p = malloc(10)`(힙 포인터)이다. **선언 방식 하나가 그 변수를 `free()`해도 되는지 여부를 완전히 결정한다** — 변수 이름도 크기도 똑같은데 말이다.
