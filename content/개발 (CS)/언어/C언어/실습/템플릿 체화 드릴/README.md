# 템플릿 체화 드릴 _index

> **목적은 "C를 배우는 것"이 아니다.**
> [c코드 골격](개발%20%28CS%29/언어/C언어/코드%20골격/c코드%20골격%20목록.md)의 뼈대가 **생각하지 않아도 손에서 나오게** 만드는 것.
> 그래서 이 폴더의 드릴은 전부 **같은 모양**이다.
> **글(이 폴더)은 요구사항 명세·뼈대·주의점을 맡고, 문제와 채점은 저장소가 맡는다.**

---

## 이 폴더와 옆 폴더(`실습/`)의 차이

| | [실습 가이드](개발%20%28CS%29/언어/C언어/[실습]%20C언어%20시스템%20프로그래밍%20단계별%20실습%20가이드.md) (기존) | **템플릿 체화 드릴** (이 폴더) |
| :--- | :--- | :--- |
| 출발점 | 개념 노트 (엔디안, atomic, epoll…) | **요구사항 한 장** (규격서 흉내) |
| 목표 | 그 개념이 동작하는 걸 본다 | **매번 같은 뼈대로 친다** |
| 성공 기준 | 돌아간다 | **안 보고 10분 안에 뼈대가 나온다** |
| 반복 | 1회 | **같은 문제를 보는 양을 줄이며 반복** |

둘은 대체 관계가 아니다.
개념이 흔들리면 `실습/`, 손이 안 움직이면 여기.

## 하루 30분 루틴

| 순서 | 시간 | 할 일 |
|---|---|---|
| ① 백지 구현 | 10분 | `problem.md` 만 보고 `solution.c` 를 채운다. 막히면 `HINT1` → `HINT2` |
| ② 일부러 깨뜨리기 | 8분 | 틀린 버전을 만들어 채점이 잡아내는지 본다 |
| ③ 노트와 비교 | 5분 | `NOTE.md` 와 이 폴더의 글, 필요하면 `make P039 ANS=1` |
| ④ 한 줄 설명 | 7분 | 막힌 곳을 한 줄로 쓴다 (`MISTAKES.md` 에 추가) |

- 같은 문제를 다시 풀 때는 `make reset-P039` 로 백지로 되돌린다 (**반복할수록 보는 것을 줄인다**: 의사코드 전체 → 번호만 → 백지)
- 복습 간격: 1회차 D+0 → 2회차 D+1 → 3회차 D+4 → 점검 D+14, 목표 시간을 넘기면 그 문제는 한 단계 앞으로

## 저장소 사용법

```bash
make P039              # drill/P039_*/solution.c 를 빌드하고 채점 (gcc -Werror, ASan/UBSan/LSan)
make P039 ANS=1        # 모범답안으로 채점 (푼 뒤 확인용)
make reset-P039        # solution.c 를 백지로 되돌림
make verify            # 전체 문제의 채점 가능성 검증
```

- `-Wall -Wextra -Werror` 를 빼지 않는다: 경고를 켜 두고 무시하는 습관이 제일 나쁘다. **경고 = 빌드 실패**로 만들어야 손이 바뀐다
- 공통 헤더(`common.h` · `log.h` · `safe.h` · `guard.h`)는 저장소의 [`drill/common/`](https://github.com/sweetpark/c-playgound/tree/main/drill/common)
- D8(P045)은 `libjansson-dev` 가 필요하다

## 합격 기준 (공통)

| 항목 | 기준 |
|---|---|
| 채점 | `make P0xx` 의 마지막 줄이 **`PASS`** (D6 은 `check.sh` 의 `PASS`) |
| 빌드 위생 | 경고 **0**, 새니타이저(ASan / UBSan / LeakSanitizer) 리포트 **0** |
| 시간 | 목표 시간 이내 (2배를 넘으면 그 회차는 다시) |
| 뼈대 | 가드로 시작하고 `memset(out)` 을 하며, 자원을 잡았다면 `goto CLEANUP` 단일 출구 |

**`PASS` 가 아니면 그 회차는 통과가 아니다.**
