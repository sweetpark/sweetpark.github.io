# P111. 공유메모리 attach-or-create — 있으면 붙고 없으면 만든다

> [!TIP]
> - 이론: [공유메모리 세그먼트 — 크기·key·권한·수명과 삭제](개발%20%28CS%29/CS%20기초/운영체제/[OS]%20공유메모리%20세그먼트%20—%20크기·key·권한·수명과%20삭제.md) (§2 크기, §3 `shmget` 플래그)
> - 실무: 공유메모리 지도 — ipcs -m 의 키가 누구 것인가
> - 실습: [P111_shm_attach_or_create](https://github.com/sweetpark/c-playgound/tree/main/drill/P111_shm_attach_or_create) — `make P111` 로 채점
> - 짝 문제: P106 `shm_probe` (세그먼트의 **수명**) → 이 문제는 **기동 순서**를 다룬다

## 📌 한눈에 보기

| 항목 | 내용 |
|---|---|
| 상황 | 데몬이 기동할 때 환경변수의 key 로 공유메모리를 **찾고, 없으면 만들고, 붙는다** |
| 치환 규칙 | 읽기(`strtoul`) → 만들기(`IPC_CREAT\|IPC_EXCL`) → 찾기(`shmget(key,0,0)`) → **크기 비교(`IPC_STAT`)** → 붙기(`shmat(…,0)`) → **성공했을 때만 전역에 저장** |
| 장애 예 | 구조체가 커졌는데 옛 크기의 세그먼트가 남아 있다 → `shmget` 은 통과 → 새 필드를 **세그먼트 밖**에서 읽는다 |
| 원인 | `shmget` 의 크기 검사는 "요청이 더 클 때"만 걸린다. 작은 요청은 조용히 통과한다 |
| 실습 문제 | [P111](https://github.com/sweetpark/c-playgound/tree/main/drill/P111_shm_attach_or_create) |

## 1. 이론 요약

| 단계 | 호출 | 확인할 것 |
| :--- | :--- | :--- |
| ① key 읽기 | `getenv` → `strtoul(s, &end, 16)` | 없음 / 16진수 아님 / 찌꺼기·부호 / 0 / 32비트 초과 |
| ② 만들기 | `shmget(key, size, IPC_CREAT \| IPC_EXCL \| 0660)` | 성공 = **내가 만들었다** (`created = 1`) |
| ③ 찾기 | `EEXIST` 면 `shmget(key, 0, 0)` | 크기 0·권한 0 = "찾기만". `ENOENT` 면 그 사이 지워진 것 → 처음부터 |
| ④ 크기 비교 | `shmctl(id, IPC_STAT, &ds)` → `ds.shm_segsz == size` | 작아도 커도 거절 |
| ⑤ 붙기 | `shmat(id, NULL, 0)` | 실패값은 `(void *)-1` |
| ⑥ 저장 | `g_addr = p` | **성공했을 때만.** 실패값을 전역에 넣지 않는다 |

```diff
- sscanf(buf, "%x", &had_shmkey);                          /* 읽기 실패해도 모른다 → 쓰레기 key */
- had_shmid = shmget(key, size, 0664 | IPC_CREAT | IPC_EXCL);
- ...
- had_shmid = shmget(key, size, 0664);                     /* 요청이 작으면 통과한다 */
- hadp = (c_had_t *) shmat(had_shmid, (void *)0, 0664);    /* 3번째 인자는 shmflg. 실패값이 전역에 남는다 */
- if ((long)hadp == -1) { ... }
+ if (parse_key(getenv(name), &key) < 0) return E_BADKEY; /* strtoul + 끝 검사 + 0/32비트 거절 */
+ id = shmget(key, size, IPC_CREAT | IPC_EXCL | 0660);
+ ...
+ id = shmget(key, 0, 0);                                  /* 찾기만 */
+ shmctl(id, IPC_STAT, &ds); if (ds.shm_segsz != size) return E_SIZE;
+ p = shmat(id, NULL, 0);
+ if (p == (void *)-1) return E_ATTACH;                    /* 전역은 건드리지 않았다 */
+ g_addr = p;
```

## 2. 재현 — 어디서 뚫리나

**신뢰 경계** : 검증 없이 흘러가는 곳

| 값 | 출처 | 검증 없이 흘러가는 곳 |
| :--- | :--- | :--- |
| `TELCO_HA_SHMKEY` 환경변수 | 운영자·기동 스크립트 | `sscanf` → `shmget` 의 key |
| 이미 있는 세그먼트 | 이전 버전·다른 계정이 남긴 것 | `shmat` 후 구조체로 읽는 메모리 |

**장애 입력표**

| 상황 | 틀린 코드의 결과 | 이유 |
| :--- | :--- | :--- |
| `TELCO_HA_SHMKEY=zzz` | 초기화 안 된 key 로 세그먼트가 **새로 생긴다** (`ipcs -m` 에 쓰레기 key) | `sscanf` 반환값을 안 봤다 |
| `TELCO_HA_SHMKEY=-1` | `strtoul` 이 받아서 `0xFFFFFFFF` 로 읽힌다 | 부호를 걸러야 한다 |
| 옛 세그먼트 8192 바이트, 요청 4096 | 에러 없이 붙는다 | `shmget` 은 요청이 **큰** 경우만 `EINVAL` |
| 읽기 전용(0400) 세그먼트 | `shmat` 실패 후 전역 `hadp == (void *)-1` | 이후 `hadp != NULL` 검사가 -1 을 유효한 주소로 본다 |
| 데몬 두 개가 동시 기동 | 둘 다 자기가 만들었다고 믿고 **초기화를 두 번** 한다 | `IPC_EXCL` 없이 `IPC_CREAT` 만 썼다 |

## 3. 주의해야 할 점

1. **"만든 쪽만 초기화한다"가 성립하려면 만들었는지 알아야 한다**
	- `IPC_CREAT` 만 쓰면 "새로 만들었나, 있던 걸 얻었나"를 구분할 수 없다
	- `IPC_CREAT | IPC_EXCL` 로 한 번에 시도하고 `EEXIST` 만 "붙기"로 넘긴다 (조회 후 생성은 사이가 벌어져 경쟁이 생긴다)
1. **그래도 "만든 직후, 초기화 끝나기 전"의 틈은 남는다**
	- 다른 프로세스가 그 사이에 붙으면 0 으로 채워진 상태를 읽는다
	- 이 틈은 이 문제의 범위가 아니다 → 세그먼트 안에 `magic`/`ready` 를 두는 핸드셰이크로 푼다 → [P112](개발%20%28CS%29/언어/C언어/실습/개념%20드릴/[P]%20P112.%20공유메모리%20배치%20—%20헤더·오프셋·ready로%20믿을%20수%20있는%20구조%20만들기.md)
1. **`shmget` 의 두 번째 호출에 크기와 권한을 또 주지 말 것**
	- 크기 `0`, 플래그 `0` 이 "찾기만"이다. 크기를 주면 의미 있는 검사가 아니라 우연한 `EINVAL` 이 된다
	- 권한을 주면 읽기 전용 세그먼트에서 `shmget` 이 실패해, 원인(`shmat` 단계)이 가려진다
1. **실패 원인을 한 코드로 뭉치지 말 것**
	- 크기 불일치(→ 세그먼트를 지워야 한다)와 권한 없음(→ 계정을 확인한다)은 조치가 정반대다
1. **`shmat(id, NULL, 0664)` 이 "돈다"고 안심하지 말 것**
	- 3번째 인자는 권한이 아니라 `shmflg`(`SHM_RDONLY` 등). 우연히 겹치는 비트가 없어서 동작할 뿐이다
1. **이미 붙은 채로 다시 부를 때의 정책을 정해 둘 것**
	- 이 문제의 정책: 먼저 뗀다. 실패해도 이전 것은 떨어진 상태로 둔다 ("실패하면 이전 상태가 유지된다"로 짜면 호출자가 어느 쪽인지 알 수 없다)

## 4. 변형 (부록)

같은 치환 규칙을 다른 소재로 다시 치는 문제들이다.

### 변형 B — 세그먼트 헤더(`magic`/`version`/`ready`)로 초기화 핸드셰이크 → **P112 로 만들었다**

### 변형 C — 세그먼트 안에 포인터를 저장하면 안 되는 이유 → **P112 로 만들었다**

### 변형 D — 같은 key 로 크기만 바뀐 새 버전을 올릴 때

- 크기가 다르면 `E_SIZE` 로 거절한 뒤, 운영자가 `ipcrm` 으로 지우고 재기동하는 절차를 로그 메시지에 담는다 (원인별 조치가 다른 메시지: 크기 불일치 / 권한 없음 / 그 사이 삭제)
