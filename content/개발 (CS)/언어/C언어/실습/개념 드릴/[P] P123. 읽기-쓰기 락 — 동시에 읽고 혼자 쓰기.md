## 📌 한눈에 보기

| 항목 | 내용 |
|---|---|
| 상황 | 읽기가 압도적으로 많은 공유 데이터 (설정 테이블, 라우팅 표). 뮤텍스는 읽기끼리도 줄을 세운다 |
| 치환 규칙 | 읽기 `rdlock` / 쓰기 `wrlock` / `cas` 는 **읽기 락을 풀고** 쓰기 락을 잡은 뒤 **다시 확인** / 쓰기 우선 속성 |
| 장애 예 | 읽기 락을 쥔 채 `wrlock` 해서 영구 교착 / 쓰기가 영원히 못 들어감 / 갱신 유실 |
| 원인 | rwlock 은 승격을 지원하지 않고, 기본값은 읽기 우선이다 |
| 실습 문제 | [P123](https://github.com/sweetpark/c-playgound/tree/main/drill/P123_rwlock_use) |

## 1. 이론 요약

| | 읽기 락 `rdlock` | 쓰기 락 `wrlock` |
|---|---|---|
| 다른 스레드의 읽기 락과 | **동시 허용** | 대기 |
| 다른 스레드의 쓰기 락과 | 대기 | 대기 |

```
읽기 스레드 4개 × 150ms  → 동시에 안에 있다 (최대 4, 총 ≈ 150ms).  뮤텍스라면 600ms
쓰기 락 300ms 동안        → 읽기도 기다린다 (그리고 새 값을 읽는다)

cas(expect, newv):
   rdlock; cur = v; unlock                ← 읽기 락을 쥔 채 wrlock 하면 자기 자신을 기다려 교착
   cur != expect → -EAGAIN
   wrlock
   v != expect   → unlock; -EAGAIN         ← 풀고 다시 잡은 사이에 바뀌었을 수 있다 (다시 확인)
   v = newv; unlock
```

| 항목 | 규칙 |
| :--- | :--- |
| 승격 불가 | 읽기 락 → 쓰기 락 승격은 없다. glibc 는 감지하지 못하고 그냥 멈춘다 |
| 풀고 → 잡고 → **다시 확인** | 사이에 다른 스레드가 값을 바꿀 수 있다 (TOCTOU). 안 하면 둘 다 "아직 5다"를 보고 둘 다 6으로 바꿔 갱신 유실 |
| 쓰기 우선 | `PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP`. 기본(읽기 우선)은 읽기가 빈틈없이 겹치면 쓰기가 **영원히** 못 들어간다 |
| `NONRECURSIVE` | 쓰기 우선에서는 **같은 스레드가 읽기 락을 재귀로** 잡다가 사이에 쓰기가 끼면 교착. 읽기 락 재귀 금지 |
| 읽기 락 안에서 쓰기 | 금지. 읽는 스레드 둘이 동시에 쓴다 |

```diff
- rdlock; if (v == expect) { wrlock; v = newv; unlock; }            /* 승격: 교착 */
- rdlock; cur = v; unlock; wrlock; v = newv; unlock;                /* 다시 확인 없음: 갱신 유실 */
+ rdlock; cur = v; unlock; if (cur != expect) return -EAGAIN;
+ wrlock; if (v != expect) { unlock; return -EAGAIN; } v = newv; unlock;
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| 읽기에 `wrlock` | 읽기가 한 번에 하나씩 (시험 `[2]`: 최대 동시 수 1) | 뮤텍스와 같아진다 |
| 읽기 락 쥔 채 `wrlock` | `TIMEOUT` (영구 교착) | 승격 불가 |
| `cas` 가 다시 확인 안 함 | 성공 횟수의 합 > 최종 값 (8스레드 × 3000) | TOCTOU |
| 기본 rwlock + 읽기 스레드 3개가 빈틈없이 겹침 | 쓰기가 1.5초 넘게 못 들어감 (시험 `[6]` 은 300ms 안) | 읽기 우선: 새 읽기를 계속 들여보낸다 |
| 읽기 락 안에서 캐시 채우기 | 읽는 스레드 둘이 같은 곳에 동시에 쓴다 | 읽기 락은 읽기 전용 |

## 3. 주의해야 할 점

1. **rwlock 이 항상 빠르지는 않다**
	- 읽기 락도 내부 카운터를 갱신한다 → 읽기 스레드가 많으면 캐시 줄 경합. 임계구역이 `+= 1` 처럼 짧으면 뮤텍스가 빠르다
	- 읽기가 많고 **임계구역이 길 때** 이득이다
1. **쓰기 우선으로 바꾸면 읽기가 굶을 수도 있다** — 쓰기가 계속 오면. 어느 쪽이 중요한지 정하고 선택한다
1. **값 하나라면 원자 변수**가 더 낫다 (락 없는 카운터). `cas` 는 `__atomic_compare_exchange` 로 락 없이 된다
1. **시간 제한이 필요하면** `pthread_rwlock_timedrdlock/timedwrlock` (절대 시간. [P119](개발%20%28CS%29/언어/C언어/실습/개념%20드릴/[P]%20P119.%20POSIX%20메시지%20큐%20—%20절대%20시간%20제한과%20우선순위.md) 과 같은 함정)

| 상황 | 선택 |
|---|---|
| 읽기와 쓰기가 비슷하거나 임계구역이 짧다 | 뮤텍스 |
| 읽기가 압도적이고 임계구역이 길다 | rwlock (쓰기 우선) |
| 값 하나 | 원자 변수 |
| 읽기가 매우 많고 쓰기가 아주 드물다 | RCU / 복사 후 교체 |

### 변형 C — `trywrlock` 으로 낙관적 갱신

- 읽기 락으로 읽은 뒤 `trywrlock` 이 실패하면 처음부터 다시. 승격 없이 재시도 루프로 푼다
