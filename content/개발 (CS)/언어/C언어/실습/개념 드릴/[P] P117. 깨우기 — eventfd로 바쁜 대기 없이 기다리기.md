## 📌 한눈에 보기

| 항목 | 내용 |
|---|---|
| 상황 | 큐가 비면 받는 쪽은 **자고**, 보내는 쪽이 넣으면 **깨운다** |
| 치환 규칙 | 기다리기 전에 **큐부터** → `poll(eventfd)` → 깨면 **신호 비우기** → 다시 큐부터. 보내는 쪽은 **넣은 뒤에** 깨운다 |
| 장애 예 | 마지막 항목 하나가 영원히 안 나온다 (신호는 한 번에 비워졌는데 큐에는 아직 있다) |
| 원인 | `poll` 부터 하고 큐를 나중에 보았다 |
| 실습 문제 | [P117](https://github.com/sweetpark/c-playgound/tree/main/drill/P117_eventfd_wake) |

## 1. 이론 요약

```
받는 쪽 evh_pop                          보내는 쪽 evh_push
 ┌─ 큐에서 꺼내기 시도 ── 되면 return     ① 큐에 넣는다 (공개)
 │  남은 시간 계산 (마감 시각 − 지금)     ② eventfd 에 1 을 쓴다 (깨운다)
 │  poll(eventfd, 남은 시간)
 │  깨어났으면 read(eventfd) ← 신호 비우기
 └─ (다시 위로)
```

| 항목 | 규칙 |
| :--- | :--- |
| eventfd | 8바이트 카운터. `write` 는 더하고 `read` 는 **전체를 읽어 0 으로** 만든다. `EFD_NONBLOCK`(비우는 read 가 안 막힘) + `EFD_CLOEXEC` |
| 큐 먼저 | 신호 3개가 한 번에 읽혀 카운터가 0 이 돼도 큐에는 항목이 남는다 → 기다리기 **전에 항상 큐를 본다** |
| 신호 비우기 | 안 비우면 `poll` 이 곧바로 돌아와 바쁜 대기 |
| 순서 | 보내는 쪽은 **넣은 뒤에** 깨운다. 거꾸로면 받는 쪽이 빈 큐를 보고 신호를 비우고 자버린다 |
| 시간 제한 | `CLOCK_MONOTONIC` 으로 **마감 시각을 한 번만** 계산. `EINTR` 뒤에 `poll(…, timeout)` 을 그대로 다시 부르면 시그널마다 제한이 처음부터 시작해 영원히 안 끝난다 |

```diff
- while (1) { poll(efd); read(efd); if (try_pop(&v)==0) return 0; }          /* poll 먼저 */
+ for (;;) { if (try_pop(&v)==0) return 0; ...; poll(efd, left_ms); read(efd); }
- write(efd, &one, 8); try_push(q, v);                                       /* 깨운 뒤에 넣음 */
+ if (try_push(q, v) == 0) write(efd, &one, 8);
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| 항목 3개를 연달아 넣고 3번 `pop` | 첫 번째만 즉시, 둘째는 **timeout** | `poll` 먼저: 신호가 한 번에 비워졌다 |
| 신호를 안 비움 | 300ms 대기에 CPU 300ms | `poll` 이 즉시 돌아온다 |
| 5ms 마다 시그널이 오는 환경에서 `pop(…, 300)` | 영원히 안 끝남 | `EINTR` 마다 300ms 를 새로 잰다 |
| 깨운 뒤에 넣음 | **가끔** 항목이 큐에서 잠든다 | 깨어난 받는 쪽이 빈 큐를 보고 신호를 비웠다. 틈이 좁아서 시험으로 거의 안 잡히고 운영에서 터진다 |

---

## 3. 주의해야 할 점

1. **시험이 못 잡는 규칙이 있다 — "넣은 뒤에 깨운다"**
	- 틈이 아주 좁아 결정적으로 재현할 수 없다. 코드 리뷰에서 순서를 확인한다
1. **받는 쪽이 여럿이면 이 구조가 아니다**
	- 같은 eventfd 를 여럿이 읽으면 누가 신호를 비웠는지에 따라 다른 쪽이 잠든 채 남는다. `EFD_SEMAPHORE` 나 받는 쪽마다 eventfd
1. **`EFD_NONBLOCK` 이 없으면** 신호를 비우는 `read` 가 빈 카운터에서 영원히 막힌다
1. **"자기 전에 큐를 다시 본다" + "깨우는 쪽이 신호를 남긴다"** — 이 둘이 맞물려야 깨우기를 놓치지 않는다. 조건변수(`pthread_cond`)에서 "술어를 락 안에서 다시 검사한다"와 같은 생각이다

## 4. 변형 (부록)

### 변형 B — 파이프로 깨우기 (self-pipe trick)

- `eventfd` 가 없는 환경(macOS)에서는 파이프의 한쪽에 1바이트를 쓴다. 비우기는 `read` 를 `EAGAIN` 까지 반복

### 변형 C — `signalfd` / `timerfd` 와 한 `poll` 에 묶기

- 큐 도착, 종료 시그널, 주기 타이머를 한 이벤트 루프에서 기다린다 (데몬의 기본 구조)
