## 1. 이론 요약

| 항목 | 규칙 |
| :--- | :--- |
| `sun_path` | 108바이트(널 포함). `strlen >= 108` 이면 `-ENAMETOOLONG`. **잘라 쓰지 않는다** (잘린 경로는 다른 파일) |
| 이미 있는 파일 | 소켓이 아니면 `-EEXIST`, **지우지 않는다** |
| 소켓 파일이 있을 때 | `connect` 로 두드려 본다. 붙으면 살아 있는 서버 → `-EADDRINUSE`, `ECONNREFUSED` 면 죽은 서버의 흔적 → 지우고 다시 |
| 파일 권한 | **만드는 순간부터** 0600: `umask(0177)` → `bind` → `umask(old)`. 소켓 파일 권한 = 접속 권한 |
| `SOCK_CLOEXEC` | 안 주면 `exec` 한 자식에게 소켓이 상속되어 서버가 죽어도 경로가 안 풀린다 |
| 상대 신원 | `getsockopt(SO_PEERCRED)` → uid/pid. **연결 시점에 커널이 기록**한 값이라 속일 수 없다. 인증은 uid 로, pid 는 로그용 |
| fd 전달 | `sendmsg` + `SCM_RIGHTS`, 데이터 1바이트 필수. 받을 때 `MSG_CMSG_CLOEXEC` |
| 받은 fd 개수 | `CMSG_SPACE(sizeof(int))` 는 패딩 때문에 **fd 2개**를 담는다 → `MSG_CTRUNC` 만 믿지 말고 직접 센다. 에러 경로에서 모두 닫는다 |

```diff
- strncpy(a.sun_path, path, sizeof a.sun_path); unlink(path); bind(fd, ...); chmod(path, 0600);
+ if (strlen(path) >= sizeof a.sun_path) return -ENAMETOOLONG;
+ lstat → 소켓이 아니면 -EEXIST → connect 로 두드려 보고 ECONNREFUSED 일 때만 unlink
+ old = umask(0177); bind(...); umask(old);
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| 경로가 120글자 | 잘린 경로에 bind/connect → 다른 소켓에 붙음 | `strncpy` 로 잘라 넣었다 |
| 설정 실수로 `path` 가 일반 파일 | 서버가 시작하면서 **그 파일을 지운다** | `unlink` 부터 호출했다 |
| 서버가 이미 떠 있는데 한 번 더 기동 | 첫 서버의 소켓을 지워 쫓아낸다 | 두드려 보지 않았다 |
| `bind` 후 `chmod` | 그 사이에 다른 계정이 접속 | 권한이 만들어진 뒤에 좁혀졌다 |
| 상대가 fd 를 2개 보냄 | 첫 번째만 쓰고 두 번째는 새어 나감 | 개수를 `MSG_CTRUNC` 로만 판단했다 |
| 받는 쪽이 먼저 닫음 | 서버가 `SIGPIPE` 로 죽음 | `MSG_NOSIGNAL` 이 없다 |

## 3. 주의해야 할 점

1. **`umask` 는 프로세스 전체의 값이다**
	- 스레드가 있으면 그 순간 다른 스레드가 만드는 파일의 권한도 바뀐다. 대안: 권한이 좁은 부모 디렉터리 안에 소켓을 만든다
1. **pid 를 오래 믿지 말 것**
	- 연결 시점의 값이다. 상대가 죽고 pid 가 재사용되면 다른 프로세스다
1. **파일 권한만으로는 부족한 경우가 있다**
	- 그룹으로 열어 둔 소켓, root 가 연 소켓. 마지막 방어선이 연결마다 하는 uid 검사다
1. **스트림 소켓도 바이트 스트림이다**
	- 메시지 경계는 직접 만든다 ([P115](개발%20%28CS%29/언어/C언어/실습/개념%20드릴/[P]%20P115.%20파이프%20프레이밍%20—%20바이트%20스트림에%20메시지%20경계%20만들기.md)). `SOCK_SEQPACKET` 이면 보존된다

## 4. 변형 (부록)

### 변형 B — 추상 네임스페이스 (`sun_path[0] == '\0'`)

- 파일 시스템에 흔적이 남지 않는다. 대신 권한(0600)이 없으니 `SO_PEERCRED` 가 유일한 방어선이다

### 변형 C — `systemd` 소켓 활성화

- 이미 열린 listen 소켓을 `LISTEN_FDS` 환경변수로 넘겨받는다. 위의 "남은 파일 처리"가 필요 없어진다
