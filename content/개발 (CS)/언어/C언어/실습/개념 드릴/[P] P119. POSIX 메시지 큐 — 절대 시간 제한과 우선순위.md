## 📌 한눈에 보기

| 항목 | 내용 |
|---|---|
| 상황 | 이름이 있는 큐에 우선순위를 붙여 보내고, 시간 제한을 두고 받는다 |
| 치환 규칙 | `now + timeout` 으로 **절대 시각**을 한 번 계산 / 받는 버퍼 ≥ `mq_msgsize` / 반환값 0 도 정상 |
| 장애 예 | `{.tv_sec = 5}` 를 넘기면 "1970-01-01 00:00:05" 라 **곧바로** `ETIMEDOUT` |
| 원인 | `mq_timedsend`/`mq_timedreceive` 는 절대 시간(`CLOCK_REALTIME`)을 받는다 |
| 실습 문제 | [P119](https://github.com/sweetpark/c-playgound/tree/main/drill/P119_posix_mq) |

## 1. 이론 요약

| | System V (P105) | POSIX (P119) |
|---|---|---|
| 찾는 법 | 정수 key (`ftok`) | 이름 `"/xxx"` (`/` 로 시작, 그 뒤 `/` 없음, ≤ 255) |
| 고르기 | `msgtyp` 로 종류를 골라 받기 | **항상 가장 높은 우선순위**, 같으면 먼저 온 것 |
| 시간 제한 | 없음 (`IPC_NOWAIT` 만) | `mq_timedsend/receive` — **절대 시간** |
| 알림 | 없음 | `mq_notify` (시그널/스레드, **한 번만** 동작) |
| 받는 버퍼 | 메시지 길이만큼 | **`mq_msgsize` 이상** (작으면 메시지가 짧아도 `EMSGSIZE`, 메시지는 큐에 남음) |
| 길이 0 | — | 정상 메시지 (반환값 0 은 에러가 아니다) |
| 이식성 | macOS 도 있음 | 리눅스 (macOS 없음) |

```diff
- ts.tv_sec = 5;                               mq_timedreceive(q, buf, n, &p, &ts);   /* 상대 값 → 이미 지난 시각 */
+ clock_gettime(CLOCK_REALTIME, &ts); ts.tv_sec += 5;  mq_timedreceive(q, buf, n, &p, &ts);
- char buf[8]; mq_receive(q, buf, sizeof buf, &p);                                     /* mq_msgsize 가 16 이면 항상 EMSGSIZE */
+ char buf[msgsize]; mq_receive(q, buf, msgsize, &p);
- if (mq_receive(...) <= 0) break;                                                     /* 길이 0 메시지를 에러로 처리 */
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| 상대 시간을 `ts` 에 그대로 | 항상 즉시 `ETIMEDOUT` | 절대 시각으로 해석된다 (개발 PC 에서 "비면 바로 끝난다"로 보여 알아채지만, 데이터가 곧 온다고 가정한 코드는 메시지를 놓친다) |
| `EINTR` 뒤 `now + timeout` 을 다시 계산 | 시그널이 잦으면 영원히 안 끝남 | 마감을 한 번만 계산해야 한다 (P117 과 같다) |
| 3바이트 메시지를 `char buf[8]` 로 받음 | `EMSGSIZE` — 메시지가 남아서 **다음 호출도 같은 에러** | 버퍼는 `mq_msgsize` 이상 |
| 길이 0 메시지를 "신호"로 보냄 | 받는 쪽이 에러로 처리 | `<= 0` 검사 (파이프의 EOF 0 과 다르다) |
| 우선순위 높은 메시지가 계속 들어옴 | 낮은 것이 영원히 안 나옴 | 기아(starvation) |
| `mq_unlink` 를 안 함 | 프로세스가 끝나도 이름이 남아 다음 기동의 `O_EXCL` 이 `EEXIST` | System V 처럼 커널 객체다 |

## 3. 주의해야 할 점

1. **System V 와 POSIX 를 오가면 시간 제한 단위가 뒤집힌다**
	- `semtimedop`(P118)는 **상대**, `mq_timed*` 는 **절대**. 함수 이름이 비슷해서 한 번은 틀린다
1. **크기 제한**
	- `/proc/sys/fs/mqueue/msg_max`(기본 10), `msgsize_max`(기본 8192), 사용자별 `RLIMIT_MSGQUEUE`. 넘으면 `mq_open` 이 `EINVAL`/`EMFILE`
1. **우선순위는 "고르기"가 아니다**
	- 특정 종류만 받고 싶으면 큐를 종류별로 나눈다
1. **`unlink` 뒤에도 열린 번호는 계속 쓸 수 있다**
	- P106 의 `IPC_RMID` 예약과 같다. 이름과 객체는 별개

## 4. 변형 (부록)

### 변형 B — `mq_notify` 로 알림 받기

- 큐가 비어 있다가 메시지가 들어오는 **순간 한 번**만 알림이 온다. 알림을 받은 뒤 다시 등록하지 않으면 이후 메시지는 알림 없이 쌓인다. 등록 → 비울 때까지 읽기 → 재등록 순서

### 변형 C — 큐를 `poll` 에 넣기

- Linux 에서 `mqd_t` 는 파일 디스크립터라서 `poll`/`epoll` 에 넣을 수 있다 (P117 의 eventfd 와 같은 이벤트 루프에서)
