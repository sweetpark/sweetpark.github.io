## 1. 이론 요약

```
세마포어 집합 (2개짜리)        sem0 = free (남은 칸)     sem1 = used (쓰는 중)      free + used == N

acquire :  semop( {sem0, -1, SEM_UNDO}, {sem1, +1, SEM_UNDO} )     ← 한 번의 호출, 전부 성공 또는 전부 실패
release :  semop( {sem1, -1, SEM_UNDO|IPC_NOWAIT}, {sem0, +1, SEM_UNDO} )
              └ used 가 0 이면 EAGAIN → 두 연산 모두 취소 → "잡은 적 없다" (-EPERM)
프로세스가 죽으면: 커널이 그 프로세스의 undo 기록을 거꾸로 적용 → 쥐고 있던 칸이 돌아온다
```

| 항목 | 규칙 |
| :--- | :--- |
| `SEM_UNDO` | 이 `semop` 이 바꾼 양을 프로세스별로 기록해 두었다가 **종료 시 되돌린다.** acquire·release **둘 다**에 준다 (한쪽만 주면 정상 종료 때 이중으로 돌아온다) |
| 한 배열로 | free/used 를 두 번에 나누면 그 사이에 죽거나 끼어들어 `free + used != N` |
| 초기화 경쟁 | `semget(IPC_CREAT)` 과 `semctl(SETVAL)` 은 원자적이지 않다. 만든 쪽이 값을 다 넣은 **뒤에** `semop` 을 한 번 해서 `sem_otime` 을 채우고, 여는 쪽은 `sem_otime != 0` 이 될 때까지 기다린다 (Stevens 의 고전 해법, P112 의 `ready` 와 같은 생각) |
| `IPC_EXCL` | 없으면 이미 있는 집합에 `SETALL` 해서 쓰고 있는 프로세스의 값을 덮어쓴다 |
| 시간 제한 | `semtimedop` 은 **상대** 시간 (POSIX `mq_timedsend` 는 절대). 마감은 한 번만 계산, `EINTR` 은 남은 시간으로 이어서 |
| 정리 | 집합은 프로세스가 끝나도 `ipcs -s` 에 남는다. `IPC_RMID` 는 만든 쪽 책임 |

```diff
- semop(id, &{0, -1, 0}, 1);                       /* 죽으면 칸이 영원히 사라진다 */
+ struct sembuf ops[2] = {{0, -1, SEM_UNDO}, {1, +1, SEM_UNDO}};  semop(id, ops, 2);
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| 칸을 쥔 채 `kill -9` | free 가 영구히 줄어든다 | `SEM_UNDO` 가 없다 |
| acquire 에만 `SEM_UNDO` | 정상 종료 때 칸이 **N 보다 늘어난다** | release 는 기록에 안 남아서 acquire 의 되돌림만 적용된다 |
| 잡지 않고 `release` 두 번 | 동시에 N+1 개가 들어간다 | 세마포어는 N 을 모른다 → used 로 막는다 |
| `fork` 한 자식이 끝남 | (착각) 부모가 잡은 칸이 돌아온다 | undo 기록은 **상속되지 않는다.** 칸은 잡은 프로세스에 묶여 있다 |
| 만드는 중에 여는 쪽이 옴 | 값이 0 이라 영원히 기다림 | 초기화 완료를 표시하지 않았다 |
| 두 번째 기동이 `semget(IPC_CREAT)` | 쓰는 중인 값이 덮어써진다 | `IPC_EXCL` 이 없다 |

## 3. 주의해야 할 점

1. **acquire 한 프로세스와 release 하는 프로세스가 다르면**
	- 각자의 undo 기록이 반대 방향으로 쌓여서, 둘 중 하나가 죽으면 칸 수가 어긋난다. "내가 잡은 칸은 내가 돌려준다"가 전제다
1. **카운터만 돌아온다**
	- 칸 안의 데이터가 반쯤 바뀐 채 죽었는지는 세마포어가 모른다. P113 의 undo 로그 같은 별도 장치가 필요하다
1. **`exec` 는 undo 기록을 유지하고 `fork` 는 비운다**
1. **P113 과의 비교**

| | robust 뮤텍스 (P113) | 세마포어 + SEM_UNDO (P118) |
|---|---|---|
| 개수 | 1 (상호 배제) | N |
| 죽은 소유자 | `EOWNERDEAD` 로 알려 줄 뿐, 복구는 내 몫 | 카운터는 **커널이 되돌림** |
| 데이터 | undo 로그로 직접 복구 | 해결 안 됨 |
