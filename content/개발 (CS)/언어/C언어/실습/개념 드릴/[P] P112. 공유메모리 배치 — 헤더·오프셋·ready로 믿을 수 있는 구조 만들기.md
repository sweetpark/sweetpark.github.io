## 1. 이론 요약

```
영역 시작(base)
┌──────────────── 32B ────────────────┐
│ magic │ version │ size │ ready      │  ← 헤더. ready 는 맨 마지막에 쓴다
│ count │ head_off│ tail_off│ free_off│
├─────────────────────────────────────┤
│ node: next_off │ len │ "alpha\0" pad│  ← 8의 배수 크기·위치
│ node: next_off │ len │ "beta\0"  pad│
│ ...                  (free_off →)   │
└─────────────────────────────────────┘
next_off = base 로부터의 거리. 프로세스 A 는 base=0x7f..a000, B 는 0x7f..c000 이어도 같은 값
```

| 항목 | 규칙 |
| :--- | :--- |
| 잇는 값 | 포인터가 아니라 **base 기준 오프셋**. 읽을 때 `(char *)base + off` |
| `ready` | 헤더를 다 채운 뒤 **release** 로 쓴다. 읽는 쪽은 **acquire** 로 먼저 읽는다 |
| `magic == 0` | "아직 아무도 안 썼다" → 기다린다 (`E_NOTREADY`) |
| `magic` 불일치 | "남의 데이터" → 기다려도 소용없다 (`E_MAGIC`) |
| `version`, `size` | 배치가 다른 옛 세그먼트에 붙는 사고를 막는다 |
| 읽기 | 오프셋·길이는 **남이 쓴 값**. 정렬·하한·상한·널 종료를 모두 확인하고서야 포인터로 바꾼다 |
| 쓰기 | `off + need > size` 는 넘칠 수 있다 → `size - off < need` |

```diff
- typedef struct node { struct node *next; ... } node_t;     /* 쓴 프로세스의 주소를 저장 */
- for (n = hdr->head; n; n = n->next) ...
+ typedef struct { uint32_t next_off; uint32_t len; char s[]; } lay_node_t;
+ off = h->head_off;
+ while (off_is_valid(h, off)) { n = (lay_node_t *)((char *)base + off); ...; off = n->next_off; }
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
| :--- | :--- | :--- |
| 한 프로세스가 같은 세그먼트를 두 번 `shmat` 하고, 쓴 쪽 매핑을 `shmdt` | 읽는 쪽이 `SIGSEGV` | 노드의 `next` 가 떼어낸 매핑의 주소를 가리킨다. (매핑이 둘 다 살아 있으면 **우연히 맞아서** 시험을 통과한다) |
| 만든 쪽이 초기화 중일 때 붙음 | 반쯤 쓰인 헤더를 읽음 | `ready` 가 없거나 먼저 쓰였다 |
| 영역이 0 으로 비어 있음 vs 0xAB 로 채워진 쓰레기 | 둘 다 "초기화 안 됨" 으로 뭉침 | 앞은 기다리면 되고 뒤는 세그먼트를 잘못 잡은 것 |
| 누군가 `next_off` 를 `0x7FFFFF00` 으로 덮음 | 읽는 쪽이 영역 밖을 읽어 죽음 | 오프셋을 그대로 믿었다 |
| `len` 을 100000 으로 덮음 / 널 종료가 사라짐 | `strlen`/`printf` 가 영역을 넘어 읽음 | 길이·널을 확인하지 않았다 |

## 3. 주의해야 할 점

1. **한 프로세스 안에서만 시험하면 포인터 방식이 "통과"한다**
	- `shmat` 을 두 번 하고 두 매핑을 모두 유지하면, 한쪽에서 쓴 포인터가 다른 쪽에서도 유효한 주소다
	- 진짜 시험은 **다른 프로세스** 또는 **쓴 쪽 매핑을 뗀 뒤** 읽는 것이다 (P112 `test.c` `[7]`)
1. **`ready` 는 값이 아니라 "순서"의 문제다**
	- `ready = 1` 을 먼저 쓰거나, 쓰더라도 순서 보장 없이 쓰면 컴파일러·CPU 가 순서를 바꿀 수 있다
	- `__atomic_store_n(..., __ATOMIC_RELEASE)` / `__atomic_load_n(..., __ATOMIC_ACQUIRE)`
1. **`count` 도 같은 규칙이다**
	- 노드를 다 쓴 뒤 `count` 를 올려야 읽는 쪽이 반쯤 쓰인 노드를 보지 않는다
1. **정렬**
	- 노드를 4의 배수가 아닌 주소에 두고 `uint32_t` 로 읽으면 UB (x86 은 조용히 돌지만 UBSan 이 잡는다)
1. **쓰는 프로세스가 둘이면 `lay_push` 는 경쟁한다**
	- 이 문제는 쓰는 쪽이 하나라고 가정한다. 여럿이면 → [P113](개발%20%28CS%29/언어/C언어/실습/개념%20드릴/[P]%20P113.%20공유메모리%20락%20—%20락을%20쥔%20채%20죽은%20프로세스%20복구하기.md)

## 4. 변형 (부록)

### 변형 B — 노드 삭제와 free list

- 오프셋 방식 연결 리스트에서 노드를 지우고, 지운 자리를 `free list` (역시 오프셋)로 재사용한다
- 지운 자리의 `next_off` 가 옛 값 그대로 남아 있으면 안 된다

### 변형 C — 세그먼트 안에 해시 테이블

- 버킷 배열을 오프셋으로 가리키고, 키 문자열도 세그먼트 안에 둔다 (`const char *` 를 저장하면 안 된다)
