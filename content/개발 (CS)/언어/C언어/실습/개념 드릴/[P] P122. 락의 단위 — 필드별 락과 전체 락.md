## 📌 한눈에 보기

| 항목 | 내용 |
|---|---|
| 상황 | 구조체 필드 a, b 가 대부분 독립으로 갱신되지만 가끔 함께 읽혀야 한다 |
| 치환 규칙 | 독립 갱신은 **자기 필드의 락만** / 함께 다루는 연산(`move`·`snapshot`·`reset`)은 **모든 락을 고정 순서로** |
| 장애 예 | 락 하나로 다 잠가서 b 갱신이 a 의 느린 처리를 기다린다 / 필드별 락인데 `snapshot` 이 합이 안 맞는 값을 읽는다 / 방향별로 락 순서를 바꿔 교착 |

## 1. 이론 요약

| | 굵은 락 (구조체당 1개) | 가는 락 (필드당 1개) |
|---|---|---|
| 코드 | 단순, 교착 걱정 적음 | 락이 늘어나 관리 필요 |
| 병렬성 | 서로 상관없는 필드도 줄을 선다 | 다른 필드는 동시에 |
| 전체 일관성 | 한 번 잠그면 끝 | **모든 락을 잡아야** 한다 |
| 언제 | 필드를 함께 읽고 쓰는 일이 대부분 / 경합이 안 측정됨 | 필드가 대부분 독립이고 경합이 **측정됨** |

```
add_a  ── mu_a ──▶ a += d                 (mu_b 는 건드리지 않는다)
add_b  ── mu_b ──▶ b += d                 (mu_a 는 건드리지 않는다)
move / snapshot / reset ── mu_a → mu_b ──▶ 둘 다  (항상 이 순서. 방향·호출 함수와 무관)
```

| 항목 | 규칙 |
| :--- | :--- |
| 독립 갱신 | 자기 필드의 락만. `mu_a` 가 오래 잡혀 있어도 `add_b` 는 안 기다린다 |
| 같은 필드 | 서로 기다린다 (락이 없으면 갱신이 유실) |
| 함께 다루기 | 두 락을 모두, **전역 고정 순서**(`mu_a → mu_b`), 푸는 것은 역순 |
| 방향별 순서 금지 | `move(+)` 는 a→b, `move(-)` 는 b→a 순으로 잡으면 반대 방향 둘이 서로를 기다린다 (P025 의 교착) |
| 스냅샷 | 락 하나씩 따로 잡고 읽으면 서로 다른 시점의 값. 두 락을 **동시에 쥔 구간**에서 읽는다 |
| 진행 중인 단독 갱신 | `snapshot` 은 그 필드의 락을 잡아야 하므로 **끝나기를 기다린다** |

```diff
- lock(a); x = s->a; unlock(a);  lock(b); y = s->b; unlock(b);        /* (x, y) 는 다른 시점 */
+ lock(a); lock(b); x = s->a; y = s->b; unlock(b); unlock(a);          /* 고정 순서 */
- if (d > 0) { lock(a); lock(b); } else { lock(b); lock(a); }          /* 방향별 순서 → 교착 */
+ lock_both(s);                                                        /* 항상 a → b */
```

## 2. 재현 — 어디서 뚫리나

| 상황 | 틀린 코드의 결과 | 이유 |
|---|---|---|
| `add_b` 가 두 락을 모두 잡음 | `mu_a` 가 400ms 잡혀 있으면 `add_b` 도 400ms | 가는 락의 이점이 사라진다 (시험 `[2]` < 80ms) |
| `add_a` 가 락을 안 잡음 | 8×2만 번 갱신이 유실 (시험 `[5]`) | `+=` 는 읽기-더하기-쓰기 3단계 |
| `snapshot` 이 락 없이 읽음 | 진행 중인 갱신의 중간 값 (시험 `[3]` 이 대기 시간을 잰다) | |
| `snapshot` 이 락을 하나씩 | `a + b != 1000` (시험 `[4]` 가 3만 번 확인) | 두 읽기 사이에 `move` |
| 방향별 락 순서 | `move(+)` 와 `move(-)` 두 스레드가 교착 → `TIMEOUT` | 서로 다른 순서 |

## 3. 주의해야 할 점

1. **처음부터 쪼개지 않는다** — 굵은 락이 정확하고 단순하다. 병목이 **측정된 뒤에** 쪼갠다
1. **쪼개면 "전체를 보는 함수"가 새 숙제가 된다** — 통계 합계, 스냅샷, 리셋. 모두 같은 순서로 모든 락을 잡는다
1. **락이 많으면 주소 순으로 정렬해서 잡는다** — 구조체 안의 락이 둘이 아니라 N 개(버킷)일 때의 일반 규칙
1. **단독 갱신을 원자 변수로 바꾸면** 락을 없앨 수 있지만, `snapshot` 의 일관성은 별도로 따져야 한다 (원자 변수 두 개를 읽는 두 번의 읽기 사이에도 `move` 가 끼어든다)
1. **샤딩**: 항목이 키로 갈리면 버킷마다 락을 두고 전체 연산은 모든 버킷을 순서대로 잡는다 (해시 샤딩)

## 4. 변형 (부록)

### 변형 B — 락 N 개 (해시 버킷)

- 버킷 배열 + 버킷별 락. `count_all()` 은 모든 버킷을 인덱스 순서로 잡는다

### 변형 C — `trylock` 으로 순서 위반 회피

- 두 번째 락을 `trylock` 으로 시도하고 실패하면 첫 락도 풀고 다시 (livelock 주의 → 백오프)
