# 개수 필드 + 포인터의 포인터 — 동적 문자열 배열 만들고 해제하기

> [!NOTE]
> 몇 개가 들어올지 컴파일 타임에 알 수 없는 문자열 목록을 구조체에 담을 때 쓰는 "개수 필드 + `char **`" 조합과, 이중으로 할당된 메모리를 순서대로 해제하는 방법을 정리한다.

## 0. 왜 필요한가

설정 파일 항목이나 파싱 결과처럼 "문자열이 몇 개 들어올지 미리 알 수 없는" 목록을 구조체 필드로 표현해야 할 때가 있다. 배열 크기를 컴파일 타임에 못 박을 수 없으므로, 실무에서는 거의 항상 **개수를 나타내는 필드**와 **포인터의 포인터**를 짝지어 쓴다.

```c
typedef struct {
    int    count;   /* list에 실제로 담긴 문자열 개수 */
    char **list;    /* list[0], list[1], ..., list[count-1] 각각이 문자열 하나 */
} str_list_t;
```

## 1. `char **`가 가리키는 것 — 포인터의 포인터 읽는 법

`char *`가 문자열 하나(문자들이 늘어선 메모리의 시작 주소)를 가리킨다면, `char **`는 **그런 포인터들이 늘어선 배열의 시작 주소**를 가리킨다.

```c
char **list;
/* list        : char* 들이 늘어선 배열을 가리키는 포인터 */
/* list[i]     : i번째 문자열의 시작 주소 (타입은 char*) */
/* list[i][j]  : i번째 문자열의 j번째 문자 (타입은 char) */
```

한 단계씩 벗겨낸다고 생각하면 된다 — `list`에 `[i]`를 붙이면 포인터 하나(`char *`)가 나오고, 거기에 다시 `[j]`를 붙이면 문자 하나(`char`)가 나온다.

> [!TIP]
> **왜 정수(`int`) 가변 배열은 `int *`인데, 문자열은 `char **`인가?**
> C언어에서 가변 동적 배열의 포인터 차수는 항상 **`원소 타입(T) *`**입니다.
> - **`int` 배열**: 원소 1개가 `int`이므로, 동적 배열은 **`int *` (단일 포인터)**입니다. `malloc` 1번, `free` 1번으로 끝나며 이중 포인터(`int **`)를 쓸 이유가 없습니다.
> - **`string` 배열**: C언어에는 `string` 기본형이 없고 원소 1개가 이미 `char *`입니다. 따라서 동적 배열은 `(char *) *` = **`char **` (이중 포인터)**가 됩니다. "포인터들의 배열"과 "각 문자열 메모리"를 2단계로 할당/해제해야 하는 이유가 바로 여기에 있습니다.

## 2. 2단계 할당 — "포인터를 담을 배열"과 "문자열 자체"는 별개의 메모리다

```c
#include <stdlib.h>
#include <string.h>

str_list_t *make_str_list(int count)
{
    str_list_t *sl;
    int i;

    sl = malloc(sizeof(str_list_t));
    if (sl == NULL) {
        return NULL;
    }

    sl->list = malloc(sizeof(char *) * count);   /* 1단계: 포인터 count개를 담을 배열 */
    if (sl->list == NULL) {
        free(sl);
        return NULL;
    }

    sl->count = count;
    for (i = 0; i < count; i++) {
        sl->list[i] = NULL;   /* 아직 채우기 전 — 실패 시 안전하게 정리하기 위한 초기화 */
    }

    return sl;
}

int str_list_set(str_list_t *sl, int idx, const char *value)
{
    if (idx < 0 || idx >= sl->count) {
        return -1;
    }
    sl->list[idx] = strdup(value);   /* 2단계: 문자열 자체를 담을 메모리 */
    return (sl->list[idx] != NULL) ? 0 : -1;
}
```

`sl->list`(포인터들을 담는 배열)와 `sl->list[i]`(각 칸이 실제로 가리키는 문자열)는 **서로 다른 `malloc` 호출로 만들어진, 완전히 별개의 메모리 블록**이다. 이 둘을 하나로 착각하는 게 이 패턴에서 나는 사고의 대부분이다.

## 3. 해제는 반드시 역순 — 원소 먼저, 배열은 그다음

```c
void free_str_list(str_list_t *sl)
{
    int i;

    if (sl == NULL) {
        return;
    }

    for (i = 0; i < sl->count; i++) {
        free(sl->list[i]);   /* 각 문자열을 먼저 해제 */
    }
    free(sl->list);          /* 포인터 배열 자체를 그다음 해제 */
    free(sl);                /* 마지막으로 구조체 자체 해제 */
}
```

순서를 바꿔서 `free(sl->list)`를 먼저 부르면, 그 배열 안에 담겨 있던 각 문자열의 주소를 더 이상 알아낼 방법이 없어진다 — 그 문자열들은 영원히 해제할 수 없는 메모리 누수로 남는다. 만든 순서(구조체 → 배열 → 각 문자열)의 **정확히 역순**(각 문자열 → 배열 → 구조체)으로 해제해야 한다는 원칙은 [실무 C 코드 관례와 UB 함정 정리]([C]%20실무%20C%20코드%20관례와%20UB%20함정%20정리.md)의 A14(생성 역순 정리)와 정확히 같은 이유다.

## 4. 자주 하는 실수

- **`sizeof(char *)`를 `sizeof(char)`로 잘못 쓰기** — `malloc(sizeof(char) * count)`는 문자 `count`개(포인터가 아니라 겨우 `count`바이트)만큼만 할당한다. 포인터 배열이 필요한 자리에 이렇게 쓰면 할당한 크기보다 훨씬 큰 메모리를 쓴 것처럼 접근하게 되어 배열 경계를 한참 벗어난다.
- **원소를 채우기 전에 초기화를 안 해서, 일부만 채워진 상태의 배열을 잘못 정리하기** — 2번 예제처럼 배열을 만들자마자 각 칸을 `NULL`로 채워두면, 중간에 실패해서 일부 칸만 `strdup`된 상태라도 정리 루프가 `NULL`인 칸은 안전하게 건너뛴다(`free(NULL)`은 표준상 아무 일도 안 하는 안전한 호출이다). 이 초기화를 빼먹으면 아직 안 채워진 칸에 남아있는 쓰레기 값을 문자열 포인터인 줄 알고 `free`하다가 크래시가 난다.
- **`list[i]`(문자열 하나)와 `list`(배열 전체)를 헷갈려서 원소별 해제를 빼먹기** — `free(sl->list)`만 부르고 3번의 반복 해제 루프를 생략하면, 배열 껍데기만 없어지고 그 안에 있던 문자열들은 그대로 누수된다.
- **배열 크기를 늘릴 때 `realloc`만 하고 새로 늘어난 칸을 초기화하지 않기** — `sl->list = realloc(sl->list, sizeof(char *) * new_count);` 이후 기존 칸들의 내용은 유지되지만, 새로 늘어난 칸들은 쓰레기 값을 담고 있다. 늘어난 구간을 `NULL`로 채우는 코드를 꼭 같이 넣어야, 나중에 그 칸을 실수로 `free`하거나 참조했을 때 안전하다.
