# Part 1. 입력데이터 검증 및 표현 _index

> 58개 보안약점 중 **19개 — 가장 큰 유형**. 입력값 검증 누락 또는 부적절한 검증, 데이터의 잘못된 형식지정으로 발생한다.
> 출처: 「전자정부 SW 개발·운영자를 위한 C 시큐어코딩 가이드」(3판) — [시큐어코딩가이드 목록](개발%20%28CS%29/언어/C언어/시큐어코딩가이드/시큐어코딩가이드%20목록.md) 참고

## 이 Part를 관통하는 질문

> **"이 데이터는 어디에서 왔고, 나는 그것을 왜 믿고 있는가?"** — 신뢰 경계(Trust Boundary)

| 외부 입력 (신뢰 불가) | 내부 확정값 (신뢰 가능) |
| :--- | :--- |
| 소켓·네트워크 수신 데이터 · 명령행 인자 `argv[]` · 환경변수 `getenv()` · 설정/데이터 파일 · DB 조회 결과 · IPC·공유메모리·시그널 · 사용자가 지정한 파일 경로 | 코드 안의 상수·열거형 · 컴파일 타임 배열 크기 · 서버 세션 인증 상태 · 화이트리스트 통과값 · 검증 함수를 거친 정규화된 값 |

19개 전부가 "왼쪽 칸의 값이 검증 없이 오른쪽 칸의 자리(질의문·경로·크기·인덱스·권한 판단)로 넘어갈 때" 생긴다. 아래 표를 볼 때마다 **어디서 왔고 → 어디로 흘러가는지**를 먼저 찾는다.

## 각 계열 안의 표준 골격

계열 파일 안의 항목은 전부 같은 순서로 적혀 있다. 처음 볼 때는 정독하고, 두 번째부터는 원하는 절만 골라 본다.

```text
{번호}. {이름} `CWE-xxx`
  ├─ 신뢰 경계  : 외부 입력 ______ → 검증 없이 → 위험한 자리 ______
  ├─ ⚠️ 한줄 경고 (그대로 암기할 문장)
  ├─ 공격 시나리오
  ├─ ❌ Bad 코드
  ├─ ✅ Good 코드
  └─ 치환 규칙   : Bad → Good으로 바꾸는 동작 한 줄
```

## 체화 루틴 — 이 Part로 반복 연습하기

19개를 한 번에 외우려 하지 않는다. **3회차 반복**으로 분산한다.

| 회차 | 보는 것 | 하는 일 |
| :--- | :--- | :--- |
| 1회차 (읽기) | 계열 파일 전체 | Bad/Good 코드를 나란히 읽고 **왜 다른지**를 소리 내어 설명해본다 |
| 2회차 (가리기) | 항목 이름 + Bad 코드만 | Good 코드를 안 보고 직접 고쳐 쓴 뒤 비교한다 |
| 3회차 (역방향) | ⚠️ 한줄 경고만 | 경고 문장만 보고 어떤 항목·어떤 Bad 코드였는지 떠올린다 |

- **금지 함수 스캐빈저 헌트**: 실제로 다루는(또는 예제) 코드베이스에서 `strcpy`·`sprintf`·`system`·`sscanf("%s")` 를 검색해, 이 표의 어느 항목에 해당하는지 짝지어본다.
- **한 줄 경고 암송**: 19개의 ⚠️ 문장만 뽑아 카드로 만들어 순서를 섞어 반복한다 — 문장 하나가 CWE 하나와 방어책 하나를 동시에 압축하고 있다.
- 각 계열 파일 맨 아래 **미니 체크리스트**를 코드 리뷰할 때 그대로 대조한다.
