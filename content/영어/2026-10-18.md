# 2026-10-18 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The incoming request packet shall be forwarded to the designated Pod with the exception of administrative control traffic.

**A.** 뜻: 관리용 제어 트래픽을 제외하고, 들어오는 요청 패킷은 지정된 포드로 전달되어야 한다.

구문 패턴: with the exception of ~ (~를 제외하고는 / ~ 외에는)
- 스펙 문서에서 예외 규정이나 제약 사항을 정의할 때 매우 자주 쓰이는 정형 표현입니다.
- 비슷한 표현으로 'except for'가 있으나, 표준/스펙 문서에서는 'with the exception of'가 훨씬 더 격식 있고 명확한 표현으로 선호됩니다.
- 'shall'이 쓰였으므로 해당 전달 동작은 시스템이 반드시 준수해야 하는 강제적 요구사항(Mandatory Requirement)입니다.

**Q.** Upon authentication failure, the signaling message shall be forwarded to the security gateway for logging.

**A.** 뜻: 인증 실패 시, 신호(Signaling) 메시지는 로깅을 위해 보안 게이트웨이로 전달되어야 한다.

구문 패턴: shall be forwarded to ~ (~로 전달되어야 한다 / 포워딩되어야 한다)
- 특정 조건이나 이벤트 발생 시 데이터 패킷, 메시지, 요청 등을 특정 컴포넌트나 엔드포인트로 전달해야 함을 명시할 때 사용합니다.
- 'shall'은 강제 규정이므로 구현체는 해당 메시지를 다른 곳으로 드롭하거나 무시하지 않고 지정된 destination으로 반드시 전송해야 합니다.

**Q.** In the event that the primary node becomes unreachable, the cluster orchestrator SHOULD initiate failover within 3 seconds.

**A.** 뜻: 주 노드에 도달할 수 없는 상황이 발생하는 경우, 클러스터 오케스트레이터는 3초 이내에 장애 조치(failover)를 개시해야 한다(권장).

구문 패턴: In the event that + 문장 (~하는 경우에 / ~ 상황 발생 시)
- 조건절 'If'보다 더 격식체로, 장애 상황이나 특정 사건 발생 조건을 명시할 때 기술 문서에서 흔히 쓰입니다.
- 문맥 비교: 'SHOULD'가 사용되었으므로 이 동작은 강력히 권장되는 사항(Recommendation)입니다. 시스템 환경이나 제약에 따라 이행하지 않을 정당한 이유가 있다면 준수하지 않을 수 있으나, 가급적 구현하는 것이 좋습니다.

**Q.** Health checks shall be performed by the kubelet at regular intervals specified in the pod specification.

**A.** 뜻: 헬스 체크는 포드 명세서에 지정된 정기적인 간격으로 kubelet에 의해 수행되어야 한다.

구문 패턴: shall be performed by ~ (~에 의해 수행되어야 한다)
- 주체가 주어지지 않고 동작이나 절차가 강조될 때 피동형 구조('shall be performed by [주체]')로 작성하여 특정 주체의 책무를 명확히 규정합니다.
- 수동태 형태의 강제 조항으로, 지정된 모듈이나 프로세스(여기서는 kubelet)가 해당 작업을 담당함을 명시합니다.

## GitHub 소통 문구

**Q.** PR 작성 시 Option A 방식으로 구현했는데, 리뷰어에게 더 나은 대안이나 의견이 있는지 부드럽게 물어보고 싶을 때

**A.** 영어 표현:
"I went with Option A for this implementation, but I'm open to alternative suggestions if you think another approach works better."

유사 표현:
- "I chose Option A here, but let me know if you prefer Option B."
- "Open to feedback if there's a cleaner way to handle this."

사용 상황:
자신이 선택한 구현 방식의 이유를 밝히면서도, 더 나은 구조나 대안이 있다면 기꺼이 수용하겠다는 개방적인 자세를 보여줄 때 유용합니다.

**Q.** 요구사항대로 정상 동작은 하지만, 코드가 다소 지나치게 복잡하게 작성된 것 같아 리뷰어에게 더 간결한 방식으로 바꿀지 의견을 묻고 싶을 때

**A.** 영어 표현:
"This works as expected, but I wonder if it might be overly complex. Would you prefer a simpler approach?"

유사 표현:
- "Does this look a bit too heavy? I can simplify it if needed."
- "Functionally it works, but I'm curious if you think we should streamline this logic."

사용 상황:
기능 구현은 완료했으나 가독성이나 유지보수성 관점에서 구조 단순화가 필요할지 리뷰어의 서드파티 시각을 요청할 때 사용합니다.

## 생활영어

**Q.** 대화나 회의 중 다른 주제로 이야기가 새어나갔을 때, '아 아무튼, 원래 하려던 이야기로 돌아가서'라고 말하며 본론으로 되돌아오고 싶을 때

**A.** 영어 표현:
"Anyway, back to my point..." / "Let's get back on track."

뉘앙스 설명:
- 'Anyway, back to my point'는 부연 설명이나 곁가지 이야기를 마친 후 다시 본인의 핵심 주장이나 본론으로 부드럽게 전환할 때 씁니다.
- 'Let's get back on track'은 참석자 전체가 다른 길로 샜을 때 회의를 다시 원래 안건으로 돌려놓기 위해 사용하는 깔끔하고 전문적인 표현입니다.

## 단어

**Q.** resilience

**A.** 뜻: 회복탄력성, 복구력, 시스템의 장애 견딤성

예문:
"We need to improve the system's resilience against sudden traffic spikes and database failovers."
(우리는 갑작스러운 트래픽 폭증과 데이터베이스 장애 조치에 대한 시스템의 회복탄력성을 향상시켜야 합니다.)
