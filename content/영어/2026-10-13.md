# 2026-10-13 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The default timeout value MAY be overridden by specifying a custom duration in the configuration file.

**A.** 기본 타임아웃 값은 설정 파일에 사용자 지정 시간을 지정함으로써 재정의(덮어쓰기)될 수 있다.

- 구문 패턴: `MAY be overridden by [method/value]` (~에 의해 재정의될 수 있다)
- Spec 표현: RFC 2119에서 'MAY'는 선택적(Optional) 동작을 나타내며, 구현체가 이 덮어쓰기 기능을 제공하지 않아도 스펙 준수(Compliance)에 영향을 주지 않음을 의미합니다.

**Q.** Upon detecting an invalid token, the node SHALL refrain from processing subsequent incoming requests.

**A.** 유효하지 않은 토큰을 감지하면, 해당 노드는 이후 들어오는 요청을 처리하는 것을 자제(중단)해야 한다.

- 구문 패턴: `SHALL refrain from -ing` (~하는 것을 자제/금지해야 한다)
- Spec 표현: 'SHALL NOT'과 유사하게 특정 동작이나 절차를 금지 및 제한함을 강조할 때 스펙 문서에서 자주 사용되는 명확한 제약 구문입니다.

**Q.** The maximum number of retry attempts SHALL be bounded by the maxRetries configuration parameter.

**A.** 최대 재시도 횟수는 maxRetries 설정 파라미터에 의해 제한되어야(상한이 정해져야) 한다.

- 구문 패턴: `SHALL be bounded by [parameter/limit]` (~에 의해 상한선이 제한되어야 한다)
- Spec 표현: 시스템 리소스의 무한 소비나 루프 방지를 위해 값의 상한선(Upper bound)을 제약할 때 규격 문서에서 사용하는 정형화된 표현입니다.

**Q.** The Pod name MUST be unique across all namespaces within the same Kubernetes cluster.

**A.** 파드 이름은 동일한 쿠버네티스 클러스터 내의 모든 네임스페이스에 걸쳐 고유해야 한다.

- 구문 패턴: `MUST be unique across [scope]` ([범위] 전체에서 고유해야 한다)
- Spec 표현: RFC 2119의 'MUST'는 절대적인 요구사항(Absolute requirement)을 의미하며, 해당 조건을 만족하지 못하면 시스템 동작 오류나 호환성 파괴가 일어남을 명시합니다.

## GitHub 소통 문구

**Q.** PR 코멘트에서 "리뷰 반영이 끝났으니 커밋들을 하나로 합쳐(Squash) 주실 수 있나요?"라고 요청하고 싶을 때

**A.** Could you please squash your commits before we merge?

- 유사 표현:
  1. Would you mind squashing the commits into a single one?
  2. Please squash your commits once you're done with the changes.
- 사용 상황: 리뷰 지적 사항 반영이 완료된 후 메인 브랜치 머지 전에 커밋 히스토리를 깔끔하게 정리해 달라고 요청할 때 주로 사용하는 정중한 문구입니다.

**Q.** 새로 올라온 이슈나 PR이 이미 기존에 작성된 것과 동일할 때, "이건 이미 보고된 이슈와 중복되는 것 같습니다. #123 이슈를 참고해 주세요."라고 남기고 싶을 때

**A.** This appears to be a duplicate of #123. Please refer to that issue for updates.

- 유사 표현:
  1. This looks like a duplicate of #123.
  2. Closing this as a duplicate of #123.
- 사용 상황: GitHub 이슈나 PR 스레드에서 중복 리포트를 정리하고 기존 스레드로 논의를 모으기 위해 사용하는 표준 안내 문구입니다.

## 생활영어

**Q.** 동료의 설명이나 상황을 들었지만 복잡해서 "무슨 말씀이신지 감이 안 잡혀요 / 머리로 이해가 잘 안 돼요"라고 솔직하게 말하고 싶을 때

**A.** I can't quite wrap my head around this.

- 뉘앙스 설명:
  'wrap one's head around something'은 복잡하거나 이해하기 어려운 개념/상황을 '머리로 받아들이고 이해하다'라는 뜻입니다. 부정형으로 사용하면 복잡한 로직이나 이해하기 힘든 상황이 직관적으로 와닿지 않을 때 부드럽게 표현할 수 있습니다.

## 단어

**Q.** Granular

**A.** 세분화된, 상세한, 입자가 고운

- 예문: We need to implement more granular permission controls for the user management module. (사용자 관리 모듈에 대해 더 세분화된 권한 제어를 구현해야 합니다.)
