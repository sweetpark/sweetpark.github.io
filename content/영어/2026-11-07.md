# 2026-11-07 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** Failure to receive an acknowledgment within the specified timeout period SHALL be considered a critical failure.

**A.** 뜻: 지정된 타임아웃 시간 이내에 응답(ACK)을 수신하지 못하는 경우 심각한 오류로 간주해야 한다.

구문 패턴: `[Condition/Event] + SHALL be considered + [State/Attribute]` (~는 ...로 간주되어야 한다)
- 스펙 문서에서 특정 사건 발생 시 시스템이 해당 상태를 반드시 어떻게 정의하고 다뤄야 하는지 규정할 때 사용하는 필수 규격 표현입니다.
- SHALL(필수 규격) vs MAY(선택적 간주: MAY be considered...)

**Q.** State synchronization SHALL NOT be performed during an active handover procedure.

**A.** 뜻: 활성화된 핸드오버 절차 진행 중에는 상태 동기화를 수행해서는 안 된다.

구문 패턴: `[Action] + SHALL NOT be performed during + [Procedure/State]` (~ 동안 ...을 수행해서는 안 된다)
- 시스템이 특정 상태나 절차(Handover, Maintenance window 등)에 있을 때 금지되는 동작을 명확히 규정합니다.
- SHALL NOT: 절대적 금지사항(Mandatory prohibition). SHOULD NOT(가급적 지양)보다 강력한 준수 강도를 가집니다.

**Q.** A graceful shutdown SHOULD be attempted before forcefully terminating the pod.

**A.** 뜻: 포드를 강제로 종료하기 전에 정상 종료(graceful shutdown)를 시도하는 것이 권장된다.

구문 패턴: `[Action A] + SHOULD be attempted before + [Action B]` (B를 수행하기 전에 A를 먼저 시도해야 한다/권장된다)
- 스펙이나 운영 가이드라인에서 장애 처리나 복구 절차 진행 시 우선 권장되는 상위 수순을 설명할 때 사용합니다.
- SHOULD: 권장 사항(Recommended). 합리적인 사유가 있다면 준수하지 않을 수 있으나 가급적 따라야 함을 의미합니다.

**Q.** The custom resource configuration SHALL be scoped to the namespace in which it is created.

**A.** 뜻: 커스텀 리소스 설정은 해당 리소스가 생성된 네임스페이스 범위로 제한되어야 한다.

구문 패턴: `[Resource] + SHALL be scoped to + [Scope]` (~는 ... 범위로 한정/제한되어야 한다)
- Kubernetes CRD 정의나 기술 스펙 문서에서 리소스의 유효 범위(Namespace scope vs Cluster scope)를 명확하게 정할 때 자주 활용되는 표현입니다.

## GitHub 소통 문구

**Q.** 리뷰어가 놓칠 뻔한 예외 처리나 좋은 개선안을 짚어줬을 때 '좋은 지적이네요! 바로 반영할게요'라고 응답하고 싶을 때

**A.** 표현: Good call on pointing that out! I'll add the validation right away.
(그 부분 짚어주셔서 좋은 지적입니다! 바로 검증 로직 추가할게요.)

유사 표현:
- Great point! I'll update the implementation.
- Good thinking! Thanks for bringing that up.

사용 상황: 상대방의 의견이나 지적이 매우 타당하고 합리적(Good call)일 때 감사를 표하며 코드 수정 의사를 전할 때 사용합니다.

**Q.** 리뷰 피드백 반영 완료 후 리뷰어에게 '피드백 수정 완료되어 다시 검토받을 준비가 되었습니다'라고 말하고 싶을 때

**A.** 표현: Addressed all feedback and pushed the changes. Ready for another pass!
(모든 피드백 반영하여 커밋 올렸습니다. 다시 검토해 주셔도 됩니다!)

유사 표현:
- Applied all requested changes. Open for re-review!
- Pushed the fixes, feel free to take another look.

사용 상황: 코드 리뷰 반영 후 리뷰어에게 재검토(re-review / another pass) 준비가 완료되었음을 알릴 때 매끄럽게 쓰이는 표현입니다.
