# 2026-10-26 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The resource quota limits SHALL be enforced by the API server during request processing.

**A.** 뜻: 요청 처리 과정에서 리소스 쿼터 제한은 API 서버에 의해 반드시 강제되어야 한다.

구문 패턴 설명: 'SHALL be enforced by [component]'는 명세서에서 특정 규칙, 정책, 제약 사항이 어느 시스템 요소에 의해 필수적으로 적용/강제(enforce)되어야 하는지 명시할 때 사용하는 표준 표현입니다.

표준 어조 비교:
- SHALL be enforced by: 강제 적용이 명세상의 필수 의무(Mandatory).
- SHOULD be enforced by: 권장 사항이며 특수한 유즈케이스에서는 예외 허용 가능(Recommended).
- MAY be enforced by: 구현체의 선택 사항(Optional).

**Q.** The allocated identifier SHALL NOT be reused until the corresponding session is explicitly terminated.

**A.** 뜻: 해당 세션이 명시적으로 종료될 때까지 할당된 식별자는 절대로 재사용되어서는 안 된다.

구문 패턴 설명: 'SHALL NOT be reused until [condition]'은 식별자, 포트, 리소스 등의 재사용 금지 기간과 해제 조건을 명확히 설정할 때 사용합니다.

표준 어조 비교:
- SHALL NOT: 절대 불허 및 엄격한 금지(Strict Prohibition).
- SHOULD NOT: 특별한 이유가 없다면 재사용을 지양함(Recommended Against).

**Q.** Frequent polling SHOULD be avoided unless real-time synchronization is strictly required.

**A.** 뜻: 실시간 동기화가 엄격하게 요구되지 않는 한 빈번한 폴링은 피해야 한다.

구문 패턴 설명: 'SHOULD be avoided unless [condition]'은 시스템 성능 부하를 줄이기 위해 특정 동작을 지양하도록 권장하되, 명시된 조건에서만 예외적 허용을 부여할 때 사용됩니다.

표준 어조 비교:
- SHOULD be avoided: 지양 권장 사항.
- SHALL NOT be performed: 명세상 절대 불허되는 금지 사항.

**Q.** A unique transaction identifier SHALL be generated for each outgoing request.

**A.** 뜻: 각 발신 요청에 대해 유일한 트랜잭션 식별자가 반드시 생성되어야 한다.

구문 패턴 설명: 'SHALL be generated for each [entity]'는 개별 요청, 메시지, 객체 생성 시 필수적으로 부여해야 하는 메타데이터(ID, 토큰 등)의 규칙을 지정합니다.

표준 어조 비교:
- SHALL be generated: mandatory 요구사항.
- MAY be generated: 추적성 확보 등을 위해 구현체 판단으로 선택적 생성 가능.

## GitHub 소통 문구

**Q.** PR에 작성한 코드의 테스트 방법(실행 명령 등)을 작성해두었고, 리뷰어가 로컬에서 직접 확인해볼 수 있도록 안내하고 싶을 때

**A.** 영어 표현:
"Test steps are provided in the PR description. Feel free to test it out locally."

유사 표현:
- "I've detailed the steps to verify this in the PR body."
- "You can find the local setup and testing instructions in the description above."

사용 상황:
PR 본문에 재현/테스트 명령어를 정리해 두고, 리뷰어에게 직접 로컬 실행 검증을 권유할 때 사용합니다.

**Q.** PR 리뷰 요청을 받았지만, 급한 다른 작업(장애 대응 등) 때문에 리뷰가 조금 늦어질 것 같다고 미리 양해를 구할 때

**A.** 영어 표현:
"I'm currently dealing with an urgent production issue, so my review might be a bit delayed. I'll get to it as soon as I can."

유사 표현:
- "I'm tied up with a critical fix right now, but I'll review this as soon as possible."
- "Sorry for the delay in advance; I'm fixing a blocker bug and will take a look shortly."

사용 상황:
리뷰 요청을 받아 확인했음을 알리면서, 긴급 업무로 인해 즉시 리뷰가 어려움을 사전에 공유할 때 사용합니다.

## 생활영어

**Q.** 어떤 프로젝트나 배포, 일상 계획 등이 아무 문제나 차질 없이 순조롭게 척척 진행되었을 때

**A.** 영어 표현:
"Everything went smoothly without a hitch."

뉘앙스 설명:
'hitch'는 '작은 문제, 걸림돌, 매끄럽지 못한 부분'을 뜻합니다. 따라서 'without a hitch'는 어떤 예외나 장애물도 발생하지 않고 일사천리로 완벽하게 진행되었음을 표현할 때 사용합니다. 작업 배포가 깔끔하게 성공했거나 이벤트가 무사히 끝났을 때 자주 씁니다.

## 단어

**Q.** outage

**A.** 뜻: (시스템/전력/서비스 등의) 정지, 장애, 중단

예문:
"The major service outage was caused by a misconfigured routing rule, but it has now been fully resolved."
(이번 대규모 서비스 장애는 잘못 설정된 라우팅 규칙으로 인해 발생했으나, 현재는 완전히 해결되었습니다.)
