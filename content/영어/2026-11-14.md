# 2026-11-14 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The maximum number of concurrent connections SHALL be determined by the policy configured in the control plane.

**A.** 뜻: 동시 연결의 최대 개수는 제어 평면에 설정된 정책에 의해 결정되어야 한다.

구문 패턴: SHALL be determined by ... (~에 의해 결정되어야 한다 / 규정되어야 한다)
- 스펙 문서에서 시스템 동작의 기준이나 파라미터 값이 외부 설정 또는 다른 엔티티의 정책에 의존함을 강제할 때 사용하는 대표적 표현입니다.
- SHALL: 스펙상 규정된 필수 의무 사항(Mandatory)을 의미합니다.

**Q.** The optional payload field SHOULD NOT be specified when the message type is set to heartbeat.

**A.** 뜻: 메시지 유형이 하트비트로 설정된 경우 선택적 페이로드 필드는 지정하지 않는 것이 권장된다.

구문 패턴: SHOULD NOT be ... when ... (~일 때는 ...하지 않는 것이 권장된다)
- SHOULD NOT: 권장되지 않는 사항(Recommended against). 시스템 동작 자체를 완전히 금지(MUST NOT)하는 것은 아니지만, 하위 호환성이나 효율성을 위해 피해야 함을 강조합니다.

**Q.** The execution of the deletion procedure SHALL be subject to the conditions defined in Section 4.2.

**A.** 뜻: 삭제 절차의 실행은 4.2절에 정의된 조건의 적용을 받아야 한다.

구문 패턴: SHALL be subject to the conditions defined in ... (~에 정의된 조건에 따라야 한다 / 제약을 받는다)
- 규격서나 사양서에서 특정 동작이나 절차가 다른 세부 절차/조건의 통제를 받아야 함을 의무화할 때 빈번히 등장합니다.

**Q.** The allocated memory limit MUST NOT exceed the value of the node's available memory.

**A.** 뜻: 할당된 메모리 제한은 노드의 사용 가능한 메모리 값을 초과해서는 안 된다.

구문 패턴: MUST NOT exceed the value of ... (~의 값을 초과해서는 안 된다)
- MUST NOT: 절대 금지(Absolute Prohibition). 시스템 안정을 저해하거나 오류를 일으킬 수 있는 명확한 상한선/경계 조건을 정의할 때 사용합니다.

## GitHub 소통 문구

**Q.** "이 코드가 왜 필요한지 이유를 명시하기 위해 주석을 조금 추가해 주실 수 있나요?" (PR 리뷰 코멘트)

**A.** 표현: Could you add a quick comment explaining why this is needed?

유사 표현:
- Would you mind dropping a brief inline comment here?
- A short comment explaining the rationale here would be helpful.

사용 상황: 직관적이지 않거나 복잡한 로직에 대해 나중에 코드를 유지보수할 동료들을 위해 간단한 주석 추가를 부드럽게 요청할 때 씁니다.

**Q.** "제안해주신 방식대로 수정해서 커밋 올렸습니다!" (PR 리뷰 답변 코멘트)

**A.** 표현: I've updated the code as suggested!

유사 표현:
- Addressed this in the latest commit.
- Makes total sense! Pushed a fix for this.

사용 상황: 리뷰어가 지적한 내용이나 제안한 개선안을 반영한 커밋을 올린 후 답변으로 남길 때 사용합니다.

## 생활영어

**Q.** 회의나 대화 중 "그 부분은 제가 착각했네요 / 제 잘못이네요"라고 실수나 혼동을 인정할 때

**A.** 표현: My bad, I got that mixed up.

뉘앙스 설명: "My bad"는 슬랙이나 일상적 업무 대화에서 자신의 소소한 실수를 인정할 때 자주 쓰는 비격식 표현이며, "got that mixed up"은 두 정보나 개념을 헷갈렸다(혼동했다)는 뜻입니다.
