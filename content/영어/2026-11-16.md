# 2026-11-16 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The configuration parameter SHALL be represented as a UTF-8 encoded string.

**A.** 뜻: 해당 설정 파라미터는 UTF-8 인코딩 문자열로 표현되어야만 함 (강제 규격).

구문 패턴: 'SHALL be represented as ~' (~ 형태로 표현되어야 한다)

스펙 표현 비교: SHALL/MUST는 선택의 여지가 없는 규격 준수 필수(Mandatory) 요구사항을 나타내며, MAY(선택 사항)나 SHOULD(권장 사항)보다 강한 지침입니다.

**Q.** The order of items in the response SHOULD NOT be assumed to be deterministic.

**A.** 뜻: 응답 항목의 순서가 결정론적(정해진 순서)이라고 가정해서는 안 됨 (권장 사항).

구문 패턴: 'SHOULD NOT be assumed to be ~' (~라고 가정하지 않는 것이 권장됨)

스펙 표현 비교: SHOULD NOT은 그렇게 하지 않는 것이 강력히 권장되는 상태를 의미합니다. SHALL NOT(절대 금지)과 달리 부득이한 예외가 존재할 수 있으나 구현 시 의존하지 말라는 경고입니다.

**Q.** If a network timeout occurs during initialization, the operation MAY be safely retried.

**A.** 뜻: 초기화 도중 네트워크 타임아웃이 발생하면 해당 작업을 안전하게 재시도할 수 있음 (선택 사항/허용).

구문 패턴: 'MAY be safely [과거분사]' (안전하게 ~해도 된다 / ~하는 것이 허용된다)

스펙 표현 비교: MAY는 표준 규격에서 선택적 기능(Optional feature)이나 허용 가능한 동작을 서술할 때 사용하며, 구동 시 필수 이행 항목이 아닙니다.

**Q.** Resources that remain unreferenced past the retention window SHALL be subject to garbage collection.

**A.** 뜻: 보관 기간을 초과하여 참조되지 않은 상태로 남은 리소스는 가비지 컬렉션의 대상이 되어야 한다.

구문 패턴: 'SHALL be subject to ~' (~의 대상이 되어야 한다 / ~의 적용을 받아야 한다)

스펙 표현 비교: 규격 문서에서 특정 조건 만족 시 시스템 메커니즘이나 제약의 적용 대상이 됨을 의무적(SHALL)으로 규정할 때 널리 쓰입니다.

## GitHub 소통 문구

**Q.** 리뷰어가 지적한 문제 중 이번 PR 범위를 벗어나는 내용을 후속 작업으로 추적하기 위해 이슈로 만들어두겠다고 말하고 싶을 때

**A.** 영어 표현: I've created a follow-up issue to track this separately.
유사 표현: I opened a follow-up ticket for this / Let me log a separate issue for this.
사용 상황: PR 리뷰 코멘트에서 당장 이번 PR에 포함하기 부담스럽지만 추후 개선해야 할 사항을 별도 이슈로 관리하겠다고 답변할 때 자주 쓰입니다.

**Q.** 특정 에지 케이스 처리에 대해 '이 부분은 ~ 방식으로 처리하는 것에 대해 어떻게 생각하세요?'라고 피드백을 물어볼 때

**A.** 영어 표현: How would you feel about handling this on the client side instead?
유사 표현: WDYT about moving this logic to...? / What are your thoughts on...?
사용 상황: PR 리뷰 대화 중 상대방에게 구현 방향성(예: 클라이언트 처리 vs 서버 처리)에 대한 의견을 가볍고 부드럽게 물어볼 때 씁니다.

## 생활영어

**Q.** 회의 중 상대방의 설명이나 질문 끝부분을 제대로 못 들어서 다시 말씀해주실 수 있는지 정중하게 물어볼 때

**A.** 영어 표현: Sorry, I didn't catch the last bit. Could you repeat that?
뉘앙스 설명: 'didn't catch the last bit'은 전체를 못 들은 게 아니라 '방금 하신 말씀의 뒷부분을 놓쳤다'는 의미로, 회의 중 자연스럽고 부담 없이 재요청할 때 자주 쓰이는 친근한 표현입니다.
