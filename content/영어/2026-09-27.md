# 2026-09-27 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The UE context shall be retained until the timer expires or an explicit release request is received.

**A.** 뜻: 타이머가 만료되거나 명시적인 해제 요청을 수신할 때까지 UE 컨텍스트가 유지되어야 한다.

[구문 설명]
'shall be retained until A or B': A 또는 B 조건이 충족될 때까지 특정 상태나 자원을 의무적으로 유지(retain)해야 함을 규정합니다. 3GPP 및 Kubernetes 시스템의 상태/세션 생명주기 스펙에서 자주 쓰입니다.

[스펙 키워드 비교]
- SHALL: 반드시 이행해야 하는 강제 사항 (Mandatory)
- SHOULD: 권장 사항 (Recommended)
- MAY: 선택 사항 (Optional)

**Q.** The detailed mechanism for credential storage is beyond the scope of this specification.

**A.** 뜻: 자격 증명 저장에 대한 세부 메커니즘은 본 규격의 범위를 벗어난다.

[구문 설명]
'is beyond the scope of ~': 특정 사양이나 구체적 표준의 범위를 벗어남을 분명히 고지할 때 사용합니다. 스펙 문서에서 표준화 대상이 아닌 구현체 전속 영역(Implementation-specific)을 구분 지을 때 필수적인 정형 구문입니다.

**Q.** In the absence of a response from the server within the specified timeout, the client shall retransmit the request.

**A.** 뜻: 지정된 타임아웃 내에 서버로부터 응답이 없는 경우, 클라이언트는 요청을 재전송해야 한다.

[구문 설명]
'In the absence of ~': '~가 없는 상황/상태에서'라는 뜻으로, 타임아웃이나 신호 부재 시의 대체 동작(Fallback behavior)을 스펙에서 규정할 때 널리 쓰이는 표준 표현입니다.

[유사 표현]
- If no response is received (일상적 표현)
- In the absence of a response (기술 문서 표준 구문)

**Q.** Upon failure of the primary node, the system shall initiate an automatic failover to the standby node.

**A.** 뜻: 주 노드 장애 발생 시, 시스템은 대기 노드로의 자동 장애 조치(Failover)를 개시해야 한다.

[구문 설명]
'Upon failure of ~': '~의 실패/장애 발생 직후 즉시'를 의미합니다. 분산 시스템이나 고가용성(HA) 스펙 문서에서 트러블슈팅 및 장애 복구 절차를 서술할 때 핵심적으로 쓰입니다.

## GitHub 소통 문구

**Q.** PR 리뷰 중 상대방의 설명을 듣고 '아, 제가 로직을 오해했었네요! 설명해 주셔서 감사합니다.'라고 매너 있게 오해를 인정하고 감사 인사를 전하고 싶을 때

**A.** 영어 표현:
"Ah, I misread the logic! Thanks for the clarification."

유사 표현:
- "My bad, I completely overlooked that part. Thanks for explaining!"
- "Got it, that clears things up!"

사용 상황:
리뷰어/작성자의 설명을 보고 자신의 착오를 깨달았을 때 쿨하게 인정하고 피드백에 감사를 표하는 문구입니다.

**Q.** 코드 리뷰 시 '동작은 문제없이 잘 되는데, 가독성을 위해 변수명/함수명만 좀 더 명확하게 바꾸면 어떨까요?'라고 부담 없이 제안하고 싶을 때

**A.** 영어 표현:
"Functionally this looks great! Just a quick suggestion: renaming this variable might improve clarity."

유사 표현:
- "Works as expected! Would you mind tweaking the function name to be a bit more descriptive?"
- "Logic is solid. A minor suggestion to rename `data` to `payload` for readability."

사용 상황:
기능적 버그는 없지만 네이밍이나 가독성 면에서 다듬을 여지가 있을 때 상대방이 기분 상하지 않게 가볍게 제안하는 리뷰어용 표현입니다.

## 생활영어

**Q.** 동료에게 '작업을 진행하다가 뜻밖의 작은 문제/장애물이 생겨서 지체되고 있어요'라고 상황을 공유하고 싶을 때

**A.** 영어 표현:
"I hit a snag while setting up the test environment."

뉘앙스 설명:
'hit a snag'는 순조롭게 진행되던 작업 중 예상치 못한 작은 차질이나 걸림돌을 만났음을 뜻합니다. 프로젝트가 무너지는 대형 장애(disaster)가 아니라, 잠시 멈추게 만드는 단순한 꼬임/차질을 편하게 말할 때 자주 쓰입니다.

## 단어

**Q.** sanitize

**A.** 뜻: (데이터/입력값에서) 유해하거나 부적절한 요소를 제거/정화하다

예문: "Make sure to sanitize all user inputs before passing them to the database query to prevent SQL injection."
(SQL 인젝션을 방지하기 위해 데이터베이스 쿼리에 전달하기 전 모든 사용자 입력값을 정화해야 합니다.)
