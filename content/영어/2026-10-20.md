# 2026-10-20 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** When multiple traffic steering rules apply, they SHALL be evaluated in descending order of priority.

**A.** 여러 트래픽 스티어링 규칙이 적용될 때, 해당 규칙들은 우선순위의 내림차순으로 평가되어야 한다.

- 구문 패턴: `SHALL be evaluated in [descending/ascending] order of [attribute]` (~의 내림차순/오름차순으로 평가되어야 함)
- 설명: 3GPP 및 Kubernetes 스펙에서 다수의 규칙, 필터, 정책 등을 정렬된 순서대로 적용할 때 쓰이는 대표적인 규정 구문입니다.
- SHALL: 표준 명세에서 반드시 구현해야 하는 강제 사항(Mandatory)을 의미합니다.

**Q.** The immutable configuration parameters MUST be specified at the time of creation and cannot be modified later.

**A.** 변경 불가능한 설정 파라미터는 (리소스) 생성 시점에 지정되어야 하며 나중에 수정될 수 없다.

- 구문 패턴: `MUST be specified at the time of [creation/initialization]` (~ 시점에 지정되어야 함)
- 설명: 리소스의 수명 주기(Lifecycle) 중 특정 시점에만 파라미터 설정이 허용됨을 명시하는 표준 표현입니다.
- MUST: 규격을 준수하기 위한 필수 요구사항(Mandatory)입니다.

**Q.** Each internal cause code SHALL be mapped to an appropriate HTTP status code as defined in Annex A.

**A.** 각 내부 원인 코드는 부록 A에 정의된 바와 같이 적절한 HTTP 상태 코드로 매핑되어야 한다.

- 구문 패턴: `SHALL be mapped to [target]` (~에 매핑/대응되어야 함)
- 설명: 프로토콜 연동이나 API 게이트웨이 스펙 등에서 내부 데이터/에러 타입을 표준 규격 프로토콜 응답으로 변환하는 동작을 명시할 때 자주 쓰입니다.
- SHALL: 구현체에서 반드시 제공해야 하는 매핑 의무를 나타냅니다.

**Q.** The actual deletion of the underlying data MAY be deferred until all active read transactions are completed.

**A.** 하위 데이터의 실제 삭제는 모든 활성 읽기 트랜잭션이 완료될 때까지 유예(연기)될 수 있다.

- 구문 패턴: `MAY be deferred until [condition/event]` (~할 때까지 연기/유예될 수 있음)
- 설명: 비동기 처리나 지연(Lazy) 정리 로직을 허용할 때 사용하는 표현입니다.
- MAY vs SHOULD: MAY는 권고사항이나 필수사항이 아닌, 시스템 구현체에 따라 허용되는 선택적 권한(Optional)을 의미합니다.

## GitHub 소통 문구

**Q.** PR에 기능 구현과 리팩토링 코드가 함께 섞여 있어서, 리뷰의 용이성을 위해 리팩토링 부분을 별도 PR로 분리해달라고 요청하고 싶을 때

**A.** 영어 표현:
"Would you mind splitting the refactoring changes into a separate PR?"

유사 표현:
- "Could we handle the refactoring in a follow-up PR so we can keep this PR focused?"
- "It might be easier to review if we separate the refactoring from the main logic."

사용 상황:
PR의 변경 범위(Scope)가 너무 넓거나 여러 목적의 코드가 섞여 있을 때, 리뷰 부담을 줄이고 커밋 이력을 명확히 관리하기 위해 부드럽게 분리를 제안할 때 사용합니다.

**Q.** 리뷰어가 지적한 문제점이나 개선 제안이 타당하다고 느껴서, "맞는 말씀이네요! 제안해주신 대로 반영해서 수정하겠습니다."라고 답할 때

**A.** 영어 표현:
"Good point! I'll update the implementation accordingly."

유사 표현:
- "That makes a lot of sense. I'll make that change right away."
- "Totally agree. Updating the code as suggested."

사용 상황:
리뷰어의 피드백을 기꺼이 수용하고 해당 지적 사항에 맞춰 코드를 바로 수정하겠다는 긍정적인 답변을 작성할 때 자주 사용합니다.

## 생활영어

**Q.** 온라인 미팅이나 대화 중 잠시 딴생각을 하느라 상대방이 방금 한 말을 놓쳤을 때, "죄송해요, 잠시 딴생각을 하고 있었어요. 다시 말씀해 주시겠어요?"라고 사과할 때

**A.** 영어 표현:
"Sorry, I got distracted for a moment. Could you say that again?"

뉘앙스 설명:
'get distracted'는 주의가 다른 곳으로 쏠려 집중을 놓쳤음을 뜻합니다. 솔직하고 자연스럽게 자신의 실수를 인정하면서 상대방에게 기분 나쁘지 않게 재설명을 부탁할 때 자주 쓰이는 친근한 표현입니다. (비슷한 표현으로 "I zoned out for a second."도 많이 쓰입니다.)

## 단어

**Q.** backpressure

**A.** 뜻:
(백엔드/시스템) 백프레셔, 배후 압력 (수신 측의 데이터 처리 속도가 송신 측보다 느릴 때, 시스템 과부하를 막기 위해 역방향으로 데이터 흐름을 제어/억제하는 메커니즘)

예문:
"When the event buffer fills up, the consumer service applies backpressure to prevent out-of-memory errors."
(이벤트 버퍼가 가득 차면, 컨슈머 서비스는 메모리 초과 에러를 방지하기 위해 백프레셔를 적용합니다.)
