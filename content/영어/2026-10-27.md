# 2026-10-27 영어 학습

## 3GPP/K8s 기술문서 표현

**Q.** The updated network configuration SHALL take effect immediately upon receiving the acknowledgment message.

**A.** 뜻: 인정(acknowledgment) 메시지를 수신하는 즉시 변경된 네트워크 설정이 적용되어야 한다(강제).
구문 설명: `SHALL take effect immediately upon ~`는 특정 이벤트 직후 조치가 즉각 효력을 발휘해야 함을 나타내는 강제 규정 표현입니다. `upon + N/V-ing` (~하자마자)와 `take effect` (효력을 발휘하다)의 조합입니다.

**Q.** Direct modification of managed resources SHOULD be avoided in favor of updating the declarative manifest.

**A.** 뜻: 선언적 매니페스트를 업데이트하는 방식을 선호하여, 관리 대상 리소스를 직접 수정하는 것은 지양해야 한다(권장).
구문 설명: `SHOULD be avoided in favor of ~`는 A 대신 B를 권장할 때 쓰입니다. `SHOULD`는 강한 권장(normative recommendation)을 나타내며, `in favor of`는 '~을 선택하여 / ~를 선호하여'라는 의미의 전치사구입니다.

**Q.** Requests exceeding the specified threshold MAY be subject to rate limiting by the API gateway.

**A.** 뜻: 지정된 임계값을 초과하는 요청은 API 게이트웨이에 의해 속도 제한의 대상이 될 수 있다(선택적/가능성).
구문 설명: `MAY be subject to ~`는 기술 규격에서 특정 조건이나 처리의 대상이 될 수 있음을 허용/명시할 때 쓰입니다. `MAY`는 선택적 허용을 나타내며 `be subject to N`은 '~의 대상이 되다'라는 뜻입니다.

**Q.** All incoming requests SHALL be subject to validation against the predefined schema.

**A.** 뜻: 모든 들어오는 요청은 사전 정의된 스키마에 대한 검증을 받아야 한다(강제).
구문 설명: `SHALL be subject to validation against ~`는 시스템에 유입되는 데이터가 기준 명세에 대해 반드시 검증(validation) 절차를 거쳐야 함을 명시하는 규정 구문입니다.

## GitHub 소통 문구

**Q.** 코드 중간중간에(인라인으로) 코멘트를 몇 개 남겨두었습니다. 시간 되실 때 확인해 주세요!

**A.** 영어 표현: "I've left a few comments inline. Please take a look when you get a chance!"
유사 표현: "Left inline feedback on a few lines.", "Added inline notes for your review."
사용 상황: PR 리뷰 중 줄 단위로 의견을 작성한 후 작성자에게 알릴 때 사용합니다.

**Q.** 예외 상황(edge case)에 대한 테스트 케이스도 몇 개 추가해 주실 수 있나요?

**A.** 영어 표현: "Would you mind adding a few test cases for the edge cases?"
유사 표현: "Could we add some unit tests covering these edge cases?", "It would be great to have test coverage for this scenario."
사용 상황: PR 리뷰 중 누락된 예외 케이스나 테스트 작성을 정중하게 요청할 때 사용합니다.

## 생활영어
